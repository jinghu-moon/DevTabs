# 图片与终端浮层共存及三栏拖动

## 问题与结果

此前 `app.popup.is_some()` 会设置 `images_occluded`，所以只要展开 Debug，整个图片预览都会消失，即使两者并没有重叠。本次移除这一全局抑制条件，按浮层实际矩形裁切图片；终端浮层遮住重叠部分，其余图片正常显示。

同时补充文件树／Agent、Agent／预览两条分隔线的左右拖动，并为文件名末尾的 Git 状态增加明确空格，预览和 Git 标记显示为 `filename [P] M`。

## 图像组合

- 不重叠：继续原有完整图片输出路径。
- 部分遮挡：将图片矩形减去浮层矩形，得到最多四个互不重叠的片段；保持原尺寸、位置和源坐标，不重新缩放图片。
- 完全遮挡：不输出图片片段；浮层移开或收起后使用既有图片恢复。
- Markdown：源图像行偏移与浮层裁切偏移相加，仍复用原编码和缓存代次。
- Half-block：保持字符缓冲区的原有叠放规则，由后绘制的浮层覆盖。

在现有 vendored `ratatui-image` 中增加 `Sixel::crop_cells`，直接截取编码游程并保留调色板。裁切不调用图片解码器、重采样器或量化编码器。横向裁切处理重复计数、颜色选择和水平回车；纵向裁切重新对齐六像素条带中的位，支持 17 像素等非 6 倍数字体高度。最后不足六行的条带屏蔽多余像素，并使用透明零位，避免擦到浮层边缘。

`Composition` 缓存最多 128 个片段、32 MiB 的派生编码；缓存键包含原图片代次、可见矩形、源行偏移和字符像素尺寸。图片失效、隐藏或后台释放时清理派生缓存。`PixelDamage` 使用与绘制一致的片段计划，在同步输出事务中重绘暴露出的文字和空白格，避免整屏清空。

弹出菜单、确认框等原有模态交互仍沿用图片暂停规则；普通 Debug／Agent 浮层不再触发该规则。

## 拖动与布局

左键按住两栏之间的竖边框并左右拖动，释放保存；拖动过程中按 Esc 恢复拖动前的宽度。顶部标题／按钮区不作为 Agent／预览分隔线，避免抢占按钮。文件拖放、预览滚动条拖动和终端浮层拖动各自保留其手势所有权。

文件树宽度沿用现有 20–80 格设置；Agent 至少 62 格，预览并排时至少 42 格。窗口变窄时继续既有单区域覆盖布局。Agent／预览比例用万分比保存到项目现有侧栏设置，普通终端宽度下可按字符格跟随鼠标；调整终端尺寸后按比例重新约束。未增加第二个配置文件。

文件树已有垂直滚动条时，该滚动条优先处理上下拖动；调整栏宽可拖它右侧紧邻的 Agent 左边框，或按 Alt 拖文件树右边框。分隔线一旦开始拖动，跨过终端区域或浮层后仍持续捕获，直到释放。

## 回归与统计

修复前恢复旧抑制条件后，真实 App 状态回归测试在“展开 Debug 不应抑制整个图片”断言失败，见 `artifacts/image-panel-before.log`。修复后该测试还检查浮层覆盖范围内没有图像锚点或 Skip 格，并检查收起恢复原图代次。

新增覆盖：

- 裁切图与原图逐像素比较，遍历六种条带对齐相位和多个横向位置。
- 透明尾部不产生越界可见像素；四片矩形覆盖恰好等于原图减遮挡区域。
- 浮层移动、缩放、完全遮住、移离和收起；静止时无额外协议输出。
- Markdown 内嵌图片的实际 Sidebar 绘制和代次复用。
- 两条分隔线、最小宽度、Esc 取消、释放保存和重新载入设置。
- 长文件名截断时保留标记间隔；既有树／编辑器滚动条回归。

沿用 `image.slice_prepare` 计时，新增 `image.clips`、`image.composition_cache_hits` 计数。独立进程统计测试中，Debug 连续改变文本 100 帧：裁切次数 **4 → 4**，图片传输次数 **4 → 4**，图片字节 **124598 → 124598**，派生缓存命中增加 **400**。这是固定测试图和字符尺寸下的输出复用证据，不代表真机帧率测量。日志为 `artifacts/image-composition-tests.log`。
