## 1. 目标与设计依据

用户在同一仓库内同时开发两个或更多模块，希望在一个 DevTabs 终端界面内看到多个 Agent 的原生界面，随时进入其中一个任务操作。每个任务使用独立 Git worktree，减少多个 Agent 同时修改同一份文件的问题；总览同时呈现项目下的任务与需要处理的事项。

本次已确认的需求：

1. 一个 DevTabs 工作区同时展示多个并行开发 Agent。
2. 支持左右并排及上下堆叠，拖动分隔线调整比例。
3. 每个面板边框展示所属任务、Agent、分支和状态等信息。
4. 总览呈现项目下的任务、任务状态、改动和进入入口。
5. 延续已有后台宿主、原生 Agent、文件树、预览、编辑、Debug、悬浮、收起与放大能力。
6. 开发途中随时追加独立功能：从当前任务直接新建分支和独立 worktree，在同一终端内新增 Agent 面板，多个任务同时可见、可分别继续输入，原任务继续运行。
7. 文件、暂存区、终端输入、对话、编辑草稿和运行目录按任务隔离；不把工作树隔离承诺成合并时绝无冲突或外部服务自动隔离。
8. 接入可靠的 Agent 本轮结束事件，通过 Windows 系统通知及任务 UI 提醒用户；后台任务结束不抢输入焦点，点击通知定位已有任务，不重复启动 Agent。
9. 每轮结束展示该轮期间发生变化的文件清单、文本增删与可查看差异，支持回看最近几轮；已有未提交改动、本轮中途提交及后续编辑不能被混为同一范围。

| 源码/磁盘独立不完整原因、缓存和有界后台工作队列 | 正确识别 linked worktree 的 Git 目录，增加任务范围缓存及公平调度 |

当前仍存在必须先解除的假设：

- 宿主普通 `Open` 在 `new_instance=false` 时按项目路径复用；总览精确 resume 通过显式 workspace 或新实例规避误复用，但这不等于宿主已支持任务身份。
- 宿主创建、Agent/Debug 聚焦、边框和侧栏插入路径仍依赖“会话 0 是 Agent、1 是 Debug”；`SessionInfo` 尚无 `task_id/role/initial_cwd`。
- `Options` 对一个工作区只有一份 Agent、cwd 与 resume；恢复日志 `launches.json` 记录的是工作区启动选项，不是任务目录。
- `overview/stats.rs::cache_stamp` 直接检查 `<root>/.git/HEAD`、`index`、`refs/heads`；linked worktree 的 `.git` 是文件，不能照搬该失效逻辑。
- 总览历史缓存和工作队列按项目/Agent 与单个选择目标组织，不能把现有“丢弃较旧查询”队列直接用于多个必须完成的创建事务。

因此首步验证是“两个稳定任务身份 + 两个独立 checkout + 显式终端路由”，随后接入同屏布局。仅把两个独立项目窗口或两个历史 resume 放在一起，不构成本文能力。

### 1.2 范围

首轮交付覆盖手动创建多个隔离任务、同屏操作、任务上下文切换、总览管理、改动审阅和受控结束流程。Git 仓库是隔离任务的前提；非 Git 项目保留已有单任务能力，并按第 7.10.7 节支持文件变化观察及可选限定范围快照，不因不能建立 worktree 而关闭文件记录。隔离任务入口单独解释原因。

自动拆任务、主管 Agent 调度、Agent 相互发消息、远程 worktree、任意嵌套分屏和任务依赖图列为后续扩展。本文的“模块”指仓库内目录；真正的 Git submodule 涉及独立仓库与初始化，不按普通目录自动处理。

DevTabs 管理工作区、文件、Git、进程及官方集成事件，不调用 AI 生成对话总结、重建压缩前记忆或自动推导任务决策。本轮改动依据磁盘事实与轮次记录，独立于 Agent 上下文压缩和聊天摘要；不为此接管 Agent 的提示词或内部工作机制。

### 1.3 首要用户场景：做到一半，临时开另一个功能

用户先正常开发任务 A，不预先规划所有并行任务。A 的 Agent、Debug 可以正在运行，文件可以尚未提交，编辑器也可以有未保存内容。此时从工作区点击“＋ 新任务”，输入功能 B 的名称，确认默认基准，即可在当前终端建立新的任务 B。

系统为 B 创建新分支、独立 worktree 和独立 Agent 对话，在当前 Windows Terminal 标签页内的 DevTabs 新面板打开。A 不切分支、不 stash、不提交、不重启、不丢草稿；B 创建失败也不改变 A。无需返回总览、关闭当前项目或重建工作区。新增 C、D 使用同一路径，首版不把“恰好两个任务”写死为容量限制。

此场景是首个完整体验的必验主路径；启动时一次创建两个任务只能作为辅助用例。

## 2. 核心模型与不变量

### 2.1 概念

| 概念 | 含义与身份 |
| --- | --- |
| 项目 Project | 用户在总览管理的项目；保留既有设置、收藏和项目便签 |
| 仓库 Repository | Git 公共目录对应的仓库，区分公共 Git 目录、checkout 根目录和当前 cwd |
| 任务 Task | 用户命名的开发工作，拥有稳定 `task_id`、说明、便签、Agent 选择和工作目录 |
| 项目工作区 Workspace | 一个可重连的后台会话集合，可承载同项目多个任务；前端只是其视图 |
| 终端会话 TerminalSession | ConPTY 及其进程，以 `terminal_session_id` 标识，显式归属于任务并标记 Agent / Debug / Extra 角色 |
| Agent 对话 Conversation | Provider 的历史对话，以 Provider + conversation ID 标识，用于 resume；不是终端进程或任务 |
| 面板 Panel | 会话的显示位置和视口状态；隐藏或改位置不代表停止会话 |

默认主工作区中的现有 checkout 映射为“主任务”。主任务不由 DevTabs 创建其目录，不能通过清理任务删除原项目。新建隔离任务默认各有独立 worktree 和新分支；一个任务可以拥有 Agent、按需创建的 Debug，以及额外命名终端。

任务是持久开发对象，终端是一次运行，对话是 Provider 的续接对象；三者分别拥有身份。任务重启可更换终端或对话，历史中的 40 条 resume 不表示有 40 个任务。一个工作区可同时容纳主任务和隔离任务。同一会话沿用现有独占输入租约与接管语义，不允许两个前端无提示地同时操控。首版在一个前端内并排显示任务，不以切换 Windows Terminal 标签页/窗口代替同屏观看。

### 2.2 当前工作区如何进入任务模型

当前同项目可以已有多个独立工作区或显式 resume，它们不等于多个隔离任务。旧构建继续按既有 IPC 隔离保留其会话，新构建不自动收编。新模型下同样允许多个独立工作区：为打开的目标明确选择/创建主任务，连接同构建的指定 workspace/session；其他工作区保留边界，只有将来显式采用操作才能关联，不能静默搬走租约或终端。

同一任务可有多次已结束的运行记录，但首版每任务至多一个活动 Agent 终端；重复启动同 task ID 返回现有状态。需要独立并行 Agent 时创建另一个任务，不靠重复的 conversation ID 区分进程。同一 Provider 对话若已绑定运行终端，续接应连接/接管该终端或说明占用，不为第二个任务自动重复打开。

项目可以位于仓库的子目录；`project_root`、`checkout_root` 与 `initial_cwd` 分开保存。迁入 worktree 时依据仓库相对路径还原模块位置，解析后的 cwd 必须属于目标 checkout；junction/符号链接复核不通过时阻止启动，不把字符串拼接当目录隔离。

### 2.3 必须成立的不变量

1. 一个任务的 Agent、Debug、文件树、预览和 Diff 必须引用同一任务上下文。
2. 同项目的不同任务不能因项目路径相同而被启动复用逻辑合并。
3. 面板移动、横竖切换、放大、收起及前端重连均不重启任务进程。
4. 布局位置和列表下标不是任务或会话身份；关闭中间面板不能改变输入的目标。
5. 普通键入、粘贴和路径插入只发往明确的单一目标；首版不提供广播输入。
6. worktree 提供文件副本隔离，不限制 Agent 的所有文件访问，也不保证没有合并冲突。
7. 进程存活、Agent 工作状态、用户审阅结果分别保存，不能相互推导。
8. 无自动超时删除 worktree，无“完成即清理”，无关闭视图即停止任务。
9. 缓存与异步结果携带任务及 checkout 身份；同名文件、同 Provider、相同分支名不能成为跨任务复用依据。
10. 既有历史对话不自动生成任务，也不为未绑定任务显示主项目的“最近一次”对话。
11. 运行中新增任务只追加资源和布局目标，不重建已有工作区、不重新运行其他任务初始化或命令。

### 2.4 “相互隔离、不会冲突”的可验收边界

| 范围 | 首版要求 | 不作的保证 |
| --- | --- | --- |
| 文件、分支、暂存区 | 每个隔离任务一个独立 checkout、新分支及独立 index；不在 A 目录执行 checkout/switch 来创建 B | Agent 拥有系统权限时不会主动越界修改其他路径 |
| 输入、对话、终端 | 独立 task/terminal/conversation 绑定；停止、粘贴、路径插入只到目标任务 | 通过屏幕文本可以可靠推断 Agent 所有内部状态 |
| 树、预览和编辑 | 独立路径、草稿、缓存及异步 generation；同名文件不互相覆盖 | 忽略外部文件变化，或自动保存用户未保存内容 |
| 构建和服务 | 各任务默认独立可写输出；显式配置端口、数据库/容器名称和环境变量 | worktree 自动隔离端口、共享数据库、全局工具配置和外部服务 |
| Git 公共数据 | 仓库写操作串行协调，创建分支唯一，不覆盖资源；提交属于各自分支 | 各 worktree 拥有完全独立的对象库、refs 或 Git 配置 |
| 最终成果 | 修改同名文件时开发目录互不覆盖，审阅时提示共同修改 | 合并到同一分支必然没有文本或语义冲突 |

产品承诺是“并行开发时不会因 DevTabs 错误共享目录或路由而串改、串输入”，而不是“所有功能最终一定能无冲突合并”。需不可信进程的权限隔离时应另用容器/虚拟机方案，不将其混入首版 worktree 功能。

## 3. 新建任务与工作目录

### 3.1 新建流程

工作区提供常驻可点击“＋ 新任务”，总览项目详情和命令菜单保留同名入口；窄屏可显示“＋”，但点击区域和帮助仍明确为新任务。入口由 DevTabs 处理，不依赖 Agent 是否接受输入。复用 Ctrl+G 前缀命令体系，具体字母实现时统一，不能占用已有 N“下一会话”。

默认紧凑表单只需任务名称，其余显示可读摘要；高级选项展开后才编辑基准、路径、分支和运行配置。打开表单只创建启动草稿，确认前不创建分支、目录或进程。

| 字段 | 默认与规则 |
| --- | --- |
| 任务名称 | 必填，可中文；显示名与路径 slug 分离 |
| 任务说明 | 可选，持久保存；启动后显式选择“发送任务”，不自动替用户按 Enter |
| Agent | 继承项目选择，支持已有 Codex / Claude；Shell 用于诊断 |
| 对话 | 默认新对话；只有显式选择并验证属于本任务 cwd 的历史记录时才 resume，不继承主项目 resume ID |
| 基准 | 默认当前活动任务 checkout 此刻的 HEAD；快捷选择“独立功能：主分支本地提交”或“接着当前进度：当前任务提交”，高级可选本地分支/提交；确认时冻结 hash，不使用来源任务最初的 base_commit 代替当前进度 |
| 模块目录 | 从工作区发起时默认当前任务配置的模块相对路径；总览项目入口按项目目录相对仓库根映射，缺失时明确提示并可选仓库根 |
| 分支 | 默认 `devtabs/<slug>-<短任务ID>`，校验名称及冲突，不覆盖已有分支 |
| worktree 路径 | 默认仓库同级 `<repo>-worktrees/<slug>-<短任务ID>`，可修改 |
| Debug | 继承“仅 Agent / Agent + Debug / 自定义”组合，界面展示实际要创建的终端 |
| 展示方式 | 固定为当前终端内的新 Agent 面板；沿用已保存的左右/上下排列偏好，不在创建表单增加窗口选择步骤 |
| 初始化 | 列出拟运行的已配置步骤、运行目录和环境设置 |

确认摘要必须同时显示基准提交、目标目录、模块路径及会话组合。任务从确认的提交创建，不能把“从当前项目创建”暗示为自动复制当前未提交改动。新任务只继承项目可共享默认值，清除来源的 `workspace/view/recovery_id/resume_id` 等运行身份，生成新的 task/operation ID；显式续接另走已验证的对话绑定。

源 checkout 有 staged、unstaged 或未跟踪文件时，不因 dirty 阻止新任务。表单摘要明确“从 A 最近提交创建；未提交改动仍只在 A”，确认按钮使用“从该提交创建并打开”；该次确认同时表达创建范围，无需额外先整理或反复确认。未保存编辑草稿同样留在 A，不作为 B 的文件来源。

“独立功能”显示项目明确配置的主分支；未配置时优先读取本地已有的默认分支信息，无法唯一确定则让用户选择，不把当前主任务的功能分支或固定的 main/master 名称当成主分支。使用本地已知提交，标明分支与短 hash，不静默 fetch 或暗示已经同步远端。“接着当前进度”显示 A 的当前分支与 HEAD，提示 B 会包含 A 在该提交前已提交的进度。两种方式都创建新分支和独立 worktree，不切换 A。

如果 B 需要 A 尚未提交的进度，用户先在 A 自行整理并提交，再刷新基准；首版不隐式复制工作目录、不自动 stash/commit、不自动覆盖配置。没有任何提交的仓库无法选定 HEAD，解释原因并引导用户创建首个提交。未来快照能力单独设计。

### 3.2 创建事务与失败处理

后台操作依次执行：验证仓库及路径 → 记录操作意图与基准 → 创建分支/worktree → 初始化 → 创建会话 → 将任务加入工作区布局。A–C 阶段初始化是明确的空步骤；D 阶段交付模板后才开放相应配置。

- 使用独立 `operation_id` 和幂等请求；双击确认、连接超时重试不能创建两个任务。
- Git、安装依赖和进程等待在后台执行，不占用绘制线程或宿主会话/输入全局锁。
- 已有路径、已有分支和其他程序创建的 worktree 一律不覆盖。
- 自动回滚仅针对本次已确认创建、且仍无新增改动和占用的资源；记录动作及结果。
- 初始化或 Agent 启动失败时默认保留已创建的任务目录，显示失败阶段，允许重试对应步骤。
- UI 或 IPC 超时视为结果未知，通过操作 ID 查询；未确认失败前不能删除可能已被会话使用的目录。
- 中途崩溃后根据操作日志与 `git worktree list --porcelain` 对账；缺失、外部移动和孤立资源明确呈现，禁止靠名称猜测后清理。

DevTabs 负责默认隔离任务的 worktree 生命周期，再用指定 cwd 启动 Agent。此模式下不能再自动附加 Provider 自行创建 worktree 的选项，避免 Agent 二次创建 checkout，使前端路径脱节。用户手动切换 cwd 或调用 `/worktree` 后，已配置目录不自动冒充进程的实际 cwd；可靠检测到不一致时提供“重新绑定任务目录”入口，首版不自动接管外部目录。

### 3.3 初始化与运行资源

初始化步骤为显式项目配置，支持依赖安装、白名单本地文件复制、环境变量和 Debug 命令。表单显示将运行的脚本；步骤状态、退出码及有界日志可查看。失败后重试不重复执行其他已成功步骤，允许显式重新执行。

未跟踪和忽略文件不会由 Git 自动复制。`.env` 等文件按用户配置逐项复制且默认不覆盖目标；不在界面或日志展示秘密值。不默认把 `target`、`node_modules` 等可写目录链接到多个任务；使用工具自身的共享缓存，任务输出目录保持独立。

服务端口采用可配置的任务变量，实际启动仍需处理端口被占用；不承诺哈希映射永不冲突。数据库、容器名称、临时文件和外部服务是否隔离由项目配置决定，创建摘要说明已配置的资源。

### 3.4 运行中追加任务与快速打开

1. 用户在 A 正常开发时点“＋ 新任务”，默认带出 A 的 Provider、模块和可共享项目配置；仅填写 B 名称即可使用其余默认值。摘要展示来源分支/提交、B 的分支/路径、会话组合及“当前终端新面板”。
2. 确认时冻结基准提交，后台创建 B。A 继续消费输出和接收输入；创建进度不长期占据模态界面。用户可关闭进度继续做 A，之后从任务列表进入 B。
3. 宿主在同一逻辑项目工作区追加 TaskRecord 和终端，发布带 revision 的任务增量/快照。前端按稳定 ID 合并，不销毁 A 的 App/Sidebar 或重建 A 进程；不存在假定启动后终端数量永远不变的数组路由。
4. B 准备好后直接加入当前终端的可见 Agent 区域，与 A 同时更新，不重复创建任务或 Agent。若用户在等待期间继续操作 A，B 出现不抢走输入焦点；点击 B 或显式“进入 B”再切换，不自动发送任务文本或 Enter。
5. 任务已创建但面板附着失败时保留 B 和运行状态，提供“重新连接任务”；重试只附着同一个任务，不执行第二次 `worktree add` 或启动第二个 Agent。
6. 创建 C、D 的逻辑相同；目录/分支冲突生成明确错误或新建议，不重命名/覆盖既有资源。来源 A 在创建期间继续提交不改变 B 已冻结基准，界面可提示来源已前进。

快速指“名称 + 默认摘要 + 一次创建确认”的操作路径，而不是承诺任意仓库能在固定秒数完成。分别记录表单可交互、Git 创建、初始化、Agent 就绪、视图附着耗时；依赖安装与 Agent 启动不能阻塞 A 的本地输入。

## 4. 同屏多 Agent 工作区

### 4.1 布局结构

工作区位于同一个 Windows Terminal 标签页内，保留共享文件侧栏、预览与单行全局底栏。每任务一个真实 Agent 终端面板，未聚焦的可见面板同样实时显示输出；不能只显示状态卡、截图或靠任务标签切换来冒充双任务同时可见。中间 Agent 区域支持下列两种首版排列，名称明确表达方向：

```text
左右并排
┌ 文件 ─────┬ 登录模块 · Codex ─────┬ 管理后台 · Codex ────┐
│ 当前任务  │ Agent A               │ Agent B              │
│ 的文件树  │                       │                      │
│           ├───────────────────────┴──────────────────────┤
│           │ 当前任务的 Debug（按需停靠 / 悬浮 / 收起）    │
└───────────┴──────────────────────────────────────────────┘

上下堆叠
┌ 文件 ─────┬ 登录模块 · Codex ─────────────────────────────┐
│ 当前任务  │ Agent A                                      │
│ 的文件树  ├ 管理后台 · Codex ─────────────────────────────┤
│           │ Agent B                                      │
│           ├──────────────────────────────────────────────┤
│           │ 当前任务的 Debug（按需展示）                  │
└───────────┴──────────────────────────────────────────────┘
```

预览沿用现有打开、覆盖与放大规则，并明确所属任务。首次添加第二个 Agent 时，按侧栏/预览/Debug 扣除后的 Agent 可用区域选择：每个面板能获得至少 60 列 × 10 行时优先左右并排，便于同时比较；否则满足上下最小尺寸时上下堆叠，保留代码行宽。两者都不满足时进入窄窗降级。60 列是初始阅读舒适参数，40 列仍是面板最小约束，均需真机校准。

用户显式切换或拖动后保存排列和比例，优先使用保存偏好；临时窗口缩小不改写它。不因输出多少、哪个 Agent 更忙或鼠标悬停自动交换位置。

Agent 排列独立于现有 `Layout` 的 Debug Float / Split / WT Tabs 语义，不把 `Split` 偷换为横排或竖排。新增 `agent_arrangement` 和面板比例；实现前统一选项文案，现有启动预设继续具有原义。多个 Agent 同屏发生在一个 DevTabs TUI 内，不依赖 WT 外部分屏。

三个以上 Agent 在首版沿同一方向等比分配，可单独收起或放大。网格和混合嵌套拆分后续实现，不为实现任意布局阻塞双 Agent 场景。

### 4.2 尺寸、拖动与降级

- 单个 Agent 初始最小面板为 40 列 × 10 行，包含上下边框；内容至少 38 列 × 8 行。该值是待真机校准的设计参数。
- 拖动相邻面板分隔线调整比例，释放保存；Esc、失焦或窗口缩放取消未完成拖动。尺寸按整数格分配，余数稳定落到末项。
- 普通聚焦不改变比例、不触发 PTY resize；窗口尺寸、显式拖动和布局操作才更新实际可见会话尺寸。
- 放大只改变显示，恢复后保留此前排列、比例、滚动位置与焦点。收起不停止后台读取。
- 不满足最小尺寸时显示单 Agent 及任务切换入口，保留其他会话；不停止任务、不覆盖用户保存的排列。空间恢复后还原。
- 切换入口显示隐藏任务数量及待处理数量。隐藏的面板清除命中区，不接收键盘或鼠标输入；PTY 保留最近有效的非零尺寸。

### 4.3 焦点、文件与 Debug 上下文

区分“实际输入焦点”和“当前任务上下文”：点击另一个 Agent 的内容区，或显式选择任务，才切换当前任务；悬停、后台输出、点击无关标题按钮不切任务。

共享文件树、预览、Diff 和当前 Debug 跟随当前任务上下文。树内部切焦点不会丢失任务身份。Debug 标题显示任务名，悬浮 Debug 也保持其固定归属，不因切任务把已有终端重新标记为其他任务；切换到别的任务时按其保存的展示状态呈现对应 Debug。

按 `task_id` 保存独立的文件树展开/选中、文件标签、阅读位置、搜索、编辑缓冲区和预览模式。可先让每个任务持有现有 Sidebar 状态实体，避免为此重写文件树、Markdown 或图片渲染器；保留有草稿的实体，监听/预取按可见性暂停或降频，不为每个隐藏任务无界启动后台线程。任务切换保留未保存缓冲区，不执行磁盘保存；面板显示真实未保存标记，任务详情可定位其草稿。关闭/删除任务、退出前端、关闭有草稿的文档时沿用保存/放弃/取消保护。

若切换会导致缓冲区必须被卸载，先提示保存/放弃/取消；取消时任务上下文与目标输入均不切换。异步读取、路径校验、图片解码和编码结果携带 `task_id + checkout_key + generation`，过期返回不能替换当前树或文档。拖拽开始和确认插入时核对同一任务/目标终端；等待校验期间切任务不得把旧路径送进新 Agent。隐藏任务的图片停止呈现并清理旧屏幕占用，切回时恢复；现有 Debug 浮窗与图片裁剪规则继续有效。

从树插入路径只发往所属任务的 Agent，显示目标任务名，不自动发送 Enter；Debug 和其他任务不能成为隐式目标。点击终端聚焦后的首个普通按键直接发送给该会话，不提供跨 Agent 广播。

### 4.4 返回总览与重新进入

复用已有底栏“← 总览”和 Ctrl+G → P，不再新增相同导航按钮。返回携带 `project_id + workspace_id + task_id + terminal_session_id` 以及必要的启动草稿，按稳定身份选回对应行；父项目被筛选或折叠隐藏时临时揭示目标。`← 总览`、分离前端、停止任务、关闭整个工作区分别保持独立语义。

当前 `main.rs` 只传回一份 `Options`，`run_from` 选回项目；未来必须扩展为显式返回目标，不能用项目路径猜测应聚焦哪个任务。重进时优先连接原工作区及其任务，不因历史 resume 子行或新的项目默认值误建终端；原任务已归档、目录缺失或宿主丢失时显示对应原因，再由用户选择下一步。

返回不承诺在进程退出后自动恢复未保存内容。任务切换时内存草稿保留；返回总览/退出若会销毁其持有者，先走保存/放弃/取消保护，或者在不销毁实体的导航生命周期内保留。首版不引入未经设计的自动磁盘草稿恢复。

### 4.5 同屏观察与持续派发下一步

用户的主操作是“同时看 A/B → 点选需要继续的 Agent → 直接输入下一步 → 再切另一边”，首版必须完整覆盖。

- A、B 可见时都实时渲染各自原生界面；只有一个键盘输入焦点。聚焦面板采用明确的边框强调与 `▸`，底栏显示“输入目标：任务名 · 分支”，颜色之外保留文字。
- 点击 B 内容区后，下一次普通键入、粘贴、Enter、Ctrl+C 等终端输入只到 B，A 继续输出；点击 A 恢复向 A 输入。不增加共用聊天输入框、不复制 Provider 输入草稿、不自动代发下一步或广播。
- 原生 Agent 输入框里尚未发送的文字保留在各自终端进程中；从 A 切到 B 再切回，不清空、不移动、不提交 A 的输入。应用前缀命令本身由 DevTabs 消费，菜单取消后仍回到原目标。
- 任务条以紧凑按钮列出任务名称和真实状态，提供上一任务/下一任务、进入指定任务、放大/还原；未实现 Provider 活动事件时只显示进程/受管命令状态，不编造“正在思考/等待输入”。
- 单任务放大用于认真阅读和长输入，显式还原后立即恢复双面板及原比例；不把放大后轮换标签当作默认的双任务观看方式。
- Debug 与文件预览沿用当前任务上下文，不给每个 Agent 都永久分配一套展开的侧栏/Debug。用户可收起树/预览/Debug 扩大 Agent 区域，任务所属关系始终明确；不因创建 B 自动丢失或关闭 A 的 Debug。
- 三个以上任务继续同一终端内管理，可收起暂时不看的任务。可见任务集合与输入焦点分开；点击被收起任务提供“替换当前可见项 / 加入可见区域”，不停止被替换任务。空间不够时明确隐藏数量，让用户选择主要观察的两个，不把全部面板挤成不可读的小格。

边框操作“收起面板”只隐藏该任务；停止默认只作用于选定任务；“关闭整个工作区”单独确认会影响的全部任务。关闭当前前端后后台继续，重连恢复任务列表、可见集合、排列及目标身份。

独立 Windows Terminal 窗口、把任务在多个窗口间移动列为后续可选扩展，不进入首版表单、实现阶段或验收主路径。当前设计的重点是一个终端内多个 Agent 同时可见、分别可输入。

### 4.6 六项交互补充与优先级

以下六项纳入实现与验收，其中前 3 项是首版基本操作要求；第 4 项的 Agent 活动提示按实际 Provider 能力开放，不能以猜测代替集成。

1. **键盘快速切换任务。** 保留鼠标点选，增加上一任务/下一任务和按任务编号进入的命令入口，使用现有 Ctrl+G 前缀体系，避免截获 Agent 正常快捷键。原 N 继续表示下一终端会话，任务切换和包含 Debug/Extra 的会话切换明确区分。编号只用于定位当前显示的 task ID，不作为持久身份；切换后边框与底栏同步输入目标，关闭菜单后首个普通按键直接发往该任务。具体键位实现时统一登记到 F1 和菜单。

2. **一次输入操作绑定一个目标。** 用户开始粘贴、拖入文件或请求路径插入时，立即冻结 `workspace_id + task_id + terminal_session_id` 及有效连接/租约版本，异步校验与排队始终携带该目标。操作期间切焦点不会把剩余内容送给另一任务；目标退出、断连或租约失效时明确失败或说明结果未知，不自动改发，也不盲目重复已经部分写入的数据。已经提交给 A 的粘贴不会因点选 B 被重新归属，后续新键入才属于 B。该约束覆盖键盘粘贴、系统粘贴事件、拖拽与文件路径动作。

3. **明确分支来源。** 新任务表单提供“独立功能：主分支本地提交”和“接着当前进度：当前任务提交”两个快捷选项，显示真实分支/hash 与是否包含 A 的已提交进度，规则见 3.1。没有已确认主分支时不能自动猜选。“从当前任务创建”不复制未提交改动，也不自动继承 A 的 resume；切换来源只更新 B 的草稿，不改动 A。

4. **未聚焦任务轻量提醒。** 后台任务可显示可靠的“有新输出”“命令已退出”“启动失败”，消息只更新任务条、面板边框与总览提示，不抢输入焦点、不自动展开或更换可见任务。“有新输出”仅表示终端输出 revision 增加，不表示完成或等待输入；显示内容需要有界合并，避免高频输出刷屏。接入经验证的 Provider 事件后，才显示相应等待确认/等待输入等状态。查看任务可消除未读提示，但不能伪装为运行状态变化；具体系统完成通知另行细化。

5. **固定两个重点观察的任务。** A/B/C/D 并行时，可固定 A/B 为当前重点可见组合，C/D 后台继续；新增任务和后台通知不替换固定项、不重排布局或改写比例。用户显式替换、取消固定或解除收起才改变组合；选择隐藏 C 先提供“临时查看/放大”和“替换可见项”，不静默挤走固定任务。临时查看后可还原 A/B。固定集合、可见集合与实际输入焦点分别保存，按 task ID 关联；固定任务停止/归档时明确提示并保留可恢复位置，不擅自用其他任务顶替。数量和尺寸不足时遵循 4.2 的可恢复降级，固定不代表任何尺寸都能同屏。

6. **单任务故障与独立恢复。** B 的 Agent 失败或退出只更新 B，保留其有界最后输出和错误原因；面板提供“查看错误”“续接关联对话”“新开对话”，按能力禁用无法验证的恢复方式。续接复用 B 的 task/checkout 和已核验 conversation，但只为 B 创建新的终端运行；新开对话清除 B 的旧 conversation 绑定。恢复动作幂等且先检查旧 Agent 是否仍存活，不能并发启动两个 B。恢复 B 不重启 A/C，不重新初始化成功步骤，不默认重跑 B 的 Debug/Extra 命令；Debug 仍活着就保留，宿主整体丢失时则明确这是全部终端丢失，不能只报 B 的局部失败。

## 5. 每个终端面板的边框信息

```text
┌ ▸ 登录模块 · Codex ─────────────────── 运行中    [更多] ┐
│                                                       │
│                    Agent 原生界面                     │
│                                                       │
└ task/auth · modules/auth ───────────── 3 文件  +82 −16 ──┘
```

| 位置 | 常态信息 | 规则 |
| --- | --- | --- |
| 上边框左侧 | 任务名称、Agent 类型；Debug / Extra 显示角色或会话名 | 名称必留，重名用短任务标识区分 |
| 上边框右侧 | 生命周期异常或可靠 Agent 状态、更多入口 | 退出码、启动失败、等待处理优先 |
| 下边框左侧 | 分支、模块相对路径 | 完整 worktree 路径在详情中显式复制 |
| 下边框右侧 | 已修改文件数、文本增删行数 | 后台采集，未知为 `—`，二进制变化不假装有文本行数 |
| 聚焦或悬停 | 放大/还原、收起、展示位置等动作 | 复用现有菜单；删除 worktree 不作为一键边框按钮 |

焦点使用强调边框与 `▸`，等待处理同时显示文字。既有 `●` 继续专用于未保存编辑状态，不作为泛用“运行中”标记。退出与错误可读，不能只换颜色。

窄面板按顺序折叠增删行数、模块路径、次要按钮、Agent 名称；优先保留任务名、分支和高优先级状态。左右信息分别计算显示宽度并保留间隔，不能重叠。极窄时退到单面板模式，更多菜单保留完整信息。

Debug 标题示例：`登录模块 · Debug · cargo run`；底边显示所属分支与命令退出情况。附加会话同样显示所属任务，禁止只有不明来源的“Debug”标题。

### 6.5 右栏项目脉搏与任务改动交集

项目选中时，保留文档 38 已实现的最近提交、12 周热力图、活跃周、30 天文件/目录热点、源码/测试/文档与构建/依赖体积、普通目录排行。其上加入有界任务汇总和需要关注列表；不再把热力图或文件热点列为待开发的新模块。

选任务时展示该任务的基准差异、当前未提交改动、明确运行的检查及操作记录，同时标明统计范围。仓库历史活动只在相同仓库/HEAD/路径范围时共享，任务成果和 checkout 磁盘统计必须隔离。项目磁盘默认只统计主 checkout，不累加同级 worktree，更不为一个项目的每个任务重复扫描同一公共 Git 数据。

共同修改基于每任务“冻结基准 → 当前 HEAD”的已提交路径与 staged/unstaged/untracked 路径的并集，统一成仓库相对路径后求交。使用 Git NUL 分隔路径保留中文、制表符和换行；重命名首版按旧/新路径处理，二进制只比较路径，untracked 只计路径不读取无界内容。不同基准可能带来保守重叠提示，显示比较依据；这不是三方合并冲突检测，也不等于 30 天历史热点。

标题使用“共同修改 / 需要协调”，实际 Git unmerged 单独显示冲突。结果标记任务对、HEAD/基准、更新时间与完整性；没有任务、只有一个任务、后台采集中、采集失败、确认没有交集是不同状态。任务对间按已采集路径集合聚合，避免每一对任务都执行 Git。需要完整路径集，不能拿 UI 的前 5 个热点文件或前 6 个 diff 文件求交；达到文件数/字节/时间预算时明确部分结果，不冒充空集。

检查结果必须关联 task、checkout、提交及运行时变更 revision。单看提交相同不足以覆盖后续未提交编辑；代码继续变化时标过期，不从任意终端文字推断“测试通过”。

## 7. 状态、提醒与用户控制

### 7.1 三类状态分别建模

| 类别 | 示例 | 权威来源 |
| --- | --- | --- |
| 环境/会话生命周期 | 创建中、初始化中、启动中、运行中、已退出、失败、目录缺失 | 创建事务、宿主、进程退出与 Git 校验 |
| Agent 活动 | 工作中、等待输入、已报告本轮完成、未知 | 经验证的 Agent 集成事件或显式程序状态上报 |
| 人工工作流 | 开发中、待审阅、已合并、已归档 | 用户动作及已完成的 Git 操作 |

Agent 本轮完成不等于任务完成；退出码 0 不等于功能验收通过；手动“标记待审阅”不停止进程。“需要关注”包括可靠等待输入、启动失败、异常退出、实际 Git 冲突和资源缺失，展示具体原因。未知不等于空闲。

首版可只显示可靠的命令生命周期与人工状态。Agent 活动能力按 Provider 声明是否支持；未支持时明确“活动未知”。不以输出静默、屏幕关键词或 stderr 非空判定任务失败。提醒聚合在面板、任务行与项目汇总，不强制切焦点或弹出抢输入。

A–C 阶段的轻量提醒只依赖已有可靠生命周期；D 阶段按下述方案交付 Provider 活动、完成提示与系统通知。没有接入事件的 Agent 不能先显示猜测的完成状态。人工工作流仍由用户控制，收到本轮结束事件不自动标记任务待审阅、已完成或已合并。

### 7.2 操作边界

| 操作 | 影响 |
| --- | --- |
| 收起面板 / 返回总览 / 关闭前端 | 改变显示或连接，后台会话继续；会销毁未保存缓冲区时先保护草稿 |
| 停止 Agent | 只停止选定任务的受管 Agent 命令；其他任务与该任务 Debug 默认继续 |
| 停止任务全部终端 | 明确列出该任务 Agent / Debug / Extra，停止后保留 checkout |
| 标记待审阅 | 仅改变人工工作流状态 |
| 归档任务 | 移出常用列表，保留可查询记录；要求相关会话已停止，不自动删除文件 |
| 清理任务目录 | 独立检查与确认，不隐式停止或删除其他资源 |

停止语义复用现有普通停止与强制停止能力，但请求必须携带任务与会话身份。打开 Debug 时若不存在才创建，不重复启动已有命令；配置为“仅 Agent”的任务不预建隐藏 Debug。

### 7.3 通知依赖与 Windows 实现边界

通知后端采用微软官方 `windows` Rust 绑定；2026-11-12 本次网页查询版本为 `0.62.2`，实际实现时复核可用稳定版本并锁入 `Cargo.lock`。仅启用所需的 `UI_Notifications`、`Data_Xml_Dom`、`Foundation`、COM 及实际激活注册相关功能，不引入 GUI 框架。现有 `windows-sys` 保留，不为通知一并重构全部 Win32 调用。

| 用途 | 依赖选择 | 采用理由 |
| --- | --- | --- |
| Windows Toast、事件及激活 | 新增 `windows`，按需启用功能 | 官方 API，可持有通知对象并控制回调生命周期 |
| Hook 事件传输 | 复用 `interprocess` / 现有命名管道基础 | 不新增常驻通知服务或消息中间件；接收入口与现有协议明确分流 |
| JSON hooks 配置与载荷 | 复用 `serde_json` | 不建立通用 hook 框架 |
| 外部 TOML 配置编辑 | 确需修改时再引入 `toml_edit` | 保留用户注释与格式；JSON 原生 hooks 能完成接入时不必引入 |

`tauri-winrt-notification` 本次查询为 `0.8.1`，可独立使用且支持点击回调，但其 `show()` 源码在发送后释放局部通知对象；需要可靠点击交互时仍须验证生命周期。Pebrel 正式 Windows 路径直接持有 WinRT 通知对象，其依赖中的该库另用于诊断，不能仅凭 Cargo 依赖判断正式实现。`winrt-toast 0.1.1` 依赖较旧绑定，暂不采用；跨平台统一接口 `notify-rust` 暂无必要。项目已有 `notify` 是文件系统监听库，不是桌面通知库。以上是功能与维护判断，未测量前不宣称某库体积最小或性能最快。

DevTabs 封装一个薄通知模块：有界发送队列、通知专用线程及正确的 COM 初始化/释放，回调只把导航事件送回宿主/前端，不在回调直接操作 TUI。持有通知对象和事件注册直到明确结束或有界保留期，不能把 `Show` 返回成功等同于用户看见横幅、点击已可靠生效或任务已读。通知失败只记录有界诊断，不阻塞 Agent、输入或状态更新。

使用 DevTabs 自有 AUMID、显示名与图标，不借用 PowerShell 的 App ID。安装/移除只管理 DevTabs 自有注册。普通未打包 EXE 的通知身份、通知中心保留及激活分别按微软文档处理；持有 WinRT 对象不代替 COM 激活/协议激活所需注册。首轮验收聚焦宿主存活时点击回到已有任务，不顺带承诺宿主退出后恢复进程；旧通知点击时宿主不存在须给出已结束/无法连接结果，不自动重启任务。

DevTabs 位于 Windows Terminal 内，回调可用不等于能激活正确 WT 窗口/标签页。点击路由要同时验证宿主、工作区、前端和任务身份，再请求原前端揭示任务；无法可靠激活标签页时明确能力边界，不靠窗口标题猜测或打开重复 Agent。用户常用 Administrator 环境，普通权限/提升权限都列为真机验收；微软 Windows App SDK 的提升权限通知限制不能直接套用为本方案 WinRT 路径已支持或必然不支持。系统免打扰/通知关闭时，应用内结果与未读状态仍有效。

### 7.4 Agent hooks 接入与事件归属

采用 Pebrel 的接入思路，依据官方接口独立实现：`Agent 生命周期事件 → 短时 hook 程序 → 本地命名管道 → 宿主校验/活动状态 → UI 与 Windows 通知`。保留原生 Agent TUI，不为通知替换成另一套聊天客户端或 app-server 界面。

| Provider | 原生接入 | 结束与其他事件 |
| --- | --- | --- |
| Codex | 依据实际安装能力，在有效配置目录的 `hooks.json` 合并 DevTabs 条目；不同时重复安装等价 inline hooks | `UserPromptSubmit`、`Stop`；具备完整能力时再订阅 `PermissionRequest`、`Interrupt`、`SessionEnd` 及精确匹配 `request_user_input` 的工具事件 |
| Codex 旧版能力 | 仅实际支持且需要时接入 `config.toml` 的 `notify` | `agent-turn-complete`；该路径能力有限且上游已有移除意图，不作为长期唯一来源 |
| Claude Code | 在有效配置目录 `settings.json` 中合并官方 hooks | `UserPromptSubmit`、`Stop`、`StopFailure`、`PermissionRequest`、指定类型 `Notification`、`SessionEnd` |
| 其他或未接入 Agent | 明确报告未支持/活动未知 | 不使用界面文本补齐能力；按 Provider 官方契约另行接入 |

配置目录遵循 Provider 的实际配置解析与目录覆盖选项，不写死用户主目录。安装器只管理有明确所有权记录的条目，保留其他 hook、配置字段及既有 notify；重复安装幂等，修改前备份、协调写入并原子保存，失败保留原文件。旧 notify 已被其他工具占用时不覆盖、不无限套娃；无法安全组合就提示冲突，由用户选择。卸载只移除本工具未被外部编辑的条目，显式关闭接入后不得自动装回。

Codex 当前原生 hooks 需要用户在 `/hooks` 中审阅并信任具体定义；安装器不写信任数据库、不绕过审阅。新增/改变命令会影响信任状态，UI 分开显示“未安装 / 待审阅 / 已配置但未验证 / 已验证接入 / 已禁用 / 失败”，附 Provider 版本与能力。配置存在不证明运行成功；以受管运行实际收到的合法事件验证对应能力。Pebrel 用于版本分层的 `0.154.0` 是其本地验证点，不作为本项目未经实测的通用最低版本。

首版可由单独小 helper 或主程序早期分派的隐藏 hook 子命令承载，测量启动开销后决定，不先增加独立服务。必须在普通应用初始化、绘制、日志 stdout 或交互之前分派：有限读取输入、有限连接/写入等待、不输出权限/继续决策，失败也快速以不阻断 Agent 的方式退出。各 Provider 的 stdin/argv、shell 与 Windows 路径引号分别处理，不把含空格、中文、单引号、`$` 的路径直接拼入 shell 命令。

DevTabs 仅在受管 Agent 启动环境中注入管道与运行身份；全局 hook 在其他终端调用时不发送事件且静默退出。宿主校验命名管道访问范围及本次运行令牌、`task_id`、`terminal_session_id`、Provider、conversation 绑定和 generation；cwd 只作交叉校验，不作唯一身份。运行令牌用于关联和拒绝误路由，不宣称能对同权限恶意进程形成安全隔离；令牌不进入常态日志。

子 Agent 可能继承同样环境且共享父 session ID，必须同时检查 Provider 载荷与主/子事件类型。`SubagentStop` 不结束主 Agent；旧运行、旧对话、其他 Provider 或不匹配事件不能更新当前任务。只解析有界结构化事实，不读取全量历史来判断每次结束。

### 7.5 完成含义、可信度与去重

| 合法信号 | 活动/结果含义 | 不得推导 |
| --- | --- | --- |
| `UserPromptSubmit` / 明确继续执行 | 工作中，建立或推进本轮活动版本 | 已有进程运行即 Agent 一直工作 |
| 明确权限请求 | 等待授权 | 所有 `PreToolUse` 都需要授权 |
| 明确用户提问事件 | 等待输入 | 普通文本中的问号代表阻塞 |
| 主 Agent `Stop` | 已报告本轮完成，记录来源与结束尝试 | 最终停止、功能完成、验证通过或可合并 |
| 经版本验证的最终回合事件 | 按明确结果记录本轮结束/失败 | 事件名含 completed 就必然成功 |
| Claude `StopFailure` | 本轮失败及有界错误 | 普通工具失败即整轮失败 |
| Codex `Interrupt` 或其他明确取消 | 已中断，保留结果，不发成功通知 | 用户中断即开发失败 |
| `SessionEnd` / 进程退出 | 会话或命令结束，原因另列 | exit 0 即本轮任务验收通过 |

Codex 和 Claude 的 `Stop` hook 都可能被其他 hook 要求继续；`stop_hook_active` 表示曾由 Stop hook 触发继续，不是当前结束已经最终确认，也不是应忽略所有后续 Stop 的标志。仅收到 Stop 时统一文案为“已报告本轮完成”，将它与经过验证的最终回合结束来源区分。后续明确继续事件立即恢复“工作中”；没有继续事件的 Provider 不作严格终止保证。不得通过固定延时、输出静默或关键词把候选升级为最终完成。

若验收要求“确认本轮最终结束后再通知”，必须接入该 Provider 经验证的后置事件；仅有 Stop 的接入不能声称满足该模式。Codex 本地源码存在最终 `TurnComplete`，需检查其中 `error`，并与 `TurnAborted` 区分；它是后续 Provider 适配的依据，不等于当前原生 TUI 已向 DevTabs 暴露此事件。实现时验证可用的增量事件渠道、版本和会话绑定，不为此全库轮询、不臆造 hooks 字段。legacy notify 能提供报告结束信号，但不提供完整失败/取消证明。

载荷明确包含本轮后台任务仍运行时，显示“回复结束 · 后台任务运行中”，不提示所有工作已经完成。任务自身的独立 Debug 服务不因存活就阻止 Agent 本轮提示；不支持后台任务字段时标明该维度未知，不假设后台数为零。会话退出、用户取消、已知失败和普通子 Agent 结束不得落入成功提示路径。

宿主是活动状态和提醒分发的唯一权威，前端消费状态/结果版本，不各自收到事件再发一次系统通知。按本次 Agent run、Provider、conversation、turn 与结束尝试/活动版本关联，维护有界去重记录：同一结束事件重复投递最多提示一次；同一 turn 经 hook 继续后再次结束应允许产生新结果，不能永久按 turn ID 屏蔽。原生 hooks 与 legacy notify 同时出现时按已验证的来源优先级合并为一次结果，不拼出两条完成提醒。

Provider 缺少稳定事件 ID/turn ID 时明确能力限制，依据已验证的状态边界保守去重，不声称实现跨崩溃严格 exactly-once。过期/乱序事件不能覆盖新的活动版本；不能仅以到达时间认定旧 Stop 属于最新用户输入。启动、重新附着或恢复历史只展示已有结果，不重新发出旧系统通知；只把新受管运行中已校验的事件作为通知来源。管道中断不代表 Agent 空闲或完成。

### 7.6 完成与未读 UI

“本轮结果”和“结果是否已读”分别建模；人工工作流不变。图标遵循现有字体/字符回退与国际化策略，不用颜色单独表达状态。

| 位置 | 提示 | 交互边界 |
| --- | --- | --- |
| Agent 标题 | 绿色 `✓ 已报告本轮完成` 或有最终依据的 `✓ 本轮结束`；显示可读完成时间 | 未知不伪装完成；新一轮开始切回工作中 |
| 面板边框 | 完成时一次短暂强调，再恢复 | 不全屏刷新/闪烁，不覆盖焦点边框含义；支持关闭动态效果 |
| 任务条/任务行 | 独立“新结果”标记；窄屏用有含义的符号和数量 | `●` 仍专用于编辑未保存；隐藏任务也有提示，不改变排序 |
| 项目总览 | 分列“2 个新结果”“1 个等待授权”等汇总 | 项目数仍按项目计；未读结果不当成错误，等待授权等需处理原因保留 |
| 结果详情 | 来源、报告/最终结束区别、时间、有界摘要、查看结果/标记已读 | 不自动跳到终端底部，不用读取全量 transcript 才能展示 |

成功/结束用绿色，等待授权或输入用琥珀色，失败用红色，中断用中性色，同时保留文字。正常结束默认“已报告本轮完成”；界面不得只剩难以判断含义的绿色色块。短暂强调只更新相关装饰，不触发终端内容、Markdown 或图片重新编码传输。

完成、通知及新增结果均不抢焦点、不更改固定 A/B 组合、不调整面板比例、不替换后台任务进入当前分屏、不滚动正在阅读的终端。任务可见、刚好聚焦或收到了系统通知不表示已读；显式“查看结果”/“标记已读”后，通过宿主确认具体结果版本。旧的确认不能清除同时到达的新结果。下一轮开始可保留此前未读结果，历史保留有上限；标记已读不改变 Agent 工作状态。

### 7.7 系统通知策略与点击路由

默认启用已验证接入产生的新结束报告通知，明确文案与信号一致，例如：

```text
DevTabs · new-project
导出功能：已报告本轮完成
feature/export · 点击查看结果
```

默认仅显示项目、任务、分支和事件类别；最后回复摘要由用户开启，始终截断并过滤终端控制字符，不带完整绝对路径、用户输入或无限 Markdown。提供系统通知总开关、“全部任务 / 仅后台任务”范围、声音与摘要开关；“后台”依据 DevTabs 可靠的任务选择/可见状态判断，无法判断 WT 前台状态时不冒充系统前后台检测。关闭系统通知不关闭应用内状态和未读提示。

失败、等待授权/输入可使用独立类别设置，不能与完成共用绿色文案。系统通知使用普通优先级，默认不叠加终端响铃或长时间闪烁；交由系统通知音策略处理。多个任务短时间完成时有界合并提醒，保留各任务结果与定位入口，不通过全局节流吞掉唯一失败/授权提示。具体窗口与上限在实现时测量记录；这是合并已收到事件，不用延时确认完成事实。

点击只提交“查看该结果”导航请求：校验宿主/构建、workspace/task/session/run 及结果身份 → 请求已有前端揭示原任务 → 默认打开该结果关联的本轮文件改动（第 7.10 节） → 确认查看的结果版本。尚在采集或无可靠记录时显示对应状态并提供返回终端入口，不假装已有完整差异。点击动作可以改变焦点，收到通知本身不可以。禁止执行任意载荷命令、自动输入/按 Enter、创建新 Agent 或重新运行 Debug。系统通知外部参数只携带可校验的定位标识，不将其当任意命令行执行。

任务已归档、终端被替换或宿主已退出时，展示对应任务结果/已失效原因，不误跳到当前同名任务，不自动恢复进程。没有可用前端时首轮允许提示需手动打开 DevTabs；支持自动打开只读/连接前端或冷启动激活必须另行验证，不能把恢复任务作为点击副作用。系统横幅未出现不丢任务结果；发送失败、系统设置限制与路由失败分别诊断。

### 7.8 通知闭环的交付顺序

D 阶段先做事件闭环：真实 Provider 能力与配置验证、受管身份、主/子区分、报告/最终结束语义、取消/失败及重复/过期事件测试；然后接 UI/未读状态和 Windows 通知，最后验收点击定位已有任务。两条必验闭环是“结束信号准确归属且不重复误报”与“点击回到已有任务而不重启”。原生 hooks 的限制必须在支持矩阵记录，不能用 fixture 通过或 legacy notify 掩盖未完成的最终结束验证。

### 7.9 通知使用与排查补充

以下六项纳入 D 阶段，优先交付统一待处理入口与通知自检，再补充稍后提醒、任务/单轮控制、关联检查与耗时摘要。复用宿主、既有弹窗和受管检查，不新增通知中心服务、独立定时服务或重复的检查执行器。

#### 7.9.1 统一待处理入口

工作区右上角提供常驻可点击“待处理 3”，总览提供同义入口；窄屏保留数量与可识别图标，零项显示“待处理 0”。点击打开紧凑浮层，支持鼠标、方向键、Enter 和 Esc，沿用现有弹窗层级与裁剪规则，不占用 Agent 普通输入键。浮层内展示任务、原因、时间及定位入口，可筛选全部、等待操作、失败、新结果。

聚合可靠的等待授权/输入、未确认失败与未读结果；同一原因在多个前端或通知渠道出现只计一项，不能让一项失败既作失败又作新结果重复计数。总数计待处理事项，任务数另列；同任务有独立事项可显示多项并按任务归组。等待操作优先，其次失败、新结果，同级按时间排列；用户正在浏览时不因后台更新打乱选中项，新增项以稳定身份合入。点击按第 7.7 节定位，既不授权也不重试命令；等待事项只有可靠解除事件才能消除，确认失败只清未读标记，不抹去失败事实。

#### 7.9.2 通知自检与接入诊断

通知设置提供“发送测试通知”和“检查 Agent 接入”，两条链路分别验证。测试通知带“测试”文案，只验证系统通知发送和测试导航，不生成真实任务结果/未读，也不声称验证了 Agent。自检为用户显式动作，普通启动、设置页面打开及自动化测试不发送真实通知。

接入检查先只读取配置和已收到事件，分阶段展示 Provider 版本/能力、helper 路径、配置所有权、审阅状态（可读取时）、管道接收、最近合法事件与对应能力。无官方可读信任状态时显示“审阅状态未知”，不靠配置存在认定已信任。检查不自动启动 Agent、修改配置或注入消息；需要实际事件时提示用户在既有受管 Agent 完成一轮验证，安装/修复走独立明确动作。

排查结果区分等待审阅、已配置但尚未收到事件、回传错误、事件被拒绝、系统发送失败、发送成功但未验证展示、点击路由失败。每个环节显示时间和可理解的下一步；历史成功不冒充当前配置已通过。诊断提供有界可复制摘要，默认过滤令牌、消息正文和敏感路径，不把进程内 `Show` 成功显示成“用户已收到”。

#### 7.9.3 稍后提醒

未读结果菜单提供“5 分钟后提醒”“30 分钟后提醒”和取消入口。每个结果版本最多保留一个待触发提醒，用户改选时间替换原提醒；默认只补提醒一次，重新安排必须是新的显式用户操作。延后提醒不标已读，也不删除原结果。

到期由宿主复用有界调度重新验证：结果仍未读、仍属原运行/结果版本、任务未归档，且之后没有开始新一轮，才重新发送。已查看、已归档、开始新一轮或结果被后续版本取代时取消；适用通知开关和静音，期间到期被抑制也不在解除静音后补发。首版仅宿主存活时有效，界面明确“本次运行内提醒”，宿主退出后不重放。等待授权如需延后仅抑制提醒，不改变真实等待状态。

#### 7.9.4 单任务与单轮通知控制

任务菜单支持“静音此任务”“恢复通知”“仅提醒下一次结束”；分别设置普通结束、失败、等待授权/输入类别，显示当前范围及策略来源。任务静音/类别偏好可持久保存，单次提醒和本次运行的稍后提醒不跨宿主重启继承。所有静音仅影响系统通知/声音，应用内状态、待处理数量和历史照常更新。

全局关闭优先于任何任务策略，界面明确说明；全局开启时按任务覆盖和类别过滤，未覆盖项继承全局设置。“仅提醒下一次结束”是用户显式的一次性订阅，在当前轮工作中可订阅当前轮，否则等待下一个可靠开始边界；没有边界/关联能力就说明不支持精确单轮，不用猜测。成功/失败结局按已启用类别发出一次，取消不发成功通知；等待授权属于中间事件，不消耗结束订阅。相同事件重投不重复消费订阅；发送尝试失败须显示失败，不自动无限重试。静音任务上开启一次性订阅时明确“本次结束例外”，发送后恢复原策略；全局关闭仍禁止发送。

#### 7.9.5 关联检查结果

复用 D 阶段受管检查能力，用户预先配置并明确启用后，展示“Agent 已报告结束 → 检查中 → 检查通过 / 检查失败”，同时保留原 Agent 信号可信度与检查范围。可选择“立即提醒 Agent 结果”或“仅在检查结束后提醒”；后者不双发普通结束，失败/等待授权仍按各自类别处理。

检查命令、cwd、超时、环境与触发方式均明确配置，不执行 Agent 回复中的命令。自动触发只适用于已验证最终结束信号；仅有可被其他 Stop hook 继续的报告时先提供手动检查，不自动与仍在工作的 Agent 并发运行。每任务有界串行并按结果版本幂等，不在 Agent 终端输入命令，不重用或重启正在运行的 Debug。失败重试由用户发起。

检查记录绑定 task、checkout、Agent run/result、HEAD 和工作树变更 revision，保留检查开始/结束时的版本。期间或之后代码变化即显示“检查结果已过期”，不生成针对当前代码的通过结论；只知道 HEAD 相同不能证明未提交文件未变。检查超时、取消、无法执行、输出截断及版本无法确认分别显示，不归为通过。检查通过只代表已配置检查在对应版本成功，不等于功能验收或已合并。

#### 7.9.6 耗时摘要

结果展示“本轮耗时 12 分钟”“结束于 14:32”，详情可查看带日期的绝对时间，避免跨日歧义。耗时来自同一受管运行、同一逻辑轮的可靠开始/结束边界；Stop 只是报告时标为“截至报告耗时”，最终事件才展示本轮最终时长。内部 Stop 继续尝试不重复累加，用户发起新一轮才建立新计时；Provider 无法区分时显示未知，不猜测拼接。

运行内优先使用单调时钟计算时长、墙上时钟展示时间；缺少开始、事件乱序无法确认、重连后时间依据不足时显示 `—` 并解释原因。总耗时默认包含等待授权、工具执行和网络等待，不冒充模型实际计算时间；只有具备完整可靠边界才能另列等待时长。检查耗时单独显示，不计入 Agent 本轮耗时，通知正文中的耗时仍受用户摘要偏好和长度限制。

### 7.10 每轮文件改动与差异查看

#### 7.10.1 用户目标与比较范围

每轮结束后，用户直接看到“哪些文件变了、改了什么”，点击即可审阅并按需进入现有编辑器。名称采用“本轮期间的文件改动”，列表简称“本轮改动”；用户手工编辑、Agent、Debug、格式化及其他外部进程都可能写文件，缺少独立归属证据时不标为“AI 修改”。无需模型调用或对话解析，压缩上下文不删除已采集的轮次记录。

| 视图 | 比较依据 | 用途 |
| --- | --- | --- |
| 本轮改动 | 同一任务本轮开始基线 → 本轮结束采集版本 | 审阅这一轮期间磁盘文件的净变化 |
| 任务累计改动 | 任务冻结基准 → 指定当前版本，明确包含已提交与未提交部分 | 查看整个任务成果，沿用第 5、6 节口径 |
| Git 未提交改动 | 当前 checkout 的 Git index/worktree 状态 | 查看 staged / unstaged / untracked，不冒充本轮成果 |
| 非 Git 变化观察 | 本轮监听到的路径事件 | 查看观察到的变化，不提供未经保存的旧内容或承诺净改动完整性 |

Git 增量差异和限定范围快照模式比较工作目录可读内容，不能拿开始 HEAD → 结束 HEAD 或结束时 `git diff` 代替。开始前已有 dirty 内容必须进入起始基线；中途 commit 不应使本轮变化消失，也不应把之前的 dirty 全算成本轮新增。仅暂存/取消暂存而文件内容未变不算文本修改，可在 Git 状态另看。修改后完全恢复原内容属于“无净变化”，不是完整写入操作审计；若 watcher 观察到此类路径，可作为辅助记录显示，不能虚构差异行数。非 Git 默认观察模式的清单语义不同，按第 7.10.7 节标注，不能共用“无净变化”结论。

#### 7.10.2 轮次边界与采集状态

自动记录依赖第 7.4、7.5 节已验证的开始/结束及任务归属，采用独立 `round_id` 关联 task、Agent run、Provider turn 和结果版本；不能以对话中的一句话、每次工具调用或上下文压缩创建新轮。Stop 报告只生成标明“截至本次结束报告”的版本；收到明确继续事件则保留该检查点，逻辑轮仍沿用原开始基线，后续结束生成新版本，不累加重复改动。

不支持可靠自动边界的 Agent 提供“开始记录 / 结束记录”，明确为手动记录区间，不假称 Provider 精确轮次。记录期间遇到失败、取消或会话退出也保留已采集变化，显示实际结局；缺少起始基线时显示“缺少本轮起点”，允许查看当前 Git 改动但不能自动替换成完整本轮差异。

起始采集必须保存即将参与比较的前态，结束采集保存后态。后台扫描有采集窗口，不能将 hook 到达时间冒充原子文件快照：若不能证明前态在本轮写入前就绪，标为“起点采集晚于开始/观察区间”；扫描中有并发写入、下一轮开始、watcher 溢出或状态无法确认时标明范围/一致性限制。hook 快速回传和 UI 输入不可为全仓扫描无限等待；需要精确人工基线时，用户先等待“基线已就绪”，再开始操作。实现阶段须先验证此边界，再声明自动模式覆盖范围，不用 watcher 未报错充当全盘一致性的证明。

差异模式的判断流程为：保存可重建前态的基准与例外内容 → 结束时获取变化候选和后态 → 对比较范围两侧路径并集分类 → 对候选文件校验内容 → 按需生成行级比较。Git 模式从已有对象与索引查询路径，不要求逐轮复制/读取全部干净文件；非 Git 快照只枚举用户选定范围。前侧无、后侧有是新增；前侧有、后侧无是删除；两侧都有但内容不同是修改；前后内容一致无净内容改动，元数据变化另列。两侧清单不完整或内容未采到时，相应路径标未知，不能按不存在判新增/删除。目录时间、文件 mtime、Git status 和 watcher 路径仅作辅助信息，不能单独证明本轮内容变化。

采集状态区分待建基线、采集中、可查看、部分结果、起点缺失、中断与失败；有界空的完整结果才显示“本轮无净变化”。通知可以先报告 Agent 状态并打开采集中页面，采集完成不再次发同一轮结束 Toast，也不拖慢 Agent；结果与差异使用独立 revision，避免后续差异就绪又把已读 Agent 结果变为重复未读。

#### 7.10.3 文件前后态与实现约束

沿用 Git CLI、现有文件遍历/监听和 `similar` 文本差异能力，首版不新增 AI SDK、Git 服务或另一套文件编辑器。Git 项目默认采用“提交基准＋例外文件快照”，不每轮复制整个目录，也不为所有干净文件新建内容副本；需要查询文件状态/路径不等于要把每个文件内容再保存一遍。

| 起始文件状态 | 基线保存方式 |
| --- | --- |
| 相对起始 HEAD 干净的受跟踪文件 | 记录基准提交/树，按需读取 Git blob；不逐文件另存内容 |
| 受跟踪但有未提交变化 | 有界保存实际工作目录内容及缺失/类型状态，不以 index blob 代替；包含 staged、unstaged、已删除等例外 |
| 非忽略未跟踪文件 | 在范围和预算内保存实际内容，超限标部分 |
| 未跟踪 ignored、构建产物/缓存等排除项 | 默认不采集，显示范围 |

例如仓库有十万个文件、起点五个修改文件和两个非忽略未跟踪文件，额外内容快照通常只涉及这七个文件，干净部分复用 Git 基准；这是方案示例，不是已测性能。若起点本就有大量 dirty/untracked 内容，仍可能需要明显 I/O 与空间，必须受预算控制。已删除例外用缺失标记，不读取不存在内容；新建暂存文件即使不在 HEAD 树中，也要作为起点已存在的例外处理。

结束候选至少合并“起止提交树差异路径、起点例外路径、结束时工作树相对结束 HEAD 的改动、起止未跟踪路径及可靠监听候选”，再按起点树加例外和结束实际内容验证；开始/结束 HEAD 不变也不能跳过 dirty 比较。Git 路径查询覆盖新增、删除、类型变化与两端重命名路径，统一使用 NUL 分隔。两侧路径并集是逻辑比较范围，可复用 Git 树，不要求每轮重新读全仓内容。中途 commit 通过树差异进入候选，起点 dirty 后恢复干净通过起点例外进入候选，不能仅靠结束 `status`。查询不完整则不声称候选完整。

结束后态如已由可验证 Git 对象表示，优先复用对象；仍未提交内容及非忽略未跟踪内容另存有界只读对象，内容相同可去重。仅存提交 hash 不能保证外部 reset/rebase/GC 后历史永久可读：保留期需要的外部内容依赖须导入 DevTabs 自有只读存储，或采用经验证的独立对象保留方式，不在用户仓库增加隐藏 ref；依赖已缺失时明确历史不可用。只按实际保留所需对象归档，不另复制整个仓库。

Git blob 与工作目录可能存在 EOL、编码、LFS/clean/smudge 过滤差异。比较使用明确一致的表示并保存转换依据，不能把正常换行转换算成本轮修改，也不能声称 LFS 指针等于文件实际内容；需执行任意外部过滤器、属性变化或无法可靠映射时，使用预算内实际内容基线或明确降级/未支持，不无条件运行外部过滤命令。只保存路径、mtime 或起始提交号不能重建所有例外旧内容；普通硬链接不能作为会被原地写入文件的历史快照。

Git 两侧逻辑清单覆盖范围内的受跟踪文件和非忽略未跟踪文件，通过 Git 树/路径查询与例外清单表达，不逐轮复制全量文件；比较两侧路径并集才能发现新增/删除。受跟踪文件即使匹配 ignore 也不能直接排除；若属于用户明确排除的构建产物/敏感范围，则列为范围外而非假装 Git 未跟踪。默认不采集未跟踪 ignored、构建产物、Git 内部目录及外部符号链接目标；明确显示范围，用户可配置排除敏感路径。Git submodule、外部链接、权限拒绝和超限项分别显示不支持/未采集，不递归读取其他任务或仓库。前态未采到的删除文件不能捏造旧内容。

文件快照与清单保存在 DevTabs 数据目录，按 task/run/round 与采集版本隔离，不在项目内生成提交、stash、ref 或暂存区改动。内容去重复用可沿用经验证的内容寻址能力；必须明确内容身份与校验方式，不能只凭 mtime/大小判定无变化。读取期间对文件变化进行有界复核，无法稳定读取则标部分，不无限重试。文件监听在差异模式下只用于候选路径和失效优化，不能恢复从未保存的前态，也不能代替 Git 查询或所选快照范围的结束核对；检查预算不足时如实给出已确认项与遗漏原因。

默认只记录落盘内容；编辑器未保存草稿单独显示“有未保存草稿，未计入”，不自动保存。新增/修改/删除精确记录；重命名只有内容或可靠 Git 依据才能标注并保留新旧路径，否则显示删除＋新增。二进制、超大文件与不支持的编码显示路径、类型及可获取的体积变化，文本行数为 `—`；EOL、编码和权限/类型变化与文本内容变化分别记录，保持原始字节依据。

结束版本一旦封存，后续编辑、提交、分支变化或下一轮运行不改变该版本的前后内容和差异；差异按需从已封存内容计算，不在打开历史时读取当前文件充当旧结果。普通文件系统采集不承诺全仓同一瞬间原子快照，保留实际采集时间窗及完整性。自动关联错误或基线缺失时宁可显示局限，不从 Agent 回复补造结果。

#### 7.10.4 列表、差异与文件导航

任务详情/预览区域提供“本轮改动”入口和最近轮次选择，沿用已有预览标签与边距，不增加常驻第四栏。列表保留稳定文件选择，显示新增/修改/删除/重命名符号、仓库相对路径、文本增删及完整性；绿色新增、红色删除，同时保留符号。总计只对已确认且可计算项求和，部分结果不能展示成全量准确值。

```text
本轮改动 · 第 12 轮 · 截至结束报告        4 个文件  +86 −23

M  src/host.rs                                +42 −12
M  src/protocol.rs                            +18  −6
A  tests/task_events.rs                       +26
D  src/legacy_events.rs                            −5
```

单击文件在预览区域查看本轮前/后版本的统一差异，显示行号、上下文、增删色和可读图例；不因查看就替换原编辑草稿。默认统一差异以适应终端宽度，不把新增左右双栏 Diff 作为首版前置。二进制/超限文件打开元信息及限制说明，删除文件可看前态。支持滚动、搜索、跳转差异块，复用已有预览交互与虚拟化能力。

提供“打开当前文件”进入已有预览/编辑器；快照差异只读，跳转前验证目标仍属该任务 checkout，当前文件已变化时提示“当前文件与本轮结果不同”，可靠映射才定位对应行，否则打开文件并说明位置可能变化。文件已删除时不创建空文件。文件树对当前选定轮次可显示独立“本轮有变化”标记，与 Git 状态、未保存标记分开；当前不存在文件仅在改动清单出现，不伪造文件树节点。通知/待处理“查看结果”默认进入对应 round/result 的改动清单，历史结果不会静默跳到最新轮。

#### 7.10.5 保留、空间与任务隔离

首版有界保留最近轮次，配置每文件、每轮、每任务/全局字节上限、文件数与采集时间预算；具体默认值在代表性仓库上测量确定。到达上限标部分结果并列原因，不悄悄退回 Git 未提交差异。清单、快照、diff 缓存和可视行分别按需读取；大 diff 不全量渲染，每次打开历史不全盘重新扫描。

后台采集按任务公平调度，状态展示不占用输入锁。有界轮次清理与内容引用计数协调，不删除当前采集中、正在查看或仍被保留轮次引用的内容；满额且不能清理时停采并提示。先失效元数据再回收不被引用的对象，崩溃后可对账，不能展示已清理内容为“零改动”。保存空间与清理入口可查看，清理仅影响 DevTabs 历史记录，不修改用户文件或 Git 历史；轮次记录独立于 Agent 上下文，清理须明确将失去哪些本地历史。

#### 7.10.6 交付顺序

纳入 D 阶段，作为成果审阅的优先交付项：先用手动记录及真实 Git fixture 验证提交基准＋例外快照、dirty 起点、中途 commit 与历史不可变；同时交付非 Git 默认变化观察，再接限定范围快照、可靠 Provider 自动边界，最后接通知定位和文件树标记。与既有 Git Diff、编辑、受管检查共享基础设施，但比较基线、内容存储与完整性必须独立。先保证“知道采到了什么”，再优化采集成本；不把 Agent 接入不完整作为展示错误本轮差异的理由。

#### 7.10.7 非 Git 项目的分级支持

非 Git 项目不自动初始化 Git、不创建隐藏仓库，也不另造完整版本控制系统。保留现有单任务工作区，明确提供下列三种选择；没有 Git 不代表不能观察文件变化，不能建立独立 Git worktree 则仍不可使用本文 Git 隔离任务流程。

| 模式 | 行为 | 展示与边界 |
| --- | --- | --- |
| 变化观察，非 Git 默认 | 复用现有 `notify`，在用户配置范围监听并有界合并重复路径事件 | “本轮观察到的文件变化”；可查看当前文件，无前态则不提供历史 diff/增删行 |
| 限定范围快照，用户开启 | 用户选择目录/文件，开始前保存有界内容基线，结束核对同一范围 | 只对已采到前后态的路径展示净差异；显示范围、预算、基线就绪和完整性 |
| 用户主动启用 Git | 提供说明/入口，由用户明确选择初始化并建立基准 | Git 初始化与首次提交是独立明确操作；完成后下一次记录才使用 Git 增量模式，不补造之前的历史 |

变化观察模式无需预先保存全部文件内容，不为每条通知复制文件。记录相对路径、观察到的事件类型/时间及可获取的当前状态；新增/修改/删除/重命名只按实际事件与可核对事实表述，事件合并不保证保留每次写入或最终净变化。修改后恢复原样仍可能留在清单，创建后删除可显示“期间新增后删除/当前不存在”，不虚构最终状态或旧内容。重命名无法可靠配对时显示观察到的旧/新路径事实，不强行推断。

监听一般在写入后通知，此时再读到的可能已经是新内容，不能把事件触发后的首次读取当成修改前基线。对未保存过前态的文件，界面显示“未记录修改前内容”，只开放当前内容预览；已删除文件显示事件信息，不生成空文件或伪 diff。观察记录本身可以按预算保留，但未另存当前内容就不能承诺结束时的内容历史，打开时明确“当前文件”。“本轮没有观察到文件事件”不等于“本轮没有修改”，不能使用差异模式的完整无净变化结论。

范围默认排除构建产物、依赖缓存、版本控制内部目录和外部链接，具体依据项目配置/已有忽略策略展示，不在后台擅自扩展到全磁盘。监听启动/重建间隙、错误、溢出、目录丢失、权限拒绝与超预算分别标“记录不完整”。范围改变产生新记录区间或明确中断，不用新范围重解释旧记录。可有界扫描核对当前存在状态，但扫描不能恢复遗漏事件和旧内容。

限定范围快照例如只选 `src`、`tests`，排除输出目录；开始前显示范围和容量预算，等基线就绪后记录。该范围内需要实际读取并保留前态，缺少 Git/已有前态就无法凭空免除成本。超限项列为未采集，不能在开启快照后对整个项目声称完整 diff；结束版本按第 7.10.3–7.10.5 节规则只读封存、分页查看与回收。默认观察和快照可以复用 watcher，但必须区分事件清单与净差异，数量、行数、已读/通知点击文案和能力标识随模式一致。

记录模式开始时冻结，运行中目录被 `git init`、仓库被移除或配置改变不自动混用两种基线；下一记录周期重新探测能力。Git 无有效 HEAD 时也不能假装存在提交基准，可显式使用观察/限定快照并说明原因。两种非 Git 模式均不需要 AI、对话摘要或 Agent 内容归因。

## 8. 审阅、合并与清理

首版交付任务差异查看、提交前检查和显式 Git 操作入口。合并向导作为独立阶段实现，在此之前通过任务终端完成 Git 操作，界面不能提供无实现的“合并成功”按钮。

合并向导明确源任务分支、目标分支、目标 checkout、两端提交及验证结果。执行前要求源改动已提交、源/目标无正在进行的 Git 操作、相关受管命令已停止，并重新验证 HEAD 与 dirty 状态。目标 dirty 或分支变化时停止执行并重新审阅，不自动 stash、commit、squash、rebase 或 fetch。

首轮内置自动合并只支持经复核可执行的 fast-forward；非 fast-forward 提供在任务终端处理的入口并保留全部上下文。外部进程仍可能修改仓库，检测到竞争或 Git 拒绝时按失败处理，不能声称暂停宿主管理的进程就锁住了仓库。

清理单独确认以下事实：无任务终端占用、无未保存编辑缓冲区、无 staged / unstaged / untracked 改动、任务分支已包含于用户确认的目标提交，且目录及分支所有权确属本任务。Git ignored 文件可能包含 `.env` 或用户成果，清理前列出其存在与有界摘要，默认要求显式确认删除，不视为“干净就没有本地文件”。

仅对 DevTabs 创建的资源使用普通 `git worktree remove` 与满足合并检查的分支删除，不默认使用 force；Git 拒绝时保留资源并解释原因。采用外部 worktree 时默认仅解除任务关联。主 checkout 永不通过任务清理删除。目录移除与分支删除分别记录，部分成功可以重试，不能伪装为完整回滚。

`ownership` 至少区分原项目、DevTabs 创建、外部采用；记录具体创建了哪些资源。repository_key 来自已规范化的 Git common dir，而非分支名；Windows 路径统一现有大小写/规范化策略，符号链接、junction 和 checkout 路径变更应复核身份，不能靠字符串前缀认领目录。

视图保存可见任务集合、输入焦点和比例，宿主保存任务/终端与租约。首版只实现同终端内管理，不为尚未交付的跨窗口移动预建草稿传输或窗口协调服务。

任务元数据只有一个权威记录源，运行快照引用 task ID，不在 Options、恢复日志、历史索引中各存一份可冲突的任务定义。恢复日志记录任务/终端启动意图和必要快照，持久 TaskRecord 不随某次前端退出删除；项目路径规范化仍保留为位置索引，不能代替 task ID。

运行 PID 与连接租约由宿主管理，不作为重启后进程还存活的依据。任务记录用单写者和原子保存，操作事务先登记再执行；重新启动时核对实际资源。持久化错误明确显示，防止成功创建却没有可恢复记录。

活动快照由宿主单写，不把每次事件写回完整任务定义。`agent_run_id` 是一次受管 Agent 运行的身份，不与持久 task、conversation 或 ConPTY 身份混用；管道身份与令牌不写入长期结果。可持久保存有界结果与已读版本，宿主重启后展示为历史，不恢复旧“工作中/等待输入”为实时状态，也不重新发旧 Toast。结果状态不覆写 `workflow_state`；新结束尝试产生新 result revision，已读确认只作用于对应版本。

待处理浮层从已有活动快照、失败与结果记录派生，不复制维护第二套状态。提醒和一次性订阅按任务/结果键保存在宿主的有界运行态；示意 `reminder` 是按结果索引的集合，不是全局只能有一项。设置写入沿用原子保存，跨前端修改校验 revision。检查记录复用已有受管检查模型，补上结果版本和过期依据；诊断读取这些事实，不另起持续扫描服务。

轮次清单引用只读前后态，不存多份完整文本 diff；内容对象、清单及其引用以可对账的原子步骤封存。记录任务 checkout 身份、实际采集窗口和范围，不以 Provider turn ID 或项目路径单独作为快照键。重复结束事件复用同一采集操作；继续后的结束版本保留原基线，各自封存后态。差异稍后采集完成只更新独立差异 revision，不改写已封存内容或重复生成结束通知。记录清理后保留可解释的历史已清理状态，不从当前工作目录重建旧差异。

`recording_mode` 明确区分 Git 增量净差异、非 Git 事件观察和限定范围快照；观察模式不强制具有 before/after 清单或内容引用。Git 基准与例外映射表达逻辑前态，已删除例外和原本不存在是不同状态。Git 对象引用记录仓库/对象/表示来源与可用性，归档所需内容后才宣称保留期可重建；对象缺失不降级使用当前文件。事件观察统计使用“观察到的路径/事件”，不与净差异文件数、行数共用口径。

### 9.2 协议与并发

必须支持运行中 `AddTask` 类操作和按 task ID 打开视图，而不只扩展初次 Open 参数。现有固定终端列表、单工作区视图就绪标记和全会话 attach 流程都需核对；新增终端采用增量发现、按任务范围附着，已有终端对象与租约保持。面板附着与任务创建分别幂等，视图失败不回滚已运行任务。

新增任务查询、创建/启动/停止、布局更新、操作查询和审阅/清理请求，名称在实现时统一。现有 Input/Poll/Resize/Present 已使用 workspace/session ID，不额外引入平行终端通道；宿主根据任务表验证归属，拒绝 task/workspace/session 不匹配的变更请求。改变资源的请求携带 `operation_id`、目标身份及预期 revision；创建异步返回操作句柄，完成后再绑定会话，不阻塞现有 Poll/Input。

会话元数据新增 `task_id`、显式角色与初始 cwd。UI 的任务快照、Git 缓存及 Agent 事件均携带 generation/revision；旧快照不能覆盖新操作。List 仍返回轻量快照，不携带全量 Diff 或终端历史。

Agent hook 接收采用独立有界入口/消息类型，不能让外部 helper 冒充 Input/Stop 等控制请求。规范化事件包含 Provider、主/子来源、会话/运行关联、可选 turn/event ID、事件种类和有界事实，字段按实际 Provider schema 验证，不伪造不存在的顺序信息。查询轻量状态、确认结果已读、通知导航分别用显式请求；前端不拥有系统通知发送权。输入租约与通知导航独立，点击不能隐式夺取另一前端的输入租约。

轮次开始/结束采集、状态查询、分页文件清单、按路径/差异块读取及手动记录使用显式请求和稳定 round/revision；大文件内容不塞进 List/Poll 快照。采集操作携带 task/run/checkout 及预期 generation，过期任务请求不能打开其他任务文件。查询只读，手动记录不向 Agent 注入输入；文件跳转/编辑仍走已有路径校验、草稿保护和输入归属流程。

多个工作区/进程对同仓库的资源修改采用 repository 级操作互斥与 Git 自身锁；多实例数据目录同时操作也需独立于 UI 锁的跨进程协调。停止单个任务不持有全局锁等待子进程退出。

沿用按构建隔离的 IPC；协议变化更新版本与帮助输出。旧宿主保留旧会话，新构建不直接接管旧版运行进程。本轮可直接替换旧配置、日志和缓存 schema；旧开发格式不要求迁移。若读取到无法识别的任务/恢复格式，明确失败并保留原文件，不按字段缺失猜测映射，也不自动重启旧记录。当前新建的普通单 Agent 工作区则按新模型显式创建主任务，这是统一模型，不是旧格式兼容层。

## 10. 性能与可观察性

### 10.1 已测基线与待达目标

现有单 Agent 版本已有以下基线，来源为文档 38 和独立包日志；它们不是多 Agent 性能承诺：

| 已测夹具 | 当前结果 | 用途 |
| --- | --- | --- |
| 200×50 TestBackend，总览 100/1,000 项、100 次切换 | p50 0.375–0.547 ms | 新增任务层级前后的绘制对照 |
| 2,000 文件暖缓存 | 中位 0.120 ms；同夹具未缓存 6.652 ms | 缓存结果一致性与热路径对照 |
| 3,000 Rust + 12,000 构建文件，暖文件系统 | 源码约 7.367–10.359 ms，磁盘约 9–10 ms | 遍历分类基线，不包括大历史热点工作量 |
| 完整 workspace 自动回归 | 360 通过、0 失败、27 忽略 | 实施前须在当时源码重新执行，不能用历史日志替代 |

以下仍是多 Agent 实现预算与验收目标，尚未实测：

- 总览沿用现有后台轮询，不为每个任务另开完整目录扫描。UI 绘制、悬停和焦点切换不启动 Git 子进程。
- Git status、diff numstat、任务基准差异分别缓存；按 checkout、基准/目标 HEAD 和变更 generation 索引。后台 Git 并发初始上限 2，同仓库写操作串行。
- 仅对可见/选中任务优先刷新，后台任务降频；结果有 TTL、超时、输出/文件数上限及部分结果标记。任务数增加不产生无限线程与无界消息。
- 各会话独立保留既有有界终端历史；隐藏 Agent 继续消费 PTY 输出，但不进行完整可视渲染、图片编码或不必要的 resize。
- 一个 Agent 高频输出不能饿死另一个 Agent 的输入与绘制。验证双 Agent 同时输出、一个 Agent 大量输出、隐藏任务继续输出三类场景。
- 目标：参考机器上 4 个 Agent 运行、2 个可见时，DevTabs 本地输入转发与状态更新不出现可感知卡顿；正式验证记录机器配置、输入至本地写入的 p50/p95、帧耗时、CPU/内存与队列峰值，不把模型响应时间混入结果。
- 收集 1 / 2 / 4 个 Agent 的资源曲线，报告相对单 Agent 基线；没有测试数据前不承诺固定 CPU、内存或帧率。

### 10.2 缓存与调度必须先修的边界

1. Git 路径通过 Git 查询解析 checkout root、实际 git dir 和 common dir，支持 `.git` 文件、linked worktree、packed refs 和模块 cwd；不能仅探测 `<cwd>/.git`。缓存版本随口径递增。
2. 历史活动缓存以仓库身份 + HEAD + 路径范围索引；工作树状态/成果以 checkout + task + HEAD/base + 变更 generation 索引。共同修改缓存还要保存参与任务集与各自 revision，不跨 checkout 借用结果。
3. 源码/磁盘继续分别标记数量上限、时间预算和读错误，只有对应下界加 `≥`；文档 38 现有固定上限约 10 分钟、暂时性问题 30 秒重试策略保留为基线。共同修改使用独立完整性标记，未完成不能标无重叠。
4. 现有 overview 查询 worker 会排空队列只执行最后请求；可用于已过期的当前预览，但多任务批次需要按任务键合并、公平轮转，创建/初始化/清理操作绝不能被丢弃。先复用有界 worker，再按测量调整，不按任务数无限建线程。
5. 每任务保存整套 Sidebar 可能同时保留 watcher、图片缓存和文档。必须测量未保存草稿保留时的内存，关闭隐藏图像呈现和预取，共享同内容只读资源；不得为省内存直接丢草稿。输出/输入队列、历史长度、后台批次均有上限。
6. 保留现有性能统计并增加任务切换、消息排队、上下文读取、Git 等待/执行、交集聚合、隐藏面板渲染/图片输出等阶段计数。记录前后同机同夹具数据；只有有测量收益且功能测试通过的优化保留。

操作诊断包含 task/session/operation ID、阶段、耗时和有界错误。常态产品界面显示任务名与可理解原因，内部 ID、PID 和原始参数留在诊断详情。

通知增加 hook 启动/回传耗时、接收至状态更新、状态至通知发送、点击至导航完成的 p50/p95，以及接收/拒绝/去重/合并/丢弃数量、队列峰值和通知对象保留数量。拒绝原因区分无受管上下文、旧 run、身份不符、子 Agent、格式/大小错误和来源未验证；日志不记令牌及默认关闭的消息正文。比较无接入与启用 hooks 的同机基线，覆盖 1/2/4 Agent 及重复/突发事件。时间/字节/队列/保留上限均需明确、可测，不按任务创建无限线程，不把系统横幅展示延迟混入模型耗时。UI 状态不等待 WinRT 完成，系统通知失败不退回同步绘制路径。

本轮改动采集单独测量起点就绪时间、前/后枚举/读取/校验、差异计算、首屏/滚动耗时、读写字节、磁盘保留量、去重收益和不完整原因。覆盖 1/2/4 任务、已有 dirty、小仓库/大仓库、二进制与超大文件、连续轮次及边界并发写入。测量明确快照范围与实际捕获窗口；采集成本不能隐入通知或 Git status 基线。优化保留同夹具内容和完整性验证，watcher/缓存加速不牺牲新增/删除发现，不把低耗时但漏文件认定为优化成功。

分别测量大量干净受跟踪文件＋少量例外、大量 dirty/untracked、非 Git 默认观察和限定快照。Git 增量验收统计新存内容数/字节与候选读取量，证明没有逐轮复制所有干净文件；同时保留状态查询真实耗时，不宣称 Git status 无全仓元数据检查成本。非 Git 观察不以扫描/快照耗时对比冒充同等精度，性能报告必须带记录模式、覆盖范围与完整性。

### 11.1 自动化与集成验收

1. 临时真实 Git 仓库创建两个任务，修改同名文件互不影响；两个分支从确认基准创建，dirty source 不静默丢改动。
2. 同一操作重复提交只创建一次；分支/目录冲突、初始化失败、Agent 启动失败、超时与创建后崩溃均能准确对账，不删除外部资源。
3. 两个 ConPTY shell fixture 同时运行，键盘、粘贴、停止、路径插入准确路由；删除或收起中间任务后其他会话身份与进程不变。
4. 横竖切换、拖动、放大还原、窄窗退化和恢复不重启任务，不产生零尺寸；隐藏面板无输入命中区。
5. 两任务包含同名文件、不同内容和未保存草稿，切换后树/预览/编辑/Debug 对应正确；旧后台读取不能覆盖新上下文。
6. 边框覆盖中文长任务名、长分支、浅/深主题、退出码、活动未知和各宽度，无左右重叠；统计未完成不显示零。
7. 总览搜索命中任务时保留父项目，折叠/排序/刷新保留身份与队列；父子同时入队不重复启动任务。
8. 重连现有宿主恢复原任务；宿主退出或系统重启后明确进程已丢失，用户显式恢复才创建新进程，不盲目续跑任意 Debug 命令。
9. 差异区分已提交/未提交与目标分支，二进制和冲突正确标记；共同修改不显示为已确认合并冲突。
10. 清理覆盖运行终端、未保存草稿、dirty/untracked/ignored 文件、未合并分支、原项目、外部采用、目录缺失及部分删除失败。
11. 按任务操作同时进行时，普通输入不被 Git/初始化长操作阻塞；资源规模与公平性测试记录真实预算。
12. 保留 `tests/project_pulse.rs`、`tests/overview.rs`、`tests/reference_parity.rs` 与既有 workspace/image/sidebar 测试；40 条历史不能变成 40 个任务，F9 搜索/新会话/原生选择不继承旧 ID，任务模块 cwd 不借用主目录历史。
13. linked worktree 的独立 index、HEAD 更新、公共 refs 与 packed refs 变化分别使相应缓存失效；任务 A 修改不能污染 B 的成果，公共历史仅在相同范围复用。
14. 左栏折叠/搜索/父子队列与已展开历史同时存在时保持身份；点击“← 总览”选回原 task/session，被过滤仍可揭示，取消草稿离开不切导航。
15. 同名图片、Markdown 内嵌图片、SVG、浮动 Debug 叠加与高速任务切换，过期解码/路径校验不覆盖新任务或输入新 Agent；隐藏图片不反复重传。
16. 共同修改的完整集合超过展示条数仍可发现交集；不同基准、重命名、二进制、未跟踪、预算中断与权限错误覆盖，部分结果不显示为确认无交集。
17. A 的 Agent/Debug 正在输出、存在 staged/unstaged/untracked 与编辑草稿时，从 A 追加 B，再追加 C；A 的分支、index、文件、PID、对话、草稿不变，B/C 基于已确认提交，不依赖关闭 A 或重回总览。
18. 同一个 TestBackend/隔离前端中，A/B 的真实终端输出同时更新；分别点击后输入下一步，只写入选定终端，切换保留两边未发送文本；重连 B 不新建任务或撤销 A 租约。
19. 创建 B 期间 A 再次提交，B 仍从冻结 hash 创建；表单关闭后 A 可继续输入，B 成功不把正在给 A 输入的文字送入 B。
20. 端口被占用、相同数据库名称和共享构建目录配置分别测试；只对已配置资源检查/提示，不将这些结果冒充文件 worktree 隔离的失败或成功。
21. 同一窗口宽屏左右/窄屏上下、显式布局偏好、放大还原及第三任务收起/替换均保持会话身份。新建任务不调用 WT 新窗口/新标签页启动；窄窗降级明确提示，扩大后恢复双面板。
22. 键盘上一/下一任务及按编号定位与鼠标选择一致，和下一终端会话分开；菜单消费前缀，返回后普通键入只到新目标，Debug 不因任务编号被误选为 Agent。
23. 大段粘贴、异步路径校验、拖拽执行中切换焦点，原操作始终投递原 task/session；目标中途断连或接管时不转发、不重复未知写入，其他 Agent 收不到碎片数据。
24. 主分支与当前任务 HEAD 不同，两个快捷来源分别产生正确 B 基准；默认分支未知、只有功能分支、没有 HEAD、dirty/未保存时界面范围说明准确，无静默 fetch 或源分支切换。
25. 未聚焦任务持续输出、命令退出或失败仅更新有界提示，不抢焦点、不更改任务排列；输出静默和匹配到“完成”文字均不能生成完成/等待事件。
26. 固定 A/B 后新增 C/D、接收提醒、缩窗还原、临时放大 C，固定组合/比例与草稿可恢复；固定对象被停止/归档时可解释，不自动替换为其他任务。
27. B 局部失败后仅恢复 B，A/C PID 不变，B 的存活 Debug 不重启；重复恢复、旧进程尚在、对话无法验证及宿主整体丢失分别处理，不能误报局部恢复成功。
28. Hook 安装/升级/卸载保留其他条目、注释及既有 notify，重复安装无重复组；无效配置、备份失败、并发外部编辑、用户修改自有条目、显式禁用和命令路径变化分别覆盖。Windows 空格/中文/单引号/`$` 路径不串参数；未审阅的 Codex hooks 不能显示接入已验证。
29. 伪 Provider/fixture 覆盖合法开始、Stop、明确继续、再次 Stop、失败、取消、SessionEnd、主/子事件及后台任务；同 turn 继续后可生成新结果，重复结束只提示一次，原生与 legacy 不双发。屏幕“完成”、BEL、静默、普通工具失败、exit 0 均不能冒充验收成功。
30. A/B 同 Provider、相同或不同 conversation、cwd 被改变、旧 run/turn 乱序、伪造来源、部分/超大输入、无受管环境、helper 超时、宿主断连分别验证；不串任务、不阻塞 Agent，重连/重启不重播旧通知，不把未知后台数当零。
31. TestBackend 验证完成、等待授权、失败、中断、浅/深主题、窄屏字符回退、中英文文案及未读计数；完成不改变焦点、固定组合、比例或滚动位置，不重传图片。结果可见不自动已读，确认旧 revision 不清除新结果，下一轮工作中与旧未读结果可并存。
32. 用可替换通知后端验证单宿主发送、多个前端不重复发送、关闭/范围/摘要设置、有界突发合并、发送失败与对象释放；不在普通自动化中弹真实系统通知。事件至 UI/Toast 请求与点击路由统计有前后数据，不用发送成功代替用户已看到通知。
33. 通知点击携带正确/旧的 task/session/run/result，任务归档、前端不存在、宿主已退出、通知中心旧条目、租约被其他前端持有时分别处理；不启动 Agent/Debug、不自动输入、不接管租约、不跳同名其他任务。只有真实激活验收通过的运行环境才声明点击可定位支持。
34. 待处理聚合覆盖同一失败同时属于新结果、同任务多个事项、多前端重复来源与解除事件；数量/筛选/稳定选择准确，后台更新不跳选。浮层鼠标/键盘、Esc 还焦点、窄屏/国际化正确，定位不自动授权或执行重试。
35. 测试通知不产生真实结果或未读；接入检查区分配置、信任未知、历史事件、回传/拒绝/发送/点击失败，不主动启动 Agent、修改配置或弹通知。普通打开设置不触发真实自检，复制诊断不含令牌和正文；真实横幅由用户单独验收。
36. 使用可控时钟验证 5/30 分钟提醒替换、取消、到期只发一次；已读、新一轮、结果替换、归档、静音、全局关闭和宿主重启均不补发过期提醒。多任务各自提醒不串，重复调度不重复发送，无每任务独立线程。
37. 覆盖全局/任务/类别继承、静音的单次例外、当前轮/下一轮订阅、失败/取消/授权中间态、无开始边界、重复结束与发送失败；一次性订阅只消费一次，不跨宿主重启恢复，不因关闭系统通知丢应用内状态。
38. 配置检查只在明确启用且允许的结束边界自动运行；仅 Stop 报告不自动并发检查。重复事件不重复运行；检查前/中/后 HEAD 或 dirty revision 变化、超时、取消、无法执行、未知版本与输出截断分别展示，旧通过不算当前通过。“仅检查结束提醒”不双发普通结束、不抑制独立授权/失败提示，不写入 Agent/Debug 输入。
39. 耗时覆盖可靠开始/结束、Stop 继续、用户新一轮、缺少开始、乱序、重连、跨日与墙上时钟调整；只有可靠时长展示数值，报告/最终/检查耗时分开，不将等待或模型响应时间误标为模型计算时长。
40. 临时真实仓库中先制造 staged/unstaged/untracked，再建立轮次基线；本轮修改/新增/删除/重命名、中途 commit、仅暂存、修改后恢复原样均按前后内容产生正确净变化，旧 dirty 不重复计入，最终 Git clean 不漏本轮成果。采集不修改工作目录、index、refs 或创建提交/stash。
41. 同一 turn 的 Stop、继续、再次 Stop、最终结束、取消、失败、手动记录及重复事件绑定正确 round/revision；缺少基线、起点晚采、扫描中写入、下一轮提前开始、断连与过期 run 不能显示伪完整结果。压缩上下文不删除记录、不切轮；后续编辑/提交及切分支不能改变已封存差异。
42. 两任务同名路径/不同内容隔离，新增/删除通过两侧清单并集发现；枚举不完整不把未知当不存在。受跟踪 ignored、非忽略未跟踪、未跟踪 ignored、二进制、超限、编码/EOL、权限错误、符号链接/外部路径/submodule 和未保存草稿分别验证，不读取外部任务或自动保存草稿。
43. 列表数量、增删汇总、统一差异、搜索/差异块跳转、部分状态、中英文/窄屏、选定轮次文件树标记及通知定位正确；打开当前文件时检查身份/版本，旧行无法映射则说明，不创建已删除文件、不覆盖编辑草稿、不改 Agent 输入焦点。差异晚到不重复通知或错误清除/新增结果未读。
44. 有界存储覆盖重复内容复用、文件/字节/时间上限、轮次淘汰、并发查看引用、崩溃部分落盘、磁盘满及损坏内容；保留记录仍可读取，清理仅影响本地历史，不删除工作文件或用当前文件补旧内容。采集/大 diff 虚拟化记录升级前后同机数据，不能靠漏采改善性能。
45. 大量干净受跟踪文件＋少量 dirty/untracked 的 Git fixture 验证仅基准引用和例外内容新增存储；覆盖 staged 新文件/删除、起点 dirty 后恢复干净、中途提交后最终 clean、仅 index 变化、起止 HEAD 相同以及不完整查询。候选合并不漏净变化，不修改用户 refs/index，记录实际 I/O 与查询成本。
46. Git CRLF/属性变化、特殊过滤器/LFS、对象缺失、reset/rebase/GC 及历史内容归档分别覆盖；比较表示一致，不无条件执行外部过滤器，不以当前内容补缺失历史。保留成功必须对应内容依赖确实可用，不能仅测试 hash 仍在元数据中。
47. 非 Git 默认模式不保存全量文件内容、不初始化 Git；事件修改后恢复、新增后删除、重复/乱序事件、无法配对重命名、watcher 溢出/重建/权限失败及范围改变均显示观察语义。无事件不等于无修改，无前态不显示 diff/行数；打开查看的是当前内容时明确标注，删除文件不创建占位文件。
48. 非 Git 限定快照只覆盖所选目录，基线未就绪、超限、排除项、并发写入、未保存草稿及历史回看按能力处理；配置不会隐式扩展全项目。运行中启用/移除 Git、无 HEAD 仓库和下轮模式重探测不混基线，只有用户独立明确操作才初始化/提交，旧轮记录不补造；单任务记录可用不等于 worktree 隔离可用。

每阶段保存升级前后测试与性能证据。自动检查使用串行测试避免现有全局主题状态的并行竞争：

```powershell
cargo test --workspace --target-dir target/perf -- --test-threads=1
cargo clippy --workspace --all-targets --target-dir target/i18n-check -- -D warnings
cargo fmt --all --check
```

UI 单元测试验证几何与事件语义，Git 集成测试验证真实资源行为，ConPTY fixture 验证会话生命周期。涉及真实 Codex / Claude 的状态、hook 信任/继续行为、恢复能力与系统通知激活由用户做真机验收；开发自动化不启动已安装 Agent、真实 WT 窗口或系统通知，不以 shell/hook fixture 冒充 Provider 集成已通过。

### 11.2 真机验收路径

先只打开任务 A“登录模块”正常开发，运行 Agent/Debug，保留未提交文件和编辑草稿；开发中点击“＋ 新任务”，只填“管理后台”，选择从 A 当前提交创建，在同一个终端界面打开 B。确认 A/B 都实时输出且 A 的改动/草稿仍在，只对 B 的独立目录写入。

点击 A 输入下一步，再点 B 输入另一条任务；两边保留各自尚未发送的文字，提交只到所选 Agent。验证边框与底栏输入目标、宽屏左右/窄屏上下、拖动、放大还原。继续追加 C，收起 C 或选择两个主要可见任务，全部进程保持运行，不新开 WT 标签或窗口。

回总览后重新进入，确认原进程、可见任务和输入目标恢复；面板连接失败可重试而不重复创建任务。再检查同名图片/Markdown、任务侧栏/Debug 跟随和未保存草稿。最后审阅差异与共同修改；同名文件在开发时互不覆盖，合并需要协调时如实提示。仅对无未保存成果且符合检查的任务执行清理。

D 阶段通知验收由用户在真实 Codex/Claude 上进行：按实际版本安装并审阅 hook，A 持续工作时让 B 结束，检查提示准确、无重复且焦点仍在 A；触发授权等待、用户中断、失败、子 Agent 完成及 Stop hook 要求继续，分别核对文案和支持边界。验证查看结果后的已读版本，下一轮开始与旧未读结果不混淆。先普通权限、再 Administrator，覆盖 WT 前台/后台、同窗口多个标签、多个前端、系统通知关闭/免打扰和通知中心点击；点击只定位已有任务，关闭宿主后再点旧通知不得重启进程。记录 Windows/WT/Provider 版本、权限、注册状态及真实结果，任何未覆盖组合标为未验证。

补充体验验收：从“待处理”定位后台任务且保留原输入草稿；分别发送明确的测试通知与检查 Agent 接入，确认不会互相冒充通过。对 B 设置稍后提醒，再查看/继续 B 验证旧提醒取消；静音 A、仅订阅 B 下一次结束，确认策略可见且不影响应用内状态。启用用户配置检查，核对报告/最终结束能力与触发边界、代码变更后的过期提示、仅检查结束提醒及耗时摘要，不以测试通过作为合并验收。

本轮改动真机路径：A 已有未提交文件时建立基线，让 Agent 在一轮中修改旧文件、创建/删除文件并提交部分成果；结束后核对清单与实际前后内容。点击文件审阅差异、打开当前文件，随后手动再次编辑并切换另一轮，旧结果保持原样。验证通知直达对应轮而非最新轮；压缩上下文后记录仍在。不支持可靠边界时使用手动记录，起点未就绪/结束采集中明确展示，不能用外观正常掩盖范围不确定。

再打开一个非 Git 项目，用默认观察记录改动，确认只提示观察到的路径、无旧内容时不显示历史差异；显式只选择源码目录开启快照，等基线就绪后修改并核对范围内 diff、范围外提示和容量限制。工作区不得自行生成 `.git`。Git 大项目需核对额外存储随 dirty/untracked 与实际成果增长，而非每轮复制整个仓库；性能和正确性分别记录。

## 13. 实现前需真机校准的参数

产品主路径已确定。以下参数允许依据测量调整，但不能改变任务隔离和输入归属：单面板最小 40×10、双 Agent 首次按可用尺寸选择左右/上下排列、60 列阅读舒适阈值、后台 Git 并发 2、任务标题折叠优先级、状态刷新周期与交集扫描预算。

Provider 的活动状态与历史恢复支持必须按实际安装版本核实，缺少可靠能力时按未知/手动恢复交付，不通过屏幕文本猜测补齐。验收结果与最终支持矩阵另写实现验证文档。

通知还需校准 hook 启动/回传预算、Toast 队列与对象保留上限、突发合并窗口、边框短暂强调时长，以及普通/提升权限下的原前端激活能力。所有参数调整不得把 Stop 报告升级成最终完成证明，也不得用节流、清除未读或自动切焦点掩盖事件丢失。

轮次改动需校准快照就绪/采集窗口、文件/轮次/全局存储预算、保留轮数与差异首屏预算；首先证明有 dirty 和中途 commit 的正确性。不能只凭 watcher 或后台扫描很快就承诺精确边界，不使用 Agent 自述来填补缺失前态。

Git 增量对象归档、表示转换与非 Git 限定快照预算单独校准；默认事件观察不承担全盘旧内容保存。三种模式的能力、空间、时间与不完整说明同步进入帮助/设置，不把“项目不是 Git”变成自动初始化的授权。

## 15. 实施前自评与收紧的交付边界

本方案的身份、隔离、同屏输入和分级文件记录方向可以进入实施；仍不能把“设计覆盖”视为运行能力已经验证。实施任务与 TDD 顺序见 [39-Parallel-Agent-Workspace-TDD-Implementation.md](39-Parallel-Agent-Workspace-TDD-Implementation.md)。以下规则补足容易误实现的边界，实施按此验收：

1. **自动轮次不承诺原子快照。** hooks 回传快，不代表前态来得及采齐；现有原生 Agent 输入无法统一在提交前冻结整个工作目录。默认自动模式按实际捕获窗口标“观察区间/部分记录”，只有可验证就绪的基线与明确区间才能给出相应范围完整性。不得为追求完整性接管 Agent 输入、无限阻塞 hook，或靠监听安静推断全盘原子一致；手动准备基线是独立可用路径。
2. **Git 状态与表示必须验证。** 起点例外以实际工作树相对冻结提交的状态确定，不能只判断 index。候选查询须覆盖两个端点的例外、新增和删除，忽略规则/attributes/config 在区间内改变时重新核对或标部分，不沿用过期规则声称完整。CRLF 等表示不能可靠等价时保留实际前态或降级，Git hash 与工作树字节不可直接混比。
3. **Git 对象复用与历史保留分开。** 运行中复用用户仓库对象，封存结果时只归档差异实际依赖的前后内容，而非完整仓库；仍未稳定的封存版本显示采集中。对象在归档前被外部 GC 移除、读取失败或超预算时标不可重建/部分，不能以仅有提交号宣称历史可用。保留内容的正常历史在用户仓库 reset/GC 后仍可查看。
4. **通知交付按能力拆开。** 事件接收、状态更新、系统发送、实际展示和点击定位是不同验证点；精确 WT 激活失败不能用新建 Agent 补救。接入/显示可先完成，点击激活未过真机测试时必须标未验证；未过的能力不计整个通知闭环完成，不允许借此省略点击路由任务。
5. **成本预算需要初始值和明确退化。** 文档 39 给出第一轮实现的可配置默认值和失败语义，它们是待测参数而非性能承诺。先验证部分结果、磁盘满、队列满及旧任务失效处理，再做缓存/去重优化；无数据时不以“轻量”替代测量，也不默默截断清单冒充完整。
6. **阶段交付与覆盖率不能互相替代。** 0–C 是隔离同屏的首个体验，D 的轮次审阅、接入/通知和六项补充、E 的合并清理各自有独立退出条件。测试先验证用户可见行为和失败保护，再实现最小路径；真实 Provider、Windows 通知和 UI 由用户验收，fixture 通过不等于真机完成。所有新任务初始待实施，不复用历史 360 通过作为本次证据。
