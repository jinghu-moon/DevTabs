# DevTabs File Sidebar Implementation

日期：2026-11-10。升级基线 DevTabs 0.2.0，交付版本 0.3.0。两阶段功能已实现；实际检查、性能、原生 Agent 测试及人工验收边界见 [07](07-File-Sidebar-Verification.md) 与 [08](08-File-Editor-Verification.md)。以下规格按最终实现修订，不能把验收矩阵中的每个场景都理解为已自动通过。

本文承接 [文件树库调研](05-File-Tree-Library-Research.md)，并纳入随后确认的 Markdown 渲染方案。实现完成后，本文件规定的行为作为侧边栏验收依据。

交付分为两个阶段：第一阶段完成文件树、只读预览及向 Agent 插入路径（第 1–12 节）；第二阶段在第一阶段验收后增加单文件源码编辑（第 13 节）。编辑不作为第一阶段的交付前置条件，也不能通过编辑功能变更第一阶段默认只读的行为。

## 1. 目标与工程约束

用户在项目工作区内浏览目录，点击文件即可只读预览；将文件从侧边栏拖至 Agent 区域，自动插入文件绝对路径，不提交提示词。侧边栏整体与各级目录均可折叠、展开。

项目仍处开发期，允许重构及破坏性改动，不为旧结构保留兼容层。必须先记录升级前测试与性能基线，实施后验证新功能及既有终端能力。以下设计参数是本轮建议采用的实现默认值，不冒充访谈中的用户逐项决策。

从基本事实推导实现边界：

1. 文件树是目录和文件的视图，不是进程管理器；读取本机文件不需要后台宿主或新 IPC 服务。
2. 预览只读取内容，不应启动 shell、运行文件、改变项目工作目录或重建 Agent 会话。
3. 树、预览和终端共用一个窗口，绘制与鼠标命中必须使用同一份布局计算结果。
4. 原生 Agent 输入框不属于 DevTabs；DevTabs 只能向已有会话输入流发送文字，不能可靠识别任意 Agent 内部页面。
5. 拖放文件等价于插入路径文字，不等价于执行命令、上传文件或发送模型请求。
6. 大目录读取、语法高亮和文件监听不能阻塞输入与终端输出读取，所有缓存与工作队列必须有界。

由此采用现成树组件、现成 Markdown/代码渲染器和既有会话通道，仅补充业务连接。首版不引入 WebView、完整编辑器、通用拖放框架、全项目索引数据库或新的常驻进程。

## 2. 第一阶段交付范围

| 能力 | 本轮行为 |
| --- | --- |
| 项目文件树 | 以工作区项目根为根节点，目录按需加载、展开、折叠、滚动和刷新 |
| 文件类型图标 | 默认启用 Nerd Font 图标，使用 devicons 映射及少量自定义覆盖；提供手动关闭入口 |
| 侧边栏整体 | 默认展开；可手动收起，保留可恢复入口；空间不足时临时自动隐藏 |
| 点击文件 | 单击打开同一个只读预览面板，再点其他文件替换内容，不累积标签页 |
| 快速定位与导航 | 在已加载节点中按名称定位、折叠全部目录、从预览定位回文件树，不建立全项目索引 |
| 文件操作 | 复制绝对/项目相对路径、在资源管理器中定位，通过按钮或键盘操作菜单访问 |
| 普通文本和代码 | 文本读取、语法高亮、行号、纵横滚动；未知语言退回普通文本 |
| Markdown | 默认渲染阅读模式，可切换源码模式；复杂内容按第 6 节降级 |
| 预览阅读操作 | 当前模式内查找、上一处/下一处、选择复制与复制内容；自动刷新尽量保持阅读位置 |
| 拖至 Agent | 同一 DevTabs 主视图内拖放，插入带引号的绝对路径及尾随空格，不发送 Enter |
| 键盘等价操作 | 对选中文件执行“插入路径”，复用与拖放相同的逻辑 |
| 文件变化 | 自动刷新受影响的已加载目录及当前预览，提供手动刷新作为补充 |
| 生命周期 | 打开/关闭树与预览不重启、不关闭现有会话；不改变后台存活约定 |

首版不包含文件编辑、保存、创建、重命名、删除、移动、多文件拖放、目录拖放、跨窗口拖放、Windows Explorer 拖入，以及图片/PDF/Office 的内嵌渲染。系统默认应用可以打开这些文件，但这不构成 DevTabs 内嵌预览支持。

此处“首版”“本轮”及第 3–12 节均指第一阶段；文件编辑和保存已安排为第二阶段任务，见第 13 节。文件创建、重命名、删除、移动等文件管理操作仍不纳入第二阶段。

Git 状态徽标、多标签预览、多选批量操作和拖动调整布局留待后续真实需求再评估；本轮不为这些能力预建索引、插件或持久化状态体系。

| 文件变化 | `notify 8.2.2` | 使用 Windows 原生 watcher，合并通知后刷新受影响目录 |
| 布局与鼠标 | 项目既有 Ratatui/Crossterm | 不添加另一套事件循环或拖拽框架 |

版本为 2026-11-10 调研结果；实施时再次核对最新稳定版并通过 Cargo.lock 固定。不得从 Git main 随意引入未发布 API。新增库不得产生 Ratatui/Crossterm 不兼容的重复事件类型。

最终选择 Syntect `default-onig` 与适配层 `regex-onig`：tui-markdown 的代码块高亮特性启用 Oniguruma，统一后端避免同时引入两套正则引擎。Windows 实际构建与 release 基准通过。补充 `unicode-width 0.2.3`、`unicode-segmentation 1.13.3`；第二阶段使用 `ratatui-textarea 0.9.4`（search）与 `regex 1.13.1`。确切依赖树由 Cargo.lock 固定。

## 4. 界面、布局与焦点

### 4.1 主视图

文件树仅出现在工作区主视图，不出现在项目总览、共享 Debug 小窗、Debug 标签或额外会话独立视图。Float/Tabs 的 Agent 主视图与 Split 主视图均可使用。

空间足够时的示意，列宽不按图中字符数硬编码：

```text
Float / Tabs 主视图
┌ Files ─────┐┌ Agent ───────────────────┐┌ Preview ──────────┐
│ ▾ src      ││ 原生 Agent               ││ README.md          │
│   app.rs   ││                           ││ 渲染 / 源码 / 关闭 │
│ README.md  ││ 输入区                    ││ 只读内容           │
└────────────┘└───────────────────────────┘└────────────────────┘

Split 主视图
┌ Files ─────┐┌ Agent ──────────┬ Preview ─────────┐┌ Debug ──────┐
│ 文件树     ││ 原生 Agent      │ 只读文件内容     ││ 原生 shell  │
└────────────┘└────────────────┴─────────────────┘└──────────────┘
```

文件树与预览是独立区域，可同时存在；预览不替换文件树。默认侧栏宽度 28 列，空间不足时缩至最低 20 列；首版不增加拖拽调整宽度。预览从 Agent 区域分配空间，Debug 区域继续作为终端。保证绘制出的终端有可用尺寸，不能把边框区域当成内容区域。

空间不足时按顺序处理：先将预览改为覆盖 Agent 的面板，再临时隐藏侧栏；仍不满足既有终端最小尺寸时显示扩大窗口提示，并保留最后有效的 ConPTY 尺寸和连接。自动隐藏不能覆盖用户“手动展开”的偏好，放大后按偏好恢复。

覆盖预览时 Agent 不分离，继续读取和更新；保留上一有效尺寸，不发零尺寸。用户从树开始拖动后，临时移开预览，露出 Agent 作为落点；取消拖动恢复预览，成功插入后保持 Agent 可见，预览内容和滚动位置仍可恢复。

关闭预览恢复 Agent 区域，收起侧栏保留当前预览。布局改变仅调整视图与有效终端尺寸，不触发 `Open` 或创建新 shell。

布局按终端单元格计算，以下为本轮明确采用的起始参数，均包含在统一布局函数和边界测试中：

| 区域 | 最小内容宽度 | 两侧边框计入后的宽度 |
| --- | --- | --- |
| Agent | 60 列 | 62 列 |
| Preview / 第二阶段 Editor | 40 列 | 42 列 |
| Split Debug | 30 列 | 32 列 |
| Files | 18 列 | 20 列，默认 28 列 |

顶层预留现有底部 2 行，剩余正文至少 10 行（含上下边框，内容至少 8 行）。各面板边框不重叠，因此不能少算分隔处的边框。设窗口宽度为 W，Float/Tabs 基础终端宽度预算 B=62，Split 的 B=94；按以下顺序计算：

1. 用户请求显示侧栏时，W≥B+20 才显示，侧栏宽度 S=min(28, W−B)；否则临时隐藏，S=0。用户手动收起时 S=0，不因窗口变宽自行展开。
2. 可用终端区 T=W−S。Float/Tabs 的 Agent 区域 L=T；Split 的 Debug 宽度 D=max(32, floor(T×0.30))，但不得超过 T−62，Agent 区域 L=T−D。仅在 T≥B 时执行这些分配。
3. 已打开预览且 L≥104 时并排，Agent 宽度=max(62, ceil(L/2))，预览占余宽；L<104 时使用覆盖预览。无预览时 L 全部给 Agent。
4. W<B 或正文不足 10 行时显示扩大窗口提示，不压缩为零尺寸，不临时关闭 Debug，不 Detach；保留最后有效 ConPTY 尺寸和面板状态。覆盖预览/编辑器可小于其理想 40 列内容宽度，按实际宽度滚动/折行。

下表假定窗口高 30 行、侧栏请求展开、预览已打开，宽度均含边框；属于可直接断言的布局示例：

| 窗口宽度 | Float/Tabs | Split |
| --- | --- | --- |
| 200 列 | Files 28 / Agent 86 / Preview 86 | Files 28 / Agent 62 / Preview 59 / Debug 51 |
| 160 列 | Files 28 / Agent 66 / Preview 66 | Files 28 / Agent 区域 93（预览覆盖）/ Debug 39 |
| 120 列 | Files 28 / Agent 区域 92（预览覆盖） | Files 26 / Agent 区域 62（预览覆盖）/ Debug 32 |
| 80 列 | Files 自动隐藏 / Agent 区域 80（预览覆盖） | 扩大窗口提示，保留会话与最后有效尺寸 |

拖动露出 Agent 时仍沿用当前覆盖布局尺寸，不切成另一套落点坐标。并排/覆盖切换的临界宽度、正文高度，以及手动隐藏、未打开预览的组合均应有测试，不能只验证上表示例。

### 4.2 焦点和快捷键

现有 `App.focus: usize` 表示终端会话索引，不能继续同时代表树、预览和终端焦点。引入最小的 UI 焦点枚举：Terminal / FileTree / Preview；终端会话索引独立保存。

| 操作 | 默认输入 |
| --- | --- |
| 展开/收起整个侧栏 | `Ctrl+G B`，或边缘 Files 按钮 |
| 聚焦文件树 | `Ctrl+G f`（小写），或点击树区域；隐藏时请求展开，空间仍不足则提示并保留原焦点 |
| 移动树选择 | 树内 ↑/↓、Home/End、PgUp/PgDn、滚轮 |
| 展开/折叠目录 | 单击目录行，或树内 →/←、Enter |
| 文件树快速定位 | 树内 `/` 打开名称输入；Enter 确认，Esc 取消 |
| 文件操作菜单 | 树或预览内 F2；↑/↓ 选择、Enter 执行、Esc 关闭 |
| 开启/关闭文件类型图标 | 文件树 F2 菜单；本前端内保留选择，默认开启 |
| 折叠全部目录 | 文件树标题按钮，或树的 F2 菜单 |
| 打开文件预览 | 文件行单击松开更新内容且焦点留在树；树内 Enter 打开并聚焦预览 |
| 插入选中文件路径 | `Ctrl+G I` |
| 聚焦/恢复已有预览 | `Ctrl+G O`，或点击预览区域 |
| Markdown 预览/源码切换 | 预览内 M，或面板按钮 |
| 查找预览文本 | 预览内 `/`；Enter 确认，N 下一处、Shift+N 上一处 |
| 复制预览文本 | 预览内 Ctrl+C 复制选区；无选区时提示使用“复制内容”菜单项 |
| 复制内容/源码、复制绝对/相对路径、在资源管理器中定位 | 对应面板的 F2 菜单；预览菜单另有“在文件树中定位” |
| 关闭预览 | 预览内 Esc，或面板关闭按钮 |
| 回到 Agent | `Ctrl+G A`；树内 Esc 回到 Agent |
| 刷新文件树与当前预览 | 树或预览内 F5 |
| 显示/隐藏隐藏项 | 树内 `.` |
| 显示/隐藏被忽略项 | 树内 I，状态栏标明当前模式 |
| 系统默认应用打开文件 | 预览内 O，或面板按钮 |

原有强制停止快捷键调整为 `Ctrl+G Shift+F`，避免与小写 f 聚焦树冲突；工作区关闭确认框内 F 的语义不变。

上述普通按键仅在对应面板聚焦时由 DevTabs 消费，Agent 中的 M、O、I、`.`、方向键、Tab 和 Esc 保持原生输入。管理前缀保持现有语义；菜单/关闭确认/选择模式存在时，优先处理其事件，不启动文件拖动。

快速定位或预览查找输入打开后，普通字符（包括 M、O、I、N、`.`、`/`）以及粘贴只编辑查询，不触发面板命令或进入终端。Esc 先取消当前查询输入/关闭菜单，其次清除预览文本选区与查找标记，最后才执行面板原有的返回/关闭操作。查询中的 Enter 只确认查询，不能同时预览文件或发给 Agent。

鼠标事件只由一个区域处理：全局确认与拖动捕获 → 面板控件 → 树/预览 → 未被消费的终端事件。窗口/终端焦点事件只在实际焦点进入或离开终端时转发，不能因点击树而继续给 Agent 发送文本。

焦点变化遵循以下规则，后台读取完成不自行改变焦点：

| 场景 | 结果 |
| --- | --- |
| 文件行单击 | 更新预览，焦点留在树；即使预览是覆盖模式也不抢焦点 |
| 树内 Enter | 打开并聚焦预览；快速定位输入中的 Enter 仍仅确认查询 |
| 再次打开同一文件 | 沿用文件版本、模式及阅读位置；按单击/Enter 规则处理焦点，不重新读取未变化文件 |
| 关闭预览 | 返回打开预览时记录的来源面板；来源不可见则回到可见 Agent，否则使用可见终端 |
| resize/手动操作使树隐藏 | 树焦点回到可见 Agent；被预览覆盖时改到预览，不能继续把键盘送给隐藏树 |
| 覆盖预览关闭或被移开 | 预览焦点转到可见 Agent；拖动取消时按既有规则恢复 |
| 全部正文不可用 | 暂存当前焦点，只消费管理、取消及 resize 等允许操作，不向不可见终端发普通输入；尺寸恢复后恢复仍有效的暂存焦点 |

树自动恢复显示时不抢回焦点；仍可见的面板在并排/覆盖切换后保持焦点。扩大窗口提示结束是上一行规则的显式例外。来源面板只记录最小的返回目标，不建立无界焦点历史。

### 4.3 视觉层次与操作反馈

以下状态互相独立，不能只使用同一种整行高亮：

| 状态 | 表达 |
| --- | --- |
| 当前 UI 焦点 | 当前面板边框及标题标记；切换焦点不改变树选择或预览文件 |
| 文件树选中项 | 行背景/反显加选择符，树失焦后仍可识别 |
| 正在预览的文件 | 行末轻量预览标记；目录导航选中其他节点时仍保留 |
| 加载/错误/截断/过期 | 简短状态文字与符号，不仅改变颜色 |

默认使用用户已配置的 Nerd Font 文件类型图标，具体渲染与覆盖规则见第 4.4 节。长文件名按终端显示宽度截断，尽量保留扩展名，不能切开双宽字符。当前项路径在状态区显示，窄窗口可省略显示但必须保留完整路径复制入口。

底部状态区按当前焦点显示少量相关操作；完整操作放在一个 F2 菜单，不堆叠多层菜单，也不要求首版实现右键菜单。正常、低色彩及反显环境均能用文字、边框、符号区分关键状态。

状态反馈复用既有底部区域，不新增影响终端尺寸的提示行。成功反馈约 3 秒后恢复帮助文字；失败保留原因至后续操作/主动关闭。提示不抢焦点、不覆盖确认提示、不因消失而重新绘制原生输入内容。拖动取消显示“已取消，未发送路径”。

操作状态不得超出可观察事实：仅进入本地队列时显示“正在发送路径”；输入链路确认接受后可显示“已发送路径，未发送 Enter”，不能据此宣称已识别 Agent 内部输入框。失败区分目标不接受输入、队列满、连接断开及送达未知；送达未知显示“请检查 Agent，勿重复插入”，不显示成功或自动重试。

### 4.4 文件类型图标与字体渲染

用户默认使用图标字体，因此第一阶段默认开启 Nerd Font 图标。`devicons` 负责按文件名/扩展名返回图标字符与建议颜色，Ratatui 将它作为文字绘制，Windows Terminal 使用用户当前配置的字体提供字形。库不包含或安装字体，DevTabs 不加载字体文件、不自动更改终端字体，也不为文件图标引入 SVG/图片渲染或终端图像协议。

树行在层级缩进后统一排列为“展开箭头槽位 → 类型图标槽位 → 文件名 → 状态标记”。目录开合由独立箭头表达，不能仅依靠两个难以区分的文件夹字形；预览、链接、未保存及错误等状态不复用语言图标来表达。

| 节点 | 图标规则 |
| --- | --- |
| 普通代码/文本文件 | 按扩展名匹配，如 Rust、Python、TypeScript、Markdown、JSON、TOML |
| 特定名称文件 | 优先按完整文件名匹配，如 Cargo.toml、Dockerfile、.gitignore，再回退扩展名 |
| 目录 | 使用统一文件夹图标，可通过少量覆盖统一项目视觉；目录类型根据已读取元数据判定 |
| 未识别文件 | 通用文件图标，文件名仍正常显示，不因缺少映射而隐藏节点 |
| 链接入口 | 保留入口文件类型图标及独立链接标记，不递归解析目录链接来选择图标 |

默认映射优先复用库，应用只集中维护少量必要的自定义覆盖，例如统一目录图标、替换个别语言图标、指定项目专属文件图标。匹配顺序为：先依据节点元数据区分目录/文件，再对该类型使用自定义精确名称、库精确名称、自定义扩展名、库扩展名、通用图标；目录不按扩展名匹配。不维护整套重复图标表，不在首版增加图标包插件或配置编辑器。

默认只对图标着色，文件名沿用正常主题文本色；选中行的对比度优先，深色使用库的建议颜色，浅色使用统一蓝色图标以保持对比度；类型仍由字形区分。颜色不是类型/状态的唯一依据，关闭图标也不能丢失目录、链接和错误信息。

图标在目录读取/节点构建时解析并缓存，绘制和鼠标命中仅使用缓存；若库 API 会检查文件类型或调用文件系统，必须放到现有后台工作队列，不能在每帧调用。切换主题仅更新相关样式，不重新扫描目录。

按终端单元格宽度分配图标槽位并留出间隔，目录箭头、图标、文件名和状态的坐标供绘制与点击/拖放共用。真实 WT 下验证 Nerd Font 字形宽度、中文文件名、水平空间不足和选中态，不能把一个 Unicode 字符直接假定为一个显示单元格。切换图标显示后重新计算布局/命中并取消进行中的拖动，保留节点身份、选择和预览。

首版不自动探测已安装字体或字形缺失；私用区字符显示方框时，用户可在树 F2 菜单手动关闭图标，回退到普通字符表示目录/文件/链接。该开关属于前端临时状态，默认开启，不为此新增持久化配置文件。关闭图标后的导航、预览、路径操作和拖放功能一致。

## 5. 文件树模型与加载

### 5.1 节点和身份

树根固定为 `WorkspaceInfo.project`，不跟随 Agent 当前工作目录变化。真实节点保存 PathBuf、文件类型和加载状态；稳定标识使用保留原始拼写的绝对 PathBuf 及根到节点的路径链，不能用可变化的行号或列表索引作为身份。当前前端只有一个项目根，不额外维护相对路径身份副本。

Windows 大小写无关键只用于比较，原始路径保留用于显示、读取和输入。长路径显示遵循第 4.3 节，不能截断真正发送给 Agent 的路径。

目录排在文件前，同组按名称排序。首屏仅读取根目录直属项，展开目录才读取其直属项；折叠只隐藏子项，不启动全项目递归扫描。刷新保留仍存在的展开路径、选择和滚动；原选择已删除时回到最近存在的父节点。

`tui-tree-widget` 对没有 children 的节点视为叶子。尚未加载的目录需要提供加载占位子项以保留展开能力；占位项标识与真实路径分开，不可预览、拖动或插入。空目录、读取失败分别显示明确状态，不把权限错误伪装为空目录。

### 5.2 隐藏项、忽略规则和链接

隐藏项显示与忽略项显示是两个独立开关。默认显示普通点文件，例如 `.env`、`.gitignore`；默认隐藏 `.git` 元数据目录，并使用 ignore 的既有规则过滤被忽略内容。Windows hidden 属性按隐藏开关处理。允许显式显示忽略项，避免“消失的文件”无法找到。

使用 ignore 已有遍历/匹配能力保留父子目录与否定规则语义；不要只匹配当前目录的一份 .gitignore。全局规则以及非 Git 目录的处理要在测试中明确，刷新 .gitignore 时同步更新相关匹配结果。

符号链接和 Windows junction 显示链接标记，首版不在树内递归展开链接目录，以避免循环和跨根扫描。可预览指向普通文件的链接；拖放时传递用户选中的链接入口绝对路径，不强行改成目标路径。

### 5.3 异步读取和有界缓存

文件读取、高亮和树刷新在前端工作线程进行，不占用宿主全局状态锁。使用前端已有生命周期内的小型有界工作队列，最多 2 个工作线程，不为每次点击或每个目录创建线程。

请求携带工作区、路径和递增代号；快速点击 A、B 后，A 的迟到结果不能覆盖 B。目录折叠、工作区退出、视图分离后，过期结果丢弃。正在进行的底层文件读取不必强制中断，但不能无限排队，也不能在退出时无限等待网络路径。

树缓存只保存已加载目录，默认最多 10,000 个真实节点；达到上限明确显示“缓存已满，目录尚未完整加载”，不能静默假装目录完整。先逐出未展开、未选中且非当前预览路径祖先的目录缓存；仍无空间时暂停加载，允许关闭分支并通过 F2 的“释放折叠目录缓存”释放空间，再手动继续。单纯收起目录不承诺立即释放缓存；刷新也不能绕过上限。

单个目录同样按需分批枚举，每批最多检查 500 个原始目录项（包括被过滤项），或后台累计处理约 20 ms 后让出工作队列，以先达到者为准；单次底层 I/O 可能更慢，不据此阻塞 UI 或宣称硬实时。未到目录末尾时显示独立“加载更多”操作行；用户 Enter/点击后继续，不能因绘制或滚动无限自动枚举。匹配过滤后本批无可见项也保留继续入口，不把它当成空目录。

首版只保证已加载项内目录优先及名称排序，不保证未枚举项的全局顺序；界面标明“已加载 N 项，目录未完整加载”。新批次合并后可重新排序，依靠稳定路径身份保持选择/滚动锚点及拖动目标，不能按旧行号插入错误文件。只有确实枚举至末尾，才移除继续入口并声明加载完整。

每个正在枚举的目录最多保留一个游标；同时最多 8 个游标，且游标状态纳入缓存预算。折叠目录、刷新、过滤规则改变、目录变更通知、切换项目或退出时关闭相应游标并使旧批次失效。重新展开若游标已释放，应开始新一代枚举，用现有节点作旧视图并按路径去重；枚举完成后移除未再发现的节点。释放旧缓存和节点计数必须正确，不能在迭代期间无限累积旧代。

进行中的批次可自然返回，但取消后不再自动请求下一批。权限错误与目录变化显示错误/待重读状态；“加载更多”、缓存满及错误占位均不是文件，不能预览、拖动或插入路径。快速定位仍只搜索当前已加载节点，不触发后续枚举。

### 5.4 快速定位、收起与文件操作

快速定位只搜索内存中已加载的真实节点（包括折叠目录下仍在缓存中的节点），按文件名做不区分大小写的字面子串匹配，不增加模糊搜索或全项目索引依赖。搜索栏持续标明“已加载节点”，不能把零结果解释为项目里不存在文件。查询限制 256 个字符，结果引用原节点，不复制文件内容；匹配不触发目录遍历或磁盘读取。

查询期间 ↑/↓ 浏览匹配项并临时展开必要祖先，Enter 确认选中并将该行滚动到可见处，不自动预览。Esc 取消并恢复查询前仍有效的选择、展开和滚动；确定无结果时提示“已加载节点无匹配，未搜索未展开目录”。占位节点不参与匹配，查询不改变隐藏/忽略开关。

“折叠全部”收起根下面的目录，根自身保持展开，当前选择移到最近仍可见的祖先；预览文件独立保留，不因树选择变化而关闭。单目录折叠、过滤或刷新使选中节点不可见时也遵循该规则。树操作始终针对当前可见的选中节点，不能画面上高亮父目录却继续把隐藏子文件作为插入/复制目标；目录本身仍不支持插入 Agent。

“在文件树中定位”以当前预览文件为目标，展开侧栏及必要祖先、滚动到该节点并聚焦树。只读取目标路径沿途目录，不递归扫描；若过滤阻挡则说明原因并让用户显式调整开关，不能静默改变过滤规则。文件删除时定位到最近存在的父目录并提示。临时窄窗口无法显示树时提示扩大窗口，不能把焦点放入不可见区域。

文件操作菜单始终标明目标：树以选中节点为目标，预览以正在预览的文件为目标，二者不能混用。复制绝对路径保持完整入口路径；复制相对路径以项目根为基准。剪贴板里的路径不添加引号、尾随空格或换行，这与 Agent 插入格式不同。根目录的相对路径为 `.`；有效链接入口仍按项目内入口计算。

复用现有剪贴板能力，失败明确反馈。“在资源管理器中定位”选择该文件；目录可打开自身，目标已删除时说明原因并允许打开最近存在的父目录。系统打开/定位使用独立路径参数或平台 API，不把路径拼接成 shell 命令；中文、空格、`&`、`$` 等字符不能被当作命令解析。不为这些操作新增后台服务。

## 6. 只读预览和 Markdown

### 6.1 文件读取

预览标题包含文件名、完整绝对路径、显示模式和截断/错误状态。按需读取并缓存当前文件，首版只保留一个预览，不提前读取整个项目。

默认读取上限 1 MiB、显示上限 10,000 行；单行展示最多 16,384 个字符，并提示截断。限制须在构建所有高亮文本前生效，不能先读完整大文件再裁剪。渲染结果设置独立缓存预算，防止大量样式 Span 使内存远超原文字节数。

支持 UTF-8/UTF-8 BOM，以及有 BOM 的 UTF-16 LE/BE。截断不能破坏 UTF-8 字符或 UTF-16 单元。其他编码先显示“无法按受支持编码预览”，提供系统应用打开入口；不静默替换乱码。编码判断先于通用二进制检测，避免将 UTF-16 的 NUL 字节误认为二进制。

二进制、图片、PDF、Office 和不可读文件显示文件类型/大小与外部打开操作，不强行当作文本。文件为空、已删除、被占用或无权限分别提示。目录点击只展开，不作为文件读取。

普通代码默认显示行号，保留缩进，支持纵横滚动。未知语言、解析失败回退普通文本；高亮失败不导致整个 App 退出。不通过运行 `cat`、`bat` 或 PowerShell 命令生成预览。

### 6.2 Markdown 模式

`.md`、`.markdown` 默认用 `tui-markdown` 阅读模式，M 切到高亮源码；两个模式分别保留滚动位置。侧栏关闭与视图切换不重新读取未变化的文件。预览区域宽度改变时更新折行和表格宽度，颜色主题/源文件版本改变时使渲染缓存失效。

| 内容 | 阅读模式 |
| --- | --- |
| 标题 | 加粗、颜色和留白区分，终端字号不变 |
| 粗体、斜体、行内代码 | 文字样式，受终端/字体能力限制 |
| 列表、引用、任务列表 | 缩进、符号、文本标记 |
| 围栏代码块 | 按语言高亮，未知语言显示普通代码 |
| GFM 表格 | Unicode 边框，中文宽度计算，按实际预览内宽折行 |
| 链接 | 显示名称和 URL；首版不自己建立链接点击命中表 |
| 图片 | 说明文字和资源路径，不读取或绘制图片资源 |
| Mermaid | 保留代码内容，不绘制图形 |
| 数学公式 | 保留公式及分隔符，不做 LaTeX 排版 |
| HTML | 显示原始文字，不解释 CSS/脚本 |

“外部打开”将原文件交给 Windows 系统默认应用，不保证该应用是 Markdown 渲染器，也不假设浏览器能渲染原始 .md。首版不生成临时网页、不启动本地 HTTP 服务；用户可用自己已安装的 Markdown 查看器阅读复杂内容。

预览读取出的控制字符应作为可见文字或占位显示，不执行源文件里的 ANSI/OSC 控制序列。Markdown 及代码预览均经过结构化文本渲染，不把文件原始字节直接写入外层终端。

### 6.3 查找与复制

预览查找针对当前模式已加载的文本：源码/代码模式搜索解码后的内容，Markdown 阅读模式搜索渲染后的可见文字。使用字面子串匹配，默认不区分大小写，不增加正则表达式界面；查询最多 256 个字符。显示匹配序号/总数，N/Shift+N 循环跳转并使匹配可见；无匹配有明确提示，不能只改变颜色。

查找和命中高亮不包含行号、面板边框及状态栏。当前模式若被截断，说明“仅搜索已加载内容”。切换模式、resize 或自动刷新后，按新文本重新计算命中位置，保留查询；不使用旧坐标高亮其他文字。查找计算遵守现有有界任务与缓存预算，不阻塞终端输入。

预览内鼠标拖选只产生预览文本选区，不进入文件到 Agent 的拖放状态。Ctrl+C 复制选区，不发送到终端；不选中文字时不隐式复制整份文件，而提示菜单里的“复制内容”。菜单另提供键盘可用的整段内容复制入口，不依赖鼠标选择才能复制。

代码/源码复制排除行号、样式和 UI 边框，保留已加载文本的缩进与换行。Markdown 阅读模式“复制内容”复制当前渲染文本，包括列表符号和实际渲染出的表格字符，去掉样式、UI 边框及搜索/选区装饰；“复制源码”明确复制解码后的 Markdown 源文。鼠标选区按当前模式文字复制，不假装映射回源码。所有复制均以已加载、已安全处理的内容为界，截断时提示，不额外读取完整大文件。

文本选择/查找命中以文本位置保存，绘制和鼠标命中共同换算终端单元格坐标，覆盖中文、组合字符、Tab、水平滚动及 Markdown 折行。resize 只重算布局，文件版本变化时清除旧选区以免复制错误内容。剪贴板失败保留选区并提示，不影响 Agent 输入和连接。

### 6.4 自动更新与阅读位置

自动刷新不把阅读位置跳回顶部。保留当前模式的首个可见逻辑行及水平偏移，按新内容尽量恢复；文件缩短时限制到有效范围，不要求首版实现全文差异计算或语义锚点。Markdown 宽度重排时尽量保留原有文本块位置，阅读/源码模式的滚动状态分别管理。

已有内容刷新时保留旧画面和“正在更新”标记，读取成功后再替换。权限错误、临时占用或原子替换保存期间读取失败时保留上次成功内容，标明“内容可能已过期”及原因，提供 F5 重试。确认删除时标记“文件已删除，显示上次内容”，不能把缓存内容误报为当前文件；该状态禁用路径插入，允许复制旧内容并明确其来源。

首次读取失败没有旧内容时，显示错误与可用重试/外部打开操作。加载中、真正空目录、过滤后无可见项、空文件、无权限、已删除分别使用不同文字；错误占位不参与预览/拖放。刷新恢复成功后清除过期/错误标记，不抢焦点，也不打断正在编辑的查找输入。

## 7. 从文件树拖入 Agent

### 7.1 手势状态

使用一个状态枚举表达 Idle、Pressed(file, origin)、Dragging(file)，而不是互相矛盾的多个布尔值。

| 事件 | 行为 |
| --- | --- |
| 文件行左键按下 | 记录实际节点路径和按下位置，选中该行，暂不打开预览 |
| 保持按下并移动至少 2 个终端单元格 | 进入 Dragging，临时显示可用 Agent 落点；状态栏显示待插入文件 |
| 同一行松开且未进入拖动 | 打开该文件预览 |
| Dragging 时在 Agent 内容区松开 | 插入一次路径，结束拖动，聚焦 Agent |
| 在其他区域松开、Esc、窗口失焦或 resize | 取消拖动，恢复原预览和焦点，不插入 |
| 拖动中文件已消失、会话断开或失去输入权 | 给出错误，不自动重连重放 |

落点只包含当前工作区 Session 0 的实际 Agent 内容矩形，不包含边框、预览、Debug、底部按钮和其他会话。树发起拖动后的全部 Down/Drag/Up 由 DevTabs 消费，不能把释放事件或拖动轨迹转发给 Agent。Agent 内自行发起的拖选仍沿用原有鼠标协议。

拖动期间用边框与文字突出唯一 Agent 落点，状态栏显示文件名；指针位于有效内容区时显示“松开插入路径”，位于 Debug、边框、预览等区域时显示“此处不可插入”。目标连接/租约不可用时立即取消可投递标记，不以颜色作为唯一提示，也不画覆盖原生输入框的浮动文件卡片。

输入设备没有上报 Up 时，不以超时当作成功放下；下一次失焦/Esc/新按下可取消残留手势。Shift 被 WT 用于宿主文本选择时，以实际收到的事件为准，提供键盘“插入路径”作为等价入口。

### 7.2 路径文本和会话输入

将节点入口构造为绝对本地路径，保留正常盘符/UNC 表示和原文件名，避免无必要地把 `\\?\` 内部路径暴露给用户。不根据终端当前目录改成相对路径，不解析为另一个工作区路径。

默认插入格式为双引号包围的绝对路径加一个空格，例如：

```text
"D:\100_Projects\项目 A\设计说明.md"
```

引号用于将空格路径表达为一个引用；这只是输入文本，不是通用 shell 转义。不开文件上传、不读取内容发送给 Agent、不自动补 @、不清空已有提示词、不发送 Enter/Ctrl+C，也不使用托管命令 Run 接口。

插入位置遵循 Agent 自身当前输入光标，保留光标两侧已有文字及原生选择替换规则。DevTabs 不先发送 Home/End/方向键移动光标，不主动重置原生选区。成功投递后聚焦 Agent，不额外调整原生光标；拖放与键盘入口遵循相同规则。

通过 `Client` 的现有输入通道发给 Agent 会话，使用该会话当时的 bracketed paste 模式编码，一次放下构造一个有界 Input 消息。不能拆成多个逐字发送来绕过队列，不经过系统剪贴板。队列满或 IPC 失败保留可重试提示；送达结果不明时禁止自动重试，避免重复输入。

键盘“插入路径”与拖放进入同一个函数。发出请求时检查工作区和会话标识、会话仍附着且 shell 存活、目标确实是运行中的配置 Agent；Agent=Shell、托管 Agent 已退出和调试窗口不接受该动作。不要为了投递路径主动抢占另一前端的输入租约。

这些检查只能排除明确无效状态，不能证明 Agent 正处于提示词编辑页。菜单和模型任务运行时也可能仍标记 Running；不能从输出画面或 CPU 猜测可编辑状态。必须实测支持版本的原生 Codex/Claude：若其当前页面不将粘贴解释为提示词，保持原生行为并记录限制，不能宣称“任意页面都能写入输入框”。

本轮核心验收是用户在原生 Agent 提示词编辑状态下主动放下文件后，路径在当前光标处出现一次、两侧已有文字保留、无需自动提交；有原生选区时单独验证其原生替换行为。若其中一个受支持 Agent 的此交互无法成立，必须解决或明确收窄支持范围后更新规格，不能仅凭 shell 收到字节就认定通过。

## 8. 自动刷新与状态归属

### 8.1 文件监听

只为打开侧栏/预览的工作区前端建立 watcher；共享 Debug 和无界面的宿主不监听整个磁盘。复用一个 watcher，监听根及已加载目录，按需增减，优先使用非递归监听，避免把 node_modules 等隐藏大目录全部纳入。

200 ms 合并同一批文件事件；回调只投递“目录/预览需要刷新”，不直接修改 UI 状态、读取文件或重绘。待处理路径去重并有界；溢出或 notify 提示丢失事件时，安排已加载范围重扫。文件替换保存、重命名、删除、根目录消失都需要处理。

监听失败时显示“自动刷新不可用，F5 刷新”，继续允许使用文件树。收起树且无预览后释放 watcher；再次打开重读可见目录，不能沿用已经过期的缓存假装实时。

### 8.2 最小状态归属

树展开、选择、滚动、快速定位、预览内容/选区/查找、操作菜单、短时反馈、UI 焦点、拖动、缓存与工作线程都归主前端。宿主继续只拥有进程、ConPTY、历史和输入租约，不给协议增加“打开文件”“拖动文件”等与宿主无关的消息。

同一前端收起/展开保留状态；项目切换、前端退出时取消拖动和丢弃过期工作。首版不持久化逐目录展开状态或预览内容，不为此新增数据库/配置文件。侧栏默认值与读取上限先集中定义为常量，避免同时引入大量不可验证的配置选项。

## 13. 第二阶段：单文件源码编辑

### 13.1 目标与范围

在第一阶段功能及回归验收完成后，允许用户显式编辑当前文件并可靠保存。文件树、路径操作、Agent 拖放和默认只读预览继续沿用第一阶段的行为；复用原预览区域，不增加第二个编辑窗口或多标签文档系统。

本阶段的基本事实是：编辑缓冲区可能包含磁盘上尚不存在的用户修改，磁盘内容也可能被 Agent 或外部编辑器同时修改。因此交付重点是内容完整性、未保存状态和冲突处理，不能把文本输入框加保存按钮当作编辑功能已经成立。

| 能力 | 第二阶段行为 |
| --- | --- |
| 显式编辑 | 点击文件仍只读；预览内 E、编辑按钮或 F2 菜单进入源码编辑 |
| 文本操作 | 光标移动、选择、输入、删除、复制/剪切/粘贴、撤销/重做、查找、缩进、行号和语法高亮 |
| 中文输入 | 使用终端实际提交的 Unicode 输入和粘贴，不另建 IME；真实 WT 验证输入法提交与候选操作 |
| Markdown | 阅读模式进入编辑时切到源码；可从菜单预览当前缓冲区，返回编辑不丢失未保存内容 |
| 保存 | Ctrl+S 显式保存原文件；不开自动保存，不顺带格式化或规范化文件 |
| 未保存处理 | 切换到其他文件、关闭文档、切换项目或正常退出前选择保存、放弃或取消 |
| 外部变化 | 无本地修改时可刷新；存在本地修改时提示冲突，不静默覆盖或丢弃缓冲区 |
| 保存失败 | 保留完整缓冲区与未保存标记，说明原因并允许重试 |

不包含 LSP、代码补全、格式化、语义重构、富文本 Markdown 编辑、自动合并、多文件批量修改、崩溃后草稿恢复及文件创建。正常退出需要保护未保存内容；进程被强制终止或机器断电时，未保存缓冲区不承诺恢复，不把它描述为已经落盘。

第二阶段首批编辑对象限本地磁盘上的普通、可写、完整读取的受支持文本文件。二进制、未知编码、截断预览、超出编辑预算、UNC/网络文件，以及符号链接、junction 路径或多硬链接文件继续只读，并给出原因及外部打开入口。先验证普通文件保存语义，不为覆盖这些边界引入复杂文件系统抽象。

### 13.2 界面、快捷键与焦点

文档标题明确显示“只读 / 编辑”、文件名和未保存标记 `*`；冲突、保存中、保存失败另用文字表达。退出编辑回到只读视图不能悄悄放弃修改；Markdown 的只读投影仍可显示未保存缓冲区，标题必须标明“未保存内容”。

| 操作 | 第二阶段输入规则 |
| --- | --- |
| 进入/返回源码编辑 | 只读文档视图内 E，或按钮/F2 菜单；不影响原生 Agent 的 E |
| 保存 | 编辑器聚焦时 Ctrl+S；处于未保存内容投影时可从菜单保存 |
| 撤销/重做 | 编辑器内 Ctrl+Z / Ctrl+Y；菜单提供可发现入口 |
| 复制/剪切/粘贴 | 编辑器内 Ctrl+C / Ctrl+X / Ctrl+V；只作用于编辑缓冲区，剪贴板失败不能先删除选中文字 |
| 查找 | 编辑器内 Ctrl+F 打开查询；输入期间按查询规则消费事件 |
| 缩进/反缩进 | 编辑器内 Tab / Shift+Tab；不发送至终端，不改变非选中行 |
| Markdown 阅读投影 | F2 菜单“预览当前内容”；投影沿用只读视图的 M、查找和复制操作，E 返回编辑 |
| 外部打开 | F2 菜单“打开磁盘版本”；存在本地修改时明确选择保存后打开、打开磁盘版本或取消 |
| 离开文档 | 面板关闭、切换文件或显式“结束编辑”走未保存判断；Esc 先退出查询/菜单/选区，不直接放弃内容 |

编辑器聚焦时 M、O、I、N、E、`.`、`/` 等普通字符都用于输入，不再触发预览/树快捷操作。管理前缀沿用既有规则；保存确认优先于任何后台结果，取消后不执行原本等待中的切换/关闭动作。

快捷键是否到达应用取决于 Windows Terminal 配置，不能假定 Ctrl+V、Ctrl+C 等一定产生 Key 事件。编辑器统一处理终端发来的粘贴事件、bracketed paste，以及实际到达的粘贴按键；每个事件只交给一个消费分支。WT 已经处理 Ctrl+V 并生成 Paste 时仅使用该内容；只有应用实际收到 Ctrl+V Key 时才从剪贴板读取，不同时再调用第二条粘贴路线。不按内容或时间盲目去重，以免吞掉用户连续两次相同粘贴。

右键由 WT 截获并粘贴时遵循相同 Paste 路径。输入法提交的文字只插入一次，候选确认与 Esc 按真实终端上报处理，不能把已被 IME 消费的按键另行模拟为编辑命令。复制、剪切、粘贴、保存、撤销、重做和查找均有按钮/F2 菜单替代入口；测试记录 WT 版本和相关按键绑定，不自动修改用户终端配置来掩盖不可达快捷键。

外部默认应用始终读取磁盘版本，不能直接看到未保存缓冲区；菜单和提示必须明确这一点。“打开磁盘版本”保留本地修改及未保存标记，不自动保存/放弃；“保存后打开”走完整保存与冲突判断，只有保存成功且当前缓冲区已与磁盘同步后才打开，若保存期间又有修改则重新提示。保存失败/冲突/取消不启动外部应用。树菜单若目标正是当前脏文档，也必须走相同规则，不能绕过确认。不生成临时副本冒充原文件。

前端新增 Editor 焦点分支即可，不建立第二套输入事件循环。编辑器内鼠标拖动用于文字选择；树发起拖动仍只向 Agent 内容区插入路径，不自动改为插入编辑器。切换焦点到 Agent、展开目录、收起侧栏和调整布局都不应触发保存确认，也不能丢弃缓冲区。编辑面板临时被覆盖或隐藏时保留状态，恢复后回到原位置。

### 13.3 内容模型与组件选择

一个活动文档只有一份可编辑文本来源：编辑缓冲区。源码高亮、查找及 Markdown 阅读投影从该缓冲区派生；磁盘快照用于外部变化判断，不作为另一份独立可修改内容。按文档修订号丢弃过期高亮/渲染结果，不能在用户继续输入后用旧预览覆盖当前文字。

在受支持编码下完整读取后才允许编辑。最终编辑预算为 **512 KiB（编码后包含 BOM）**、10,000 行、单行 16,384 字符；只读读取继续允许 1 MiB。最初 1 MiB 编辑在六进程保存基准中峰值约 107 MiB 超标，因此按第 13.6 节收缩编辑预算；任一限制导致截断时只能预览，绝不能把截断内容作为完整文件保存。编辑后也执行同等内容预算和独立有界撤销历史预算，超限操作应整体拒绝并说明原因，不能只接受部分粘贴或静默丢字。

保留原 UTF-8/UTF-8 BOM/UTF-16 LE BOM/UTF-16 BE BOM、LF/CRLF 风格及文件末尾换行状态；不因一次无修改保存就改变字节。混合换行或孤立 CR 的文件在本阶段保持只读，避免无法保证原样写回。新增换行遵循该文件风格，空文件默认 UTF-8 无 BOM、LF。对于可视化过的控制字符，不把占位符写回原文件；无法无损编辑的内容保持只读。

未保存状态应反映当前内容是否等同于最后成功保存的内容，不能只由“按过键”决定；撤销回已保存内容后清除 `*`，保存后继续保留合理的撤销/重做历史。代码高亮失败仍可编辑普通文本，不能让着色器拥有唯一内容副本。

实施前调研并选用维护中的 Ratatui 编辑组件，复用光标、选区、编辑和撤销历史；核对当时最新稳定版、Ratatui/Crossterm 类型兼容性、中文单元格映射、Tab、长行、粘贴原子性及内存预算。最终采用维护中的 `ratatui-textarea 0.9.4`（原 tui-textarea 的 Ratatui 0.30 适配分支），复用编辑、选择、查找与撤销历史。事件类型与 Ratatui/Crossterm 兼容。应用仅增加编码、预算、菜单和保存协调，不自行实现文本编辑算法。

按需新增 `src/editor.rs` 负责活动文档和保存协调，复用 files/preview 的读取、编码和高亮逻辑；只有实际出现共享需求时才提取公共函数。不新增文件服务、编辑 IPC、常驻进程或草稿数据库，宿主继续只管理会话。

### 13.4 保存、冲突与文件变化

进入编辑时记录完整磁盘内容快照的指纹及必要文件身份信息。保存前重新核对实际目标，不仅依赖 mtime、长度或 notify 事件；同长度、同时间戳内容变化也必须触发冲突。目标已删除、被替换、变成只读或链接时停止写入，保留缓冲区并说明原因，不悄悄重建文件。

| 状态 | 行为 |
| --- | --- |
| 无本地修改，磁盘更新 | 成功重读后刷新，尽量保留阅读/光标位置，重置不再适用的旧撤销历史 |
| 有本地修改，磁盘更新 | 保留缓冲区及未保存标记，显示冲突；允许取消并继续编辑，或经明确选择放弃本地修改、重载磁盘 |
| 冲突时要求保存 | 拒绝静默覆盖；本阶段不提供一键强制覆盖/自动合并，可复制缓冲区交给外部工具处理 |
| 保存失败 | 原文件与内存修改均应保留，显示实际错误；不得先截断原文件再写入 |
| 保存成功 | 仅将本次实际写入的修订标记为已保存，刷新树/预览；后续输入仍标记未保存 |

保存采用目标同目录临时文件、`sync_all` 与 Windows `ReplaceFileW`。提交时使用系统备份参数捕获实际被替换的文件，再核对其完整内容及文件身份；核对成功删除备份。若外部原子替换恰好发生在最后一次检查后，保留 `.devtabs-<id>.bak` 恢复文件、内存缓冲区并报告交付状态未知，不误报保存成功，也不强制恢复覆盖可能再次变化的磁盘版本。先完成编码、完整写入和必要 flush，再提交替换。只在成功后更新磁盘快照与保存状态；失败清理本次临时资源，不删除用户文件。保持目标文件所需权限和属性，验证 Windows 文件占用、只读及替换行为，不照搬其他系统的 rename 假设。

先用临时夹具验证保存方案，再确定可交付支持边界。以下三项分别记录机制、实测结果及限制，不能互相替代：

| 性质 | 验证目标 |
| --- | --- |
| 替换完整性 | 成功读取的内容是完整旧版或新版，不出现半份写入。实测 ReplaceFileW 可能让新打开者短暂得到 NotFound；DevTabs 后台读取仅对此错误重试最多 4 × 5 ms，之后仍明确失败。不承诺任意外部读者无间断打开或断电持久性 |
| 冲突检测 | 保存前磁盘内容/身份与读取快照不同则拒绝覆盖；mtime、notify 或原子替换本身均不能替代内容核对 |
| 并发写入协调 | 分别测试多个 DevTabs、外部直接写入、外部原子替换，以及检查后提交前的竞争；保存前已检测变化拒绝提交，提交窗口竞争保留系统备份并报错，明确哪些文件共享/锁规则实际生效 |

仅做“比较指纹后 rename”仍可能存在检查到替换之间的竞争，不能描述为已消除。DevTabs 之间的保存需串行化并在锁内重新核对；应用自己的锁不能被视为约束任意外部程序。Windows 文件共享、打开句柄和替换行为须以真实测试验证，不预先承诺通用的条件替换 API 或绝对零竞争。

已验证的默认保存范围为本地普通文件：同一路径的 DevTabs 保存由路径命名互斥锁串行化；要求路径始终可打开的外部并发读者不在已验证范围，因 ReplaceFileW 存在短暂命名窗口；持有 READ | DELETE 共享的只读句柄可排除直接写入者，并允许自身原子替换。未协作的外部原子重命名没有通用 Windows 条件替换保证：该场景不承诺“提交前绝不覆盖”，其防护限定为提交备份核对、保留被替换的版本及明确失败；需要严格零覆盖条件提交的文件应保留只读/复制并交给外部协调。默认只启用上述已验证场景，不能把它称为对所有外部程序都零竞争。已检测冲突、无法建立所需访问约束或目标身份改变时拒绝保存并保留缓冲区；对任意外部程序仍无法保证的竞争窗口，要在方案及验收记录中明确。如果技术验证不能满足本节的防覆盖要求，暂停该场景保存能力、保留编辑/复制/外部处理入口并修订支持范围，不能用警告替代既定保护，也不能因此宣称所有本地文件都无法或都可以安全保存。

保存期间可继续接收输入，保存任务捕获确定的文档身份和修订。一个文档同一时刻最多一个保存任务，重复 Ctrl+S 合并，不并发替换同一文件；若此后还有修改，成功反馈不能清除新修订的 `*`。有待执行的切换/退出时，保存成功后仍有新修改就重新判断，不能直接关闭文档。

notify 只触发核对，不能直接用磁盘内容覆盖脏缓冲区。自身保存产生的通知通过实际内容/身份核对消解，不靠短时间忽略所有事件，避免漏掉紧随其后的 Agent 修改。F5 在存在本地修改时也必须走冲突/放弃确认，不能绕过保护。

### 13.5 第二阶段实施顺序

| 步骤 | 工作和完成条件 |
| --- | --- |
| 0 | 保存已验收第一阶段的源码、锁文件、可执行文件哈希、完整测试及性能结果至 `artifacts/editor-baseline`，作为独立升级前基线 |
| 1 | 调研编辑组件，在真实 WT 验证中文输入/选择、撤销、粘贴/终端快捷键截获、菜单替代操作、缩进和类型兼容；先用临时夹具分别验证无损写回、原子替换、冲突检测和 Windows 并发写入协调，再明确保存支持边界 |
| 2 | 接入单文档缓冲区、Editor 焦点、显式编辑/只读投影、未保存标记、查找及预算，不改变 Agent/Debug 输入 |
| 3 | 接入显式保存、磁盘快照检查、失败保留、未保存离开确认和异步修订处理，通过文件完整性测试 |
| 4 | 接入 notify 冲突处理、Markdown 缓冲区预览、树/预览更新与状态恢复，通过第一阶段全量回归及编辑性能验收 |

第一阶段不提前实现编辑命令、保存协议或通用编辑插件框架。进入第二阶段时允许直接重构预览内容模型和焦点分发，删除被替换的结构，不保留兼容分支；实现、升级前后证据及仍需真实输入法验收的边界记录在 08。

### 13.6 第二阶段升级前后测试与完成标准

开始前在 `artifacts/editor-baseline` 保存第 11.1 节所列质量检查、完整测试及 release 基准的实际输出和退出码，追加第一阶段已形成的侧栏/预览/拖放测试；完成后执行同一组检查，再追加编辑测试。第二阶段不能复用更早的只读预览升级前结果冒充本次基线。

| 范围 | 必测情景及结果 |
| --- | --- |
| 编辑组件集成 | 真实 WT 中文 IME 提交、中文/组合字符/Emoji 选区、Tab、行首尾、跨行删除、长行、剪切粘贴、撤销/重做；不能拆坏字符或误发至 Agent |
| 模式与焦点 | 点击仍只读，E 进入源码；编辑时 M/O/I/E/`.`/`/` 为文本；Ctrl+S/C/X/V/Z/Y 与查询按区域分发；切到 Agent 和布局隐藏不丢修改 |
| 终端输入边界 | WT 截获与实际下发 Ctrl+V 两种情况、右键粘贴、bracketed paste、连续相同粘贴、IME 候选确认/Esc；一次操作仅插入一次，两次操作不得误去重，菜单替代可用，记录终端绑定 |
| 无损保存 | UTF-8 含/不含 BOM、UTF-16 两种 BOM、LF/CRLF、末尾有/无换行、空文件；无修改往返字节完全一致，编辑后只出现预期变化 |
| 只读边界 | 二进制、未知编码、截断/超预算、混合换行、只读文件、链接与多硬链接、网络路径不能误入可保存状态；保留外部打开入口 |
| 未保存确认 | 切文件、结束编辑、关闭面板、切项目及正常退出的保存/放弃/取消均正确；取消不继续原动作，保存失败不能退出 |
| 保存与撤销 | 撤销回已保存内容后清除标记，保存后可撤销；保存中继续输入仍为未保存，重复保存不并发写，迟到结果不作用于另一个文件 |
| 外部冲突 | Agent/编辑器修改、相同长度/时间戳变化、原子替换、删除/权限变化、并发 DevTabs 保存及检查到替换间的竞争；不能静默覆盖本地修改或未核对的磁盘内容 |
| 保存性质 | 原子替换、冲突检测、并发协调分开验证；记录正常读者、外部已有句柄/直接写入/替换及多个 DevTabs 的结果和支持边界，不以“原子保存成功”替代全部验收 |
| 外部打开 | 脏文档的保存后打开/打开磁盘版本/取消正确；失败、冲突及保存期间继续修改不错误启动；树/预览/编辑器入口一致，不把内存内容误报为磁盘内容 |
| 错误恢复 | 夹具模拟磁盘写失败/空间不足、文件占用、替换失败；原文件不截断，缓冲区完整、标记保留、可复制/重试；剪贴板失败不先剪掉文字 |
| Markdown 与监听 | 未保存源码投影来自当前缓冲区；返回编辑位置保留；自身保存通知不清空撤销历史，不漏掉随后外部修改；F5 不覆盖脏内容 |
| 既有回归 | 第 11 节第一阶段全部验收与既有终端/宿主能力继续通过，拖文件仍只向 Agent 插入路径且不发送 Enter |

保存测试只操作临时夹具，不修改用户真实文件、Agent 工作成果或参考工程。故障注入及并发测试验证实际文件字节、缓冲区内容和保存状态，不仅断言内部标志。

沿用第 11.4 节的机器与测量口径，增加编辑模式、接近预算上限文本、连续编辑/撤销、Markdown 未保存投影和保存任务的测量：输入/滚动/查找的可见反馈目标 ≤50 ms，磁盘保存不阻塞终端，全部 DevTabs 工作集合计仍以 ≤100 MiB 为目标，记录新增撤销历史和渲染缓存的开销。达不到时优先缩小有界预算或更换组件，不能通过漏计进程、删除旧回归或隐瞒输入卡顿交付。

第二阶段完成条件：上述范围完整可用，文件无损往返、保存失败保留和冲突处理成立，第一阶段与原有终端功能回归通过；记录实际版本、组件、限制、测试输出及性能。不能仅凭演示文件编辑成功就宣称具备可靠保存能力。
