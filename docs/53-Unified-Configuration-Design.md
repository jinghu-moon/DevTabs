# 设置界面与统一配置设计

日期：2026-11-14。

状态：实施中。阶段及验证证据见 [实施记录](54-Settings-Refactor-Verification.md)。本设计取代此前围绕兼容、旧格式迁移和多层项目配置展开的方案。

## 1. 前提与推导

项目处于开发期，允许重构数据模型、界面、命令和文件结构；**不要求兼容旧格式，不开发迁移器、双读双写、旧版本适配或迁移事务**。升级前后仍须分别测试，证明新设计成立、已有业务能力正常。

区分源码事实、产品要求和设计决策，避免把当前选择写成不可更改的事实。

**源码事实：** 项目已具有不同 Agent、命令和会话组合；会话、任务、布局及检查结果有各自身份和生命周期；便签与书签包含无法从运行状态重建的用户内容；多前端和宿主会同时读写数据。现有入口及证据见 §2。

**产品要求：** 设置表达今后的默认行为，业务操作表达本次动作；同一行为的键盘、鼠标、CLI 和设置页共用求值与校验；保存失败和并发编辑不得静默丢失内容。本轮要求统一偏好入口，语言、主题、通知和快捷键仅提供用户级设置，项目覆盖用于启动、文件侧栏与检查；这是当前需求边界。

**设计决策：** 使用一个生效的偏好文件 config.toml，用户内容独立，UI 记忆独立，任务业务文件由原业务所有者维护。前者服务于手改和集中管理，后几类避免高频自动写入干扰偏好，也允许分别处理内容冲突与业务事务。便签、书签共用一个低频内容存储是本轮取舍，并非所有用户内容天然必须同文件；保留现有容量约束并补合并测试，见 §4.1、§6.3。

统一偏好的代价是取消仓库内自动生效的共享配置：项目复制或克隆到另一台机器后，中央项目覆盖不会自动随仓库到达。当前选择接受这一能力变化，未来确有共享需求再增加显式模板导入，不引入持续覆盖层。页面分类不决定文件数量，实际写入方、生命周期、故障边界才决定存储划分。

### 2.3 留在原位置的内容

设置中心提供持久默认和管理入口；执行操作仍在发生业务的位置完成。

- 新建项目、打开项目、创建任务、启动预设、批量启动、停止/强停、关闭工作区、合并/归档任务继续是业务操作。
- 便签正文、书签和备注由原编辑器/列表管理；设置页可以提供入口，不把正文当设置项。
- 当前搜索词、当前选区、临时筛选、当前图片缩放、当前会话焦点、未保存编辑缓冲不写 config.toml。
- PID、租约、输入所有者、扫描进度、检查结果、Git 状态、Agent 活动来自实际运行，设置页只展示或跳转。
- 超时/内存预算、停止保护、最小窗口尺寸等正确性约束先保留代码常量；没有用户需求就不增加“高级设置”。
- Windows Terminal 字体、窗口透明度、外部输入法/截图热键由其所有者管理，DevTabs 不生成假的设置承诺。

## 3. 设置界面结构

沿用第一份 HTML 的“分类导航＋设置项＋说明＋固定操作区”，第二份 HTML 作为组件视觉参考，不将组件种类当成功能清单。

| 分类 | 内容 | 边界 |
| --- | --- | --- |
| 外观与语言 | 语言、主题、即时预览 | 预览可撤回；现有 terminal 主题不是新增固定深色主题 |
| 总览 | 默认排序/筛选、详情/统计、比例 | 折叠与上次选中是 UI 记忆 |
| 启动与终端 | 默认 Agent、组合、布局、续接、参数、Debug、shell、历史行数、新窗口 | 设置下次默认，不更改已运行 PTY |
| 项目 | 发现目录、手动项目/排除、收藏、项目覆盖、预设、准备与检查 | 编辑具体项目需明确 path；“继承”可操作 |
| 文件与预览 | 树宽度/比例、跟随、紧凑、隐藏/忽略默认、换行/Markdown、图片协议 | 当前文档的临时操作仍就地使用 |
| 快捷键 | 命令、作用域、绑定、首选、冲突、录制/测试 | 直接嵌入统一管理页；没有全局“备用键优先”开关 |
| 通知与集成 | 全局通知/声音/类别、Hooks 和系统通知的诊断/显式操作 | 外部安装是副作用操作，不能假装属于可取消草稿 |
| 配置与数据 | 实际路径、重载、恢复默认、配置导出、用户内容备份、缓存清理、诊断 | 操作与只读信息，无需对应持久字段 |

总览和工作区都能用鼠标进入设置。现有 F4 项目设置改为打开同一设置系统的“项目→当前项目”，避免复制一个编辑器；全局设置通过命令面板和菜单进入，最终快捷键由命令注册表决定。

Tab/Shift+Tab 在导航、内容、底部按钮间移动；区域内按方向键/控件规范处理，文本框优先输入。模态和录制独占输入，关闭后回到原焦点。按钮提示从有效快捷键表生成。

切换分类保留全窗口草稿；保存提交所有配置草稿，放弃撤销草稿和主题预览，恢复本页默认仅更新本页草稿，关闭时明确处理未保存修改。安装 Hooks、发送测试通知、清缓存等立即执行的操作单独标注、确认或报告结果；“放弃修改”不能声称撤销它们。

### 3.1 HTML 参考的使用范围

[设置页面演示](<../refer/DevTabs 设置 · 终端风格演示.html>)用于确定页面结构、设置行、预览和操作区；[基础组件演示](<../refer/DevTabs 设置基础组件 · 终端风格演示.html>)用于确定组件外观与状态表达。二者是视觉参考，不是已经验证的键盘交互实现或功能清单。

正式页面以第一份的纵向设置行作为主体：名称帮助定位，控件表达当前值，下方说明解释后果。第二份的多框网格保留为组件展示思路，不搬进正式设置页；普通设置行不逐项套边框，也不为填满窗口增加卡片或无用控件。

### 3.2 颜色、层级与终端尺寸

基础规则集中定义并复用 [appearance.rs](../src/appearance.rs) 的主题体系。组件只引用语义样式，不各写一份颜色，也不另存一份设置页专用主题配置。

| 基础项 | 参考方式与约束 |
| --- | --- |
| 颜色 | 背景、正文、弱文字、边框、选中底色、强调、成功、警告、错误各有明确职责；先复用已有调色板，确有缺口再补语义颜色 |
| 强调色 | HTML 的橙色强调、青色标签、灰蓝选中底可参考其层级关系；实际颜色随现有主题变化，不固定复制十六进制值 |
| 文字层级 | 页面/分组标题、设置名、当前值、说明与状态分层；说明使用弱文字，错误保留足够对比，不靠字号变化表达全部层级 |
| 分组 | 单线边框与嵌入上边框的标题用于分组、预览及弹层；普通行靠对齐、间距和焦点标记组织 |
| 间距 | 使用终端单元格，组间通常空一行；名称与控件留稳定间隔，同行控件按字符宽度布局，不复制 CSS 像素 padding/line-height |
| 对齐 | 同组控件起点对齐，数值与单位相邻，说明置于控件下方；中文与按键帽使用实际终端显示宽度，不能按字符串长度截断 |
| 窄窗口 | 空间不足时设置名、控件、说明上下排列，导航可切换为紧凑形式；操作区持续可达，焦点项自动滚入可见范围，不照搬 HTML 的像素断点 |
| 留白 | 内容按自然高度排列，允许空白；分类/内容边框不必为填充屏幕延伸到底部，底部操作区与内容留清楚间隔 |

HTML 的字体家族、圆滑过渡、半透明遮罩和窗口不透明度不直接成为 TUI 设置。弹层通过终端可实现的覆盖与背景弱化区分层次；终端字体和窗口透明度仍由宿主管理。

### 3.3 基础组件样式

| 组件 | 可参考样式 | 正式使用规则 |
| --- | --- | --- |
| 分类导航 | 当前分类有底色、左侧指示和文字强调 | 当前分类与键盘焦点分别表示，未保存状态可附符号；不能只用颜色 |
| 设置行 | 名称、控件、说明对齐；当前行有轻量底色或侧标记 | 整行定位与具体控件焦点区分，说明随内容换行；不使用整行高亮掩盖输入框焦点 |
| 按钮 | 主操作实底、次操作弱底、危险操作红色、禁用降低对比 | 危险性在静止时可见；禁用有原因且不可触发；按钮尺寸与间隔统一，快捷键提示查有效绑定 |
| 开关/复选 | `[✓] 开`、`[ ] 关`，复选组有全选/半选标记 | 状态同时有符号和文字；项目覆盖另提供“继承”，不把继承伪装成关闭 |
| 分段选择/单选 | 少量短选项平铺，选定值填色 | 语言、主题、Agent、布局适用；两种控件复用选中/焦点规则，不建立两套视觉体系 |
| 文本输入 | 独立底色、焦点边框、错误边框及下方说明 | 路径、命令、名称复用；格式合法、目录存在、可访问分别表达，不用一个绿色状态冒充全部验证 |
| 数值步进 | 减/加按钮围绕数值与单位 | 边界显示禁用，允许直接输入与校验；单次步长、范围由字段定义 |
| 滑块 | 单元格刻度、已选区与数值并列 | 只用于已有连续参数，提供键盘调整与精确值入口；不因演示中有滑块就增加透明度功能 |
| 下拉选择 | 当前值与展开指示，菜单项有选中/焦点状态 | 长列表或需要说明时使用；展开覆盖内容而不挤动页面，确认/取消后返回原焦点 |
| 可排序列表 | 主内容占剩余宽度，移动/删除操作靠右 | 用于有顺序语义的会话、预设等；首尾移动按钮禁用，长路径截断后可查看/复制全文，不暗示目录顺序有尚未定义的优先级 |
| 按键帽/录制区 | 按键有边界，组合用 `+`，序列用 `→`，别名分隔 | 整个 chord 尽量不拆行；录制状态明确，完成/取消有鼠标入口，文本编辑可达；行为遵循 docs/52 |
| 标签/状态徽标 | 短文字、紧凑底色、必要时附移除入口 | 可编辑标签与只读业务状态样式区分；运行/失败等必须有文字，不只看红绿 |
| 提示/横幅 | 图标、文字、语义颜色、侧边标记 | 成功结果可短暂提示；配置错误、冲突和必要操作保持可见，并提供修复入口；保存失败不只显示一闪而过的提示 |
| 确认框 | 操作对象和后果清楚，安全选项优先 | 默认焦点落在取消等安全项；输入不穿透背景，关闭恢复原焦点，删除项目配置与删除目录明确区分 |
| 折叠分组 | 大三角表示展开/收起，内容缩进 | 用于高级选项/项目覆盖；符号和文字均可点击，不能只靠细小箭头命中 |
| 键值行 | 名称与只读值对齐，弱分隔连接 | 用于实际配置路径、版本、有效来源；路径可复制，版本来自程序，不写死演示数据 |
| 页签 | 当前项填色，其他项弱底色 | 仅在确有局部子页面时使用，避免和主分类导航重复；样式与分段控件一致，但切换页面和修改值的语义分开 |
| 进度 | 已完成区、未完成区与进度文字并列 | 仅已知总量时显示百分比；未知总量显示活动标记与已发现数量，不能按定时器虚构进度 |
| 底部操作区 | 修改状态与保存、放弃、恢复集中排列 | 长内容滚动时仍可达；清楚说明保存覆盖所有分类、恢复只影响本页草稿，不使用演示提示代替真实保存结果 |

### 3.4 统一状态与视觉验收

组件按适用性定义普通、悬停、键盘焦点、已选、禁用、校验错误和未保存状态：输入/选择控件覆盖其编辑状态，按钮覆盖可触发状态，只读键值行和进度无需制造“已选/未保存”。悬停只表示指针位置；已选表示当前值；键盘焦点额外使用指示符或边框。选中值获得焦点时，两种信息仍能同时看见。禁用操作跳过常规 Tab 顺序，但所属设置行仍可选中查看原因；禁用内容不执行。

颜色之外始终提供符号或文字。正常提示、警告、错误、进行中与不可用状态不能混成同一种强调色；终端主题或低色彩环境中仍应能判断含义。

样式复用顺序为颜色/文字层级/间距/边框/焦点规则，再由按钮、输入、列表等组合；不为组件单独扩充配置文件或通用样式脚本。后续渲染与交互测试需覆盖：深浅主题、中文/英文、窄窗口、长路径、控件选中同时获焦点、纯键盘操作、禁用/错误/未保存状态，以及弹层关闭后的焦点恢复。与 §8 的功能验收同时满足，不能仅凭截图相似认定完成。

### 3.5 常用流程与输入规则

| 流程 | 进入与编辑 | 保存、取消与失败 |
| --- | --- | --- |
| 修改全局默认 | 从菜单/命令面板打开；未选中项目时 F4 打开“项目”分类的项目选择列表，显示“请选择项目”，全局分类照常可用；不隐式采用上次项目 | Ctrl+S/保存提交全部分类草稿；有错误则定位第一个错误所属分类、项目和控件，其他草稿保留；无草稿关闭不写文件 |
| 设置项目覆盖 | 有当前项目时 F4 直达该项目；工作区使用任务的原项目路径，不拿 checkout 当新项目；页头始终显示目标完整路径。可继承项显示有效值、来源和“继承/覆盖”；标题/颜色只显示自定义值或“无自定义值” | “覆盖”以当前有效值初始化草稿；“继承”删除该项覆盖。切项目保留各项目草稿；恢复本页清当前项目启动/侧栏覆盖（含标题/颜色），收藏、检查定义、项目/预设等实体通过各自明确操作修改 |
| 编辑并应用预设 | 保存队列为预设时捕获 §5.5 的值及顺序；会话 ID 需先转为明确续接策略。设置页编辑名称、顺序和启动值 | 保存预设只保存定义；已提交预设的“加入启动队列”只暂存，不启动。有预设草稿时提供“保存全部后加入 / 放弃本预设草稿后加入 / 返回”，首项走外层全部校验和原子保存，第二项不丢其他分类草稿、采用已提交定义。队列允许本次修改，最终显式启动，启动失败按原批次机制保留结果 |

“恢复本页”在全局分类删除该页偏好覆盖，在项目详情仅恢复当前项目启动/侧栏默认（标题/颜色回到无自定义值），不批量删除目录列表、收藏、预设和 prepare/check。数据管理及快捷键页的恢复操作显示具体范围；快捷键按 docs/52 处理。

普通设置行包含多个子控件时，Tab/Shift+Tab 按导航→内容可用控件→操作区顺序移动；方向键在导航/列表中移动，在选择/数值控件中改值，在文本框中移动光标。单行 Enter 确认当前编辑，Space 仅在按钮/开关等适用控件中触发；多行命令 Enter 插入换行。Ctrl+S 保存、Esc 逐层关闭弹层/子编辑，回到页面后再触发关闭处理；具体绑定仍走 docs/52 的命令表，录制、输入法和文本输入优先级遵循其规则。存在未保存草稿时提供“保存并关闭 / 放弃并关闭 / 继续编辑”，默认继续编辑，保存失败仍留在设置页。

复合字段的具体编辑边界：

- Agent 参数按有序条目编辑，每条是一个字面参数，保留空参数；增加、删除、排序不做 shell 分词。可提供数组文本编辑入口，但不能将整段命令按空格拆开；例如 ["--model", "中文 名称", ""] 的第三项不能丢失。
- 额外会话每项含名称、PowerShell 命令、目录；支持添加、删除、排序。继承时只读展示有效列表，转覆盖后复制整份列表；删除末项得到显式 []，另有恢复继承操作。名称按大小写不敏感去重，错误定位具体条目，目录空值为当前任务工作目录；未启用的列表仍校验结构，当前未启用不执行。
- Debug/额外会话命令使用多行编辑器，输入仅编辑文本；prepare/check 的 argv 为字面参数列表，cwd、env、timeout 分字段编辑，不模拟键盘将命令送进 PTY。
- 预设条目、会话顺序都有业务意义。一次草稿内使用内存行标识维护焦点，保存时会话/argv 以所属整数组合并，避免为此新增持久 UUID；预设 entries 的并发顺序变更按整列表冲突处理。

### 3.6 逐项组件选择与页面骨架

本节为目标 UI 规格，不表示现有 F4 已实现这些组件。依据 §2 的实际能力、§5 的字段契约选择组件：独立布尔使用带文字的复选开关；两三个短且互斥的值使用分段单选；较多选项或需要逐项说明时用下拉/单选列表；精确数值用可直接输入的步进框；空间比例配可视化与精确输入；有序复合数据使用列表加详情编辑。TOML 键路径只在“来源/诊断/复制字段路径”中展开，常规界面显示用户能理解的名称。

所有页面复用同一外层：标题及关闭入口、分类导航、可滚动内容、固定底部操作区。顶端只放阻断错误/保存冲突等持久横幅，字段错误紧邻对应控件。底部显示全窗口未保存数量和“保存全部 / 放弃修改 / 恢复本页默认”；无实际改动时保存不可用，关闭仍可用。复合编辑器的“完成”只合入内存草稿，不另写文件；有子草稿时 Ctrl+S 先校验并收入子编辑，再执行保存全部，不能跳过未完成输入。首次进入仅展开常用分组；高级分组有错误时自动展开并定位。

| 页面 | 由上到下的内容 | 页面内的组织方式 |
| --- | --- | --- |
| 外观与语言 | 语言→主题→主题示例 | 简单设置行加一个紧凑静态示例，示例不含可执行业务按钮 |
| 总览 | 默认排序/筛选→信息面板→分栏尺寸 | 简单设置行；尺寸分组带两栏/三栏示意 |
| 启动与终端 | 默认启动→参数与命令→终端高级 | 组合、布局始终可见；长文本和会话在专用子编辑器中完成 |
| 项目 | 项目设置 / 发现目录 / 启动预设 | 三个有实际职责的局部页签；F4 直达项目设置，保留该项目与局部滚动位置 |
| 文件与预览 | 文件树→Agent/预览分栏→文档阅读→图片 | 简单设置行；文件树与比例有小示意，图片能力另列只读状态 |
| 快捷键 | 前缀→搜索/筛选→命令列表与详情 | 嵌入 docs/52 的管理器，使用外层统一保存区 |
| 通知与集成 | 通知策略→宿主采用状态→Hooks/系统通知 | 策略是草稿，安装、诊断、测试为单独操作区 |
| 配置与数据 | 路径/格式→错误与重载→配置操作→用户内容→清理 | 只读键值行与命名明确的按钮，不制造操作型布尔配置 |

宽度充足时名称与控件同一行、说明在下；内容不足以容纳最长选项、来源和焦点标记时改为上下排列。项目/预设/命令列表在宽窗与详情并列，窄窗先显示列表、确认当前项再进入详情；提供明确返回入口，保留选中项、草稿和滚动位置。高级多行编辑器占用内容区或独占弹层，允许内部滚动，底部完成/取消保持可达。分类窄屏入口为显示当前分类名称的可点击选择器，不强行保留空侧栏；即使空间不足也保留关闭、返回和未保存处理入口。

### 3.11 快捷键的逐项设计与统一草稿

入口打开同一管理器并定位本分类；菜单直达 shortcuts.open 也进入同一设置系统，命令目录、冲突、录制与测试规则以 docs/52 为准。该文档中的独立弹层“应用/取消”在嵌入时映射为外层保存全部/放弃修改，不再保留一个会绕过其他设置草稿单独落盘的应用按钮；录制完成只进入草稿。

| 配置项 / 展示名 | 组件 | 交互边界 |
| --- | --- | --- |
| shortcuts.prefix / 命令前缀 | 按键帽摘要＋更改按钮，打开“录制/文本”两种输入模式 | 任意支持的有效 chord 经统一校验；不照搬 HTML 固定 Ctrl+G/Ctrl+A/Ctrl+B 分段，因为它们不是可随意互换的无风险选项 |
| bindings[].command/context / 命令与区域 | 可搜索命令列表＋当前命令详情，区域为允许范围内的下拉选择 | 显示本地化名称及可展开的稳定 ID；只有允许区域能选，不允许任意输入 context 字符串；创建条目先确定命令和区域 |
| bindings[].add / 自定义绑定 | 有效绑定逐行列表＋添加按钮；录制区/文本输入复用解析器 | 一行一个 chord 或两步序列，不用逗号文本框存全部别名；已有默认键单独标注，追加不替换原集合 |
| bindings[].remove / 已删除绑定 | 当前绑定行的删除动作＋可选备注输入；删除项在详情中可恢复 | remove 由删除默认绑定产生，删除新增项只去掉 add；不会展示底层字符串数组要求普通用户手动维护 |
| bindings[].disabled / 此区域全部快捷键 | 独立的“停用此命令在此区域的快捷键”复选开关 | 文案注明包括未来新增默认绑定，菜单/鼠标命令仍可用；恢复启用按原差异值，不丢原配置 |
| bindings[].preferred / 提示中优先显示 | 绑定列表内的单选标记，每项可“设为首选显示” | 候选仅限该命令/区域的有效绑定；不会因换首选删除 F3 或生成新别名；无有效绑定时显示不可用原因 |
| bindings[].notes / 删除备注 | 删除时可填、详情可编辑的短文本，随对应键展示 | 只是用户说明，不表示已探测外部占用；删除/恢复备注按 docs/52，不生成“外部保留”策略层 |

顶部搜索支持命令名/ID/按键文本，筛选用下拉选择“全部/当前区域/已修改/未绑定/内部冲突/含删除备注”；搜索与筛选是 UI 临时值。宽窗命令列表旁显示详情，窄窗确认命令后进入详情。原始 add/remove 差异可在诊断中只读展开；“已修改”以有效注册表和用户差异计算，不以手工编辑过某一行猜测。

内部冲突提供双方命令、区域、键和明确替换按钮；外部未收到只作事实提示。按键测试使用独占弹层，目标区域下拉、测试记录与预计结果只读；不执行预计命令。测试使用当前已提交生效表，另以清晰标签展示草稿预计结果（有草稿时），避免把未保存绑定宣称为已生效。录制 Esc/Enter 时仍有鼠标完成/取消入口。恢复当前命令、导入、恢复全部先改草稿；导出/备份默认取已提交差异，若提供导出草稿需明确选项，不暗中保存草稿。

单任务静音、通知一次、稍后提醒、检查后通知继续在任务菜单，不在设置页列成全局偏好；可提供文字入口说明。操作区与“保存全部”用分组和“立即执行”标记区分，正在执行的同一操作不可重复点击，完成后不清除其他配置草稿。

| 恢复偏好默认 | 选择范围的确认框，列出将删除的覆盖 | 确认后仅更新统一设置草稿，保存全部后才落盘；不删除发现目录实体、预设、收藏、用户内容或任务；快捷键恢复按其规则；默认焦点取消 |
| 配置导出 | 路径输入＋范围选择（完整配置/快捷键）＋导出按钮 | 导出已提交配置，不创建新的生效来源；有错误时标注诊断状态，不暗中清洗。导出全配置含命令/env 等用户内容，预览范围后确认覆盖目标 |
| 用户内容备份/恢复 | 归档路径输入、备份按钮；恢复先显示内容摘要及差异再确认 | 导出配置不冒充完整工作区备份；用户内容操作仅针对 user-data。恢复按便签路径/书签 ID 展示新增、同值和冲突，使用当前值作 base 走 §6.3，重复 ID/坏归档拒绝，备份恢复不动运行任务 |
| 清统计缓存 | 明确对象的按钮＋将清理路径/范围确认 | 只作用 cache 下已知可重建统计缓存；执行结果报告成功/失败，不用 clear_cache 配置字段 |
| 重置 UI 记忆 | 单独按钮，确认列出最近时间、折叠与全局终端浮层默认 | 只改 ui-state，已有窗口不跳位置；不清启动预设、用户内容或任务恢复记录 |
| 便签/书签管理入口 | 跳转按钮或位置说明 | 打开其所属编辑器/列表，正文不作为设置表单字段 |

字段错误保持在所属行下，错误摘要列“分类→项目/命令→字段”，可键盘选择跳转并展开所在高级组。跨窗口保存冲突用详情弹层显示“打开时/最新已保存/我的修改”；长文本按段落上下切换而非窄屏三列挤压。用户可采用最新值，或保留我的值重新以最新 base 形成待保存草稿；父实体删除冲突必须明确选择放弃编辑或重新新增，不能自动复活。冲突处理结束后仍需保存全部。

列表空态给出对象含义与对应添加入口；后台探测中只显示真实活动状态，不虚构百分比；不可用项给出原因和可执行的修复动作；保存失败持续展示且不清草稿。高级分组展开、预设/项目选择、测试上下文、搜索和探测结果均不新增持久偏好字段。

## 4. 需要哪些文件

### 4.1 一个配置文件，两个辅助存储

```text
<数据目录>/
  config.toml             唯一生效的用户偏好与项目配置
  user-data.json          用户内容：项目便签、书签、书签备注
  ui-state.json           UI 记忆：最近打开、折叠、浮层几何等
  runtime/                宿主/任务业务文件，按实际所有者保存
  cache/                  可重算统计等缓存
```

这里**配置文件只有一个**。user-data.json 和 ui-state.json 是程序存储，不是额外偏好层；无内容时不必预建。TOML 服务于手改偏好，JSON 服务于结构化程序存储，不要求全项目所有持久文件使用同一种格式。

| 文件/目录 | 必要内容与理由 | 写入与清理 |
| --- | --- | --- |
| config.toml | 全局默认、项目覆盖、目录、收藏、预设、快捷键、通知 | 真实设置编辑时写；恢复默认只影响选定偏好 |
| user-data.json | 便签和书签共用低频用户内容存储，减少重复读写机制；合并后仍分别保留实体校验与容量边界 | 锁内读最新，内容编辑做基值比较；损坏报错，禁止空默认覆盖；完整备份必须包含 |
| ui-state.json | 低频 UI 记忆、项目最近时间，需要自动保存但不应改用户配置 | 最近时间取较大值，折叠按组更新，浮层整矩形采用最后确认的布局；见 §6.3 |
| runtime/ | tasks、launches、activity、layouts、checks、preparation、rounds/objects、lifecycle、按任务通知设置、通知注册事实等 | 保留各自事务/身份/并发所有者；名称不意味着可随意删除，其中多项需持久恢复 |
| cache/ | 统计等可从原始事实重新计算的结果 | 可显式清理，不包含任务唯一记录、轮次唯一数据或用户内容 |

任务日志/轮次对象不能和 UI 记忆合为一个大 state.json：它们有独立校验、体量及恢复事务，合并会扩大故障和写入范围。反过来，没有独立生命周期或性能证据的低频设置不单独建文件。

不增加 settings.json、shortcuts.toml、projects.toml、presets.toml、themes 目录、local.toml、覆盖文件或配置数据库。源码默认值留在代码；不同时维护一份默认 TOML 和代码默认。

读取阶段不创建文件；界面使用代码默认值。实际配置编辑、用户内容编辑或 UI 记忆更新时分别创建相应文件。

辅助文件的目标数据形状：user-data 顶层为 notes（规范项目路径到正文的映射）和 bookmarks（已有书签 ID、project、path、byte/line、anchor、markdown、note 的列表）；ui-state 顶层为 projects（各项目 last_opened）、overview（折叠组等）和 floating（应用内终端浮层的全局最后确认矩形）。floating 延续当前 terminal-panel.json 的跨窗口默认布局语义，并非 Windows 窗口位置；正在运行的窗口不因别处保存而移动，后续新前端加载默认矩形并适配终端尺寸。任务 UUID、活动 ACK 和检查状态均不进入这两个文件。

用户内容的读取按实际字节数限流，统一文件上限 16 MiB；书签子集继续采用当前 8 MiB、4096 条总量、每项目 128 条、备注 256 字符、anchor 128 字符限制，便签继续每项目 2048 字符。16 MiB 是合并存储的工程预算，不是可调偏好；到达容量边界仍允许删除和不增大受限部分的编辑，超限拒绝写入且保留原文与草稿。统一存储改变布局，不删除书签的 Remap/定位能力，也不以少建文件为由取消原有边界。

### 4.2 取消自动读取项目文件

项目差异全部放在 config.toml 的 project 条目里。**新设计取消 `.devtabs.toml` 的自动加载和设置回写**，prepare/check 同样从中央项目条目读取。其当前功能改由中央配置承担，不再保留“共享文件和本地文件谁优先”的第二套问题。

这里需要同时改 [checks.rs](../src/checks.rs) 的 initialize 与宿主检查入口：当前它们还直接加载 Profile。检查必须按任务的原项目路径找到中央定义，再以实际 task checkout 解析 cwd；只改 F4 表单不足以完成统一。

团队共享模板目前没有被确认为必需能力，因此不新增活跃共享配置层。以后如有需求，可以显式导入/导出项目模板：导入预览后写入同一中央模型，模板本身不持续参与运行时覆盖。这是明确的新操作，不是旧格式迁移要求。

配置与用户数据备份可以由显式命令生成普通归档；无需为未发布配置设计自动迁移批次、迁移备份清单和多文件提交协议。外部 Hooks 的 ownership/备份是防止改坏其他软件的现有业务机制，不能因此删除。

### 4.3 准备步骤与检查配置的生命周期

目标采用“准备随任务固定，检查按次求值”，不对全部配置建立持久版本库：

| 对象 | 取值时机 | 保存后对既有任务的影响 |
| --- | --- | --- |
| prepare | 主任务首次登记、子任务生成 Plan 时，按原 project 路径读取并校验中央定义；将完整有序 Spec 列表写入已有 Task/Plan 业务记录（目标 Task.prepare 字段） | 已有任务及已生成的 Plan 继续使用其快照；新 Plan/新任务采用新定义。复制创建子任务重新读中央定义，不复制父任务的旧 prepare |
| 默认 check | 用户明确请求检查时，按 Task.project 读取最新有效 check；请求中显式给定 Spec 则使用该 Spec | 下一次检查采用新值；当前正在执行的检查不改命令、不重启，失败后再次请求是一次新检查 |
| 一次准备/检查执行 | 在开始前确定完整 Spec、task/checkout、run/result 等身份，释放配置/宿主状态锁后执行 | 执行线程不再中途读取中央配置；结果归属、stale 判断、租约和进程清理沿现有规则 |

主任务登记和子任务计划阶段只捕获准备定义，不执行命令；实际执行保留当前显式初始化、AddTask 在启动会话前初始化的入口。重载配置、恢复连接、恢复设置默认本身不触发准备。主任务初始化同样使用已记录的列表，不临时重读。空列表是确定的快照，之后新增中央 prepare 不会自动作用到旧任务；需要新定义时创建新任务，本轮不增加“强制重做全部准备”功能。

initialize 改为接收已确定的准备列表和实际 checkout，保留当前按任务、步骤索引与完整 Spec 摘要记录成功的机制；重试跳过已成功步骤、从未成功步骤继续，失败/超时不记成功。宿主重启、Plan 重试继续使用原快照。Task/Plan 快照缺失或损坏按业务记录错误处理，不能用最新配置偷偷补齐；这不是旧格式兼容要求。

快照复用现有 Task/Plan 序列化，不另建快照文件；计入 Catalog 当前 8 MiB 总预算，生成计划/登记时先检查序列化后的总量，超限在创建资源或执行命令前报告，不能临时回退到配置引用。该预算及命令输出上限继续是代码约束，不增加偏好开关。

中央 cwd 的相对值以实际 task.checkout 为基准，原项目路径仅用于查定义。绝对 cwd 保留现有执行时 canonicalize 后必须位于 checkout 内的限制；设置保存不要求尚未生成的 checkout 存在。命令语法校验、prepare 最多 16 步等在创建 Plan 前完成，目录存在性/可执行程序等在执行环境中再校验，失败不回退执行另一个命令。prepare 与 check 独立诊断，单独 check 错误不阻止合法启动。

### 5.2 层级、默认和存在性

仅需要：**代码默认 → 用户全局覆盖 → 该项目覆盖 → 本次显式启动覆盖**。不增加目录层、项目 Profile、用户脚本条件和主机专属覆盖文件。

- language、theme、notifications、shortcuts 始终用户级。项目只允许 launch、sidebar、checks 和 favorite/path；路径不能借任意表提升作用域。
- 可继承字段缺失表示继承。false、允许的空字符串、空数组都是存在的覆盖，不可以用 truthy 判断丢掉；实体元数据、检查定义、快照字段按 §5.4–5.5 的规则解释。
- 恢复继承删除字段；明确设置为当前默认仍可存储，避免以后默认变化时悄悄变动。
- launch 的字段级覆盖保留存在性，sessions/agent_args 为整体替换；空数组清空继承。debug_command 空字符串表示没有启动命令。
- title/color 仅允许项目级和本次启动/预设使用，不设全局默认。项目中缺失或显式空字符串均表示无自定义值，保存时空值可规范化为删除字段；不因可选字符串引入通用 null/清空标记。全局 launch.title/color 提示作用域错误，不当作有效全局值。
- composition 默认由代码明确指定为 agent-debug，不再根据 sessions 是否非空暗中改成 custom。选择 custom 才使用额外会话；切回其他组合可保留列表，但界面明确标注“当前未启用”。
- checks 只有项目级定义；prepare 整体替换，check 缺失表示未配置，读取/导入本身不会执行任何步骤。
- 本次 CLI/启动表单只覆盖用户明确填写项。不能把 clap 的默认 Agent/layout 当作用户指定值覆盖配置；CLI 参数解析与默认求值要分离。
- --data-dir/DEVTABS_HOME 是定位配置之前使用的引导参数，不放进它自己所定位的 config.toml；workspace/view/run/lease、restore/last/fresh 等身份和一次性动作也不直接持久化。
- 局部命令继续方便使用，但必须明确是“仅当前视图”还是“保存为默认”；显示开关不能无声改变下次启动配置。

### 5.3 项目、预设与快捷键

项目仍使用规范化绝对 path 作为唯一键，不为设置重构增加项目 UUID。Windows 路径比较统一分隔符与大小写规则，保留盘符根/UNC 语义；暂不可达目录可保留，重复规范路径拒绝保存。路径写单引号或正斜杠，避免 TOML 反斜杠转义；项目移动需显式更新相关引用，不按目录同名猜测。

会话 directory 的相对路径沿当前 host::spawn_task 以 Task.cwd 为基准，缺失时也使用 Task.cwd；普通主任务通常为 project.path，子任务保持其在新 checkout 内的模块相对位置。Task.cwd 与 Task.checkout 可能不同，解析后仍须位于实际 checkout 内；检查 cwd 则以 checkout 为基准，见 §4.3。shell 仅支持 PowerShell 兼容程序的命令名或绝对路径，命令名由启动时环境解析；当前 shell_args 固定使用 -NoLogo/-NoExit/-EncodedCommand，不能据字段名宣称支持 cmd/bash。项目和发现路径不依进程当前目录变化，不隐式展开环境变量语法。

预设是有序启动快照，而非项目名称引用数组，也不序列化完整 CLI Options。每个 entry 包含绝对项目路径及 §5.5 的完整启动值；title/color 等指定可选值缺失在快照中表示无值，不回退到后来变更的项目配置。套用快照后允许本次用户显式调整；界面偏好与活跃任务身份不冻结进预设。

快捷键继续使用 docs/52 的 add/remove/disabled/preferred，不按普通数组替换；F3 与 Ctrl+F3 共存，首选只影响展示。其差异字段由根 schema 统一管理，单独导出快捷键时也使用相同 config 容器，不增独立文件格式。

### 5.4 字段契约与类型边界

内存职责明确区分稀疏的 LaunchOverrides（保留是否存在）、求值后的 ResolvedLaunch（值与来源分开）和完整的 LaunchSnapshot（预设重复启动值）；这些名称描述职责，不要求通用继承框架。快照解码不能复用带继承默认的覆盖解码器。设置页的来源信息为派生值，不持久化。

| 字段 | 层级与缺失/空值语义 | 默认、范围及依据 |
| --- | --- | --- |
| schema | 文件根格式标识；实际文件中必填，文件整体缺失则直接使用代码默认 | 本格式为整数 1；缺失、类型错误或不支持的值阻止配置保存与新的配置驱动操作，保留修复入口及已有运行会话 |
| general.language、appearance.theme | 用户级，缺失用代码默认 | auto；terminal。枚举沿 i18n::Language 与 appearance::Theme，不把示例 zh-cn/tokyo 当默认 |
| overview.sort/filter | 用户级，缺失用代码默认 | recent/all；分别采用 model::Sort、Filter 的现有枚举 |
| overview.detail/statistics | 用户级布尔，false 是覆盖 | 均 true，沿当前 App 初始化逻辑 |
| overview.list_ratio/detail_ratio | 用户级可选整数；缺失为自动布局；恢复自动删除字段 | 1–9999 万分比。均相对总可用列宽；两项显式设置时总和须小于 10000。自动策略沿 columns：列表三栏 3800、两栏 4400，详情三栏 3800；实际渲染继续服从列最小宽度，不把窄屏裁定后的值回写请求值 |

### 5.5 预设快照的精确范围

当前 tests/reference_parity.rs 已覆盖 fresh、new_instance、new_window、no_profile、history 和字面参数。目标保留这些可重复的启动能力，具体边界如下：

| 分类 | 字段与规则 |
| --- | --- |
| 固定的启动值 | entry.project；entry.launch 下 agent/layout/composition/shell/agent_args/debug_command/sessions/title/color；entry.terminal.history_lines。更改全局或项目默认不改变这些已保存值 |
| 固定的会话策略 | entry.launch.conversation 必填 latest/fresh/picker，分别映射当前 continue_latest、fresh、resume 意图。全局/项目 resume_latest=true/false 对应 latest/fresh；CLI --fresh/--resume 和本次面板可显式覆盖。只有准备真正新建 Agent 时才解析 latest 对应的具体会话 ID |
| 固定的启动选项 | entry.launch.new_window/new_instance/no_profile 均为必填布尔。后两项只允许在本次启动与预设，不增加同名全局/项目偏好；保留现有预设断言，no_profile=true 时仍生成 -NoProfile |
| 每次采用的当前偏好 | 语言、主题、总览、快捷键、通知、sidebar/preview 默认，包括 image_protocol；它们服务于前端而非冻结的 PTY 启动。预设应用后的显式本次视图覆盖仍可使用 |
| 每次采用的项目业务定义 | prepare 按新任务/Plan 捕获，check 按检查请求求值，遵循 §4.3；预设不作为检查配置第二来源 |
| 仅本次或业务恢复使用 | resume_id、workspace/view/navigation、run/lease/recovery/window_group 等身份；restore/last/headless、data_dir、image_cell_size 等动作/诊断。继续保留对应 CLI、历史会话与恢复入口，均不写入预设 |

快照必填范围：project、launch 的 agent/layout/composition/conversation/new_window/new_instance/no_profile/shell/agent_args/debug_command/sessions，以及 terminal.history_lines。快照只有 title/color、每个 session 的 command/directory 可缺失，表示无自定义值/使用 Task.cwd；debug_command=""、agent_args=[]、sessions=[] 必须显式保留。缺少任一必填值属于无效快照，不借代码默认或项目当前值补全。

保存预设从本次已确定启动意图捕获，而非从已解析的执行 Options 反推。例如 latest 已解析出 resume_id 时仍保存 latest；若本次是用户明确指定历史会话 ID，保存前要求用户选择 latest/fresh/picker，不偷偷变成 latest，也不保存该 ID。普通启动、预设、CLI 最终转换为同一执行模型，但保留来源与意图直到完成捕获。

上述有意变化需记入发布说明和改后测试：预设不再冻结前端语言、图片协议/像素诊断或具体会话身份；仍能在本次打开时显式选择它们。原测试里启动策略/历史行数/no_profile/new_instance 等功能断言保留；依赖“序列化整个 Options”的结构断言改为本节逐字段断言。

## 6. 配置服务与交互契约

### 6.1 最小职责划分

保留 TOML 文档以局部编辑注释；类型化用户覆盖与有效设置在内存求值。一个 SettingsStore 负责读取、校验、合并与保存，设置页、CLI、快捷键菜单、宿主通知操作共用它。

另有 UserDataStore 与 UiStateStore 管理两类辅助存储，复用锁和原子写工具，不为每个偏好各建 service/文件。任务/检查/轮次沿已有业务存储，不能让设置服务接管 PTY 或持有宿主状态锁执行文件 I/O。

每个设置项登记唯一键路径、类型、默认/继承、允许层、校验、生效时机与文案。用于菜单绑定和校验，不开发任意 UI schema 语言；项目会话、预设和快捷键等复合编辑器可用专用组件。

字段规格以 §5.4–5.5 为实施契约；代码登记表是其唯一执行实现，不再在设置控件、CLI 和宿主各写一套默认值。错误包含文件路径、逻辑键路径、所属项目/预设、原始值位置和阻止的操作；来源展示区分“原文无效”和“当前有效回退值”。

### 6.2 读取与失败

- 文件缺失使用代码默认，读取不落盘。根格式号不支持则提供诊断，拒绝写入，不尝试迁移。
- TOML 语法错误无法可靠分段：运行窗口保留最近合法内存值，首次启动提供原文修复入口，禁止默认值覆盖坏文件。
- 语法合法时，普通偏好错误定位具体路径并隔离；项目启动/检查和预设错误阻止相应操作，不能回退成另一个命令后执行。
- 未知字段提示未应用并保留原文，避免拼写错误悄悄成功；保存无关字段不删除它。此行为用于手改诊断，不承担旧/未来格式兼容。
- 快捷键无效按 docs/52 隔离，默认表保证管理入口可达；录制/测试不能执行背景命令或写 shell。
- user-data 损坏报告错误且保留原字节；UI 记忆损坏可回退默认并说明，不清理任务业务文件。

目标错误隔离与操作矩阵：

| 情况 | 显示/读取 | 保存与执行边界 |
| --- | --- | --- |
| 项目 A 的 check 无效、项目 B 正常 | A 检查字段展示原值与错误；不伪装成“未配置” | 可保存主题和 B 的有效草稿；A 的默认检查被阻止。A 的有效启动、prepare 不因独立 check 错误被阻止；显式提供并校验通过的本次检查 Spec 可用 |
| prepare 或会话/启动字段无效 | 定位对应数组项/字段及来源 | 仅阻止依赖该无效定义的初始化/新任务/启动，不回退成默认命令；无关外观仍可保存。仅 Agent 组合也不能掩盖同一启动定义内无效会话结构 |
| 普通偏好如主题/比例无效 | 显示原文与错误，并单独标示最近合法值；首次读取回退代码值 | 可保存无关项，保持错误原文；编辑该项必须修复或恢复默认。回退值不能因浏览、切分类或保存别处而落盘替换原文 |
| 快捷键段已有错误 | 显示 docs/52 的隔离诊断及实际有效表 | 未修改快捷键可保存语言；修改快捷键必须通过整个绑定依赖组校验，不把无效草稿发布成半套索引 |
| 本窗口在多个分类新增了有效/无效草稿 | 草稿按全窗口保留，汇总错误定位到具体分类和控件 | “保存全部”原子提交全部草稿；任一改动或其依赖校验失败则本次全部不写，禁止暗中只保存有效分类 |
| 外部文件已有未知项或作用域错误 | 保留原文并诊断；已知但放错层的执行字段阻止相应求值 | 保存无关字段不清洗文件；整个表不可解码时将该实体或段作为错误边界，仍允许其他独立段使用 |
| 根 schema 缺失/不支持或 TOML 语法坏 | 文件级诊断，已有界面使用上次合法内存值；首次启动保留修复入口 | 阻止全部配置保存及新的配置驱动启动/检查，已有运行会话与已捕获执行继续；提供原文件打开/复制，不以默认覆盖原字节 |

保存先比较 latest 与 base，再对“实际改动字段＋依赖闭包”校验；不要求未编辑的既有错误全部修好。比如改 Agent 或 composition 必须重验该对象的参数、会话和启动组合；改任一总览比例必须重验配对比例；改一个快捷键需重验完整索引；改项目 launch 不触碰无关 check。未知项不参与执行。文件已提交后，已知执行定义存在错误时仍对相关操作阻止执行，不能因为有上次合法缓存就执行已被用户改坏的旧命令；正在执行的任务按 §4.3 保持本次定义。

### 6.3 保存与并发

草稿仅记录实际变更路径及 base。保存取得数据目录配置锁、读 latest、执行字段级三方比较；不同字段合并，同字段不同值显示冲突并保留草稿。project/preset/shortcut 用 path、name、command/context 定位，不能依数组下标合并。

具体比较：draft==base 表示未修改；latest==base 时接受 draft；latest==draft 时视为已完成的同值变更；其余同字段变更为冲突，包含缺失/删除状态。父实体被删除与子字段编辑冲突。sessions、agent_args、discovery 各路径数组和 preset.entries 以整数组为字段；project/preset/shortcut 实体的增删改按语义键定位，顺序调整按所属有序列表冲突处理，不尝试猜测两次重排的合成顺序。预设改名在同一次 config 提交中检查旧实体及目标名称，两个窗口改名/编辑同一实体不能产生重复或复活已删除项。

使用 toml_edit 局部更新文档，重验受影响的字段与依赖；同目录临时文件写完并同步后原子替换，成功才发布内存值。原子替换、并发冲突和失败恢复是新版本自身的正确性要求，与旧格式兼容无关。

外部编辑器不遵守 DevTabs 锁；替换前内容摘要检测能发现已发生变更，但检查和替换之间仍有竞态，不能承诺跨任意编辑器的绝对事务。保留可恢复的原字节副本用于保存失败/用户显式恢复，不建立迁移批次系统。

便签、书签、最近时间和当前浮层几何变化不得写 config.toml。UserDataStore 和 UiStateStore 同样按实际变更操作合并，不能各窗口覆写整份旧快照。

辅助存储采用以下操作语义，共用锁内读最新、校验、原子替换工具，不共用“所有冲突都最后写入胜出”的策略：

| 对象/操作 | 并发规则 |
| --- | --- |
| 编辑或清空同一项目便签 | 保存携带打开时正文 base 和新正文；按三方比较，内容不同的并发编辑报冲突并保留草稿、展示最新正文，用户重新编辑/明确采用其草稿后再对最新基值保存；不会自动拼接正文。不同项目便签独立合并 |
| 新增书签 | UUID 按现有方式产生；同 ID 同值幂等，不同值拒绝。项目/绝对路径/容量校验沿现有业务，不能覆盖另一项目条目 |
| 修改书签备注/定位字段 | 只提交实际变更字段及各自 base。备注编辑与路径 Remap 可合并并保留最新路径；同字段不同值冲突。条目已删除则拒绝更新，不能用旧 Put 重建 |
| 删除书签 | 携带看到的条目基值；最新条目已改变则提示冲突，已删除则幂等；确认删除需以最新条目重新提交 |
| 文件操作的书签 Remap | 延续已有受管文件操作来源、按项目和当前路径更新的规则；对最新记录改 path 或删除受影响条目，不覆写其他备注。该文件操作已删除对应书签时，旧备注草稿只能报已删除 |
| 最近打开时间 | 更新 projects[path].last_opened=max(latest,event_time)，采用打开事件时间，不采用后台写入完成时间 |
| 总览折叠记忆 | 按组 SetCollapsed(group,bool) 更新；不同组独立合并，同组按完成的保存顺序记忆 |
| 全局终端浮层矩形 | 移动/缩放确认后以一个矩形提交，按最后完成的保存记忆；x/y/w/h 不跨窗口拼接。拖动中和取消不写，既有窗口只更新自己的本地几何 |

内容冲突的处理停留在便签/书签所属编辑器，不把用户内容加入设置草稿；取消编辑不修改文件。冲突判断在锁内完成，容量失败和磁盘失败都保持原文件、保留本地草稿。用户明确重试覆盖也须以当时最新基值提交，不提供绕过比较的无条件写。

### 6.4 生效时机

| 设置 | 生效 |
| --- | --- |
| 语言、主题、当前总览外观 | 当前前端保存成功后生效；主题草稿预览可撤回 |
| 快捷键 | 保存后完整索引切换，已有按下/松开所有者按 docs/52 延续 |
| launch、terminal.history_lines | 新建对应会话时采用；复用会话不重新启动 shell |
| sidebar/preview 默认 | 新建视图/文档采用；如提供“应用到当前视图”，必须显式且保留未保存编辑内容 |
| 全局通知 | 配置提交与宿主采用分别报告；宿主校验成功后整段替换，失败保留上次合法值并给诊断 |
| 其他窗口、外部手改 | 复焦/显式重载时核对摘要；有草稿时合并或提示，不覆盖草稿 |

首期无需常驻监听。宿主在处理通知设置/准备发送通知时可按文件版本检查有效值，不能只让前端生效。所有路径共用同一配置读取规则，避免 UI、CLI、宿主各有默认值。

主题预览的 base 用于配置三方比较，不能同时充当撤销目标。前端另保留最近已确认的 committed 值；重载发现外部新主题时更新 committed，当前预览仍仅作为本窗口临时覆盖。放弃/关闭预览时重新核对文件并撤去临时覆盖，显示最新合法 committed；读取失败则使用最近合法 committed 并诊断，绝不将打开设置时的旧主题写回磁盘。保存成功后 committed 更新为本次实际合并结果再结束预览；写入失败继续保留草稿/预览，提供重试或放弃。

通知的最小生效反馈复用现有 Request::Notifications/Action::Diagnostics 与 notifications::View；当前 View 仅有 enabled/diagnostic 等，目标补充只读的已采用摘要、最近检查摘要及错误状态，不新增独立同步协议。前端保存后显示“已保存；通知由宿主下次处理/发送时重载”，只有观察到宿主已采用同一配置摘要才显示已生效；宿主离线、摘要未知或读取失败显示未确认/待重载，不声称全部窗口已同步。宿主记录最近检查摘要、最近合法通知段与错误，诊断查询也触发检查，允许显式重试而无需发送测试通知。发送前须先检查最新值，成功关闭通知后不能按旧缓存继续入队；已进入系统通知平台的通知不保证撤回。

当前 notifications::Settings 将 disabled/silent 和任务 muted/after_check/task_categories 混放，persist_notification_state 从缓存整份写出。目标将全局偏好更新改走 SettingsStore 的字段操作，任务策略只写任务业务状态；宿主重载不把旧全局缓存写回 config。保存成功但宿主采用失败不回滚 config，保存草稿已提交完成、采用失败的诊断持续可见，也不重启 PTY。

恢复偏好默认只移除相应覆盖，不删除用户内容、预设或项目目录；涉及项目/预设删除另有明确操作和范围确认。清缓存只作用 cache；重置 UI 记忆只作用 ui-state；任务和恢复记录由原业务管理。

## 7. 重构范围与明确移除项

本次可直接重新定义 Config/Project/LaunchSpec，拆分持久设置、用户内容、UI 记忆及启动身份；删除现有“完整 Config 全量序列化覆盖”、项目文件自动加载/回写、通知独立全局偏好文件等重复路径。

不做旧 config.toml 解析、`.devtabs.toml` 转换、数据自动搬运、历史版本重命名映射、多格式共存与兼容字段。新格式测试使用隔离目录与新夹具；现有个人数据是否手工保留属于使用者操作，不允许实现阶段默默删除真实用户内容。

允许有明确理由地改变默认键位或字段语义，但要记录为“有意变化”，补新行为测试；不能用“不兼容”解释便签丢失、保存错项目、输入粘键、后台任务误停等业务回归。

### 8.3 新增测试

1. 配置解析、缺失/false/空集合/显式默认、继承来源、路径与重复项目、单根 schema；证明没有项目隐式第二来源。

3. 设置导航、鼠标/键盘、窄窗口、中文/英文、深浅主题；保存全部草稿、切分类、取消预览、恢复本页、关闭未保存状态。

5. 编辑便签/书签与更新最近/浮层后 config 字节不变；UserDataStore 并发变更不丢内容；恢复默认/清缓存不碰用户内容或任务唯一状态。
6. 只读浏览设置不写文件、不启动进程；Hooks 等立即操作明确独立于草稿取消；现有未保存编辑器和活跃 Agent 不被设置重载打断。
7. 快捷键功能测试和生产键位审计按 docs/52 完成；运行时身份不进入 config 或预设。

### 8.4 判定标准

使用全新数据目录重新运行基线业务套件及新增测试，记录有意变化与原因。自动测试、UI 渲染、Windows 真机外部热键/输入法/已安装 Agent 分别记录；依赖真实环境或显式标记 ignore 的测试不能当作已通过，也不默认对真实外部配置运行安装测试。

升级后必须证明：**新设置功能可用，原业务能力仍有测试覆盖，允许改变的只是明确批准的接口和行为，而非丢掉功能。** 配置格式不兼容不需要迁移测试，新的保存/故障/并发路径需要完整测试。

## 9. 实施依赖与范围

1. 先完成现状字段/入口基线和新配置模型，所有字段确定唯一所有者。
2. 实现配置服务、用户内容/UI 记忆存储及新格式夹具，统一 CLI、宿主和业务读取，直接移除重复来源。
3. 实现快捷键核心并接入同一配置服务，完成输入保真测试。
4. 完成设置界面，接入已有项目表单和新设置项，统一菜单/提示；运行完整改后测试和真机验证。

设置中心是对已有能力的统一入口，不因缺少控件而缩小功能，也不因 HTML 有控件就制造新需求。新开关、额外文件和抽象必须能回答“对应哪个已确定的用户行为、由谁写、为何不能使用已有模型”。

实施约定：总览就地排序、筛选、详情/统计开关和拖动比例仅改变当前视图；文件侧栏就地宽度、比例、跟随、紧凑和过滤同样仅改变当前视图。需要持久默认时使用设置中心的对应字段，收藏仍是明确持久操作。折叠记忆和最近打开只写 ui-state。不得由临时视图更新反向覆盖设置默认。

docs/53 负责共同草稿、保存与重载时机；docs/52 负责命令、上下文与输入路由。快捷键管理嵌入后统一使用外层保存全部，不额外建立独立落盘事务。复焦及显式重载遵循 §6.4。
