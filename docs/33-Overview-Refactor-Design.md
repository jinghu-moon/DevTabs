# 总览界面重构设计

状态：阶段 0–6 的代码与自动化验证已完成，独立 Release 产物交付；真机 UI 待用户验收。实现结果、性能口径、测试日志与边界见 [34-Overview-Refactor-Verification](34-Overview-Refactor-Verification.md)。本文保留设计依据，以下补充说明以实际交付行为为准。

## 1. 目标与依据

总览要帮助用户完成三个连续动作：找到项目、想起工作上下文、确认并执行正确的启动方式。

以老项目的信息结构为基础，以新 HTML 整理层级，接入本项目现有 Agent + Debug、会话宿主、恢复登记、预设与国际化能力。优先复用已有实现，允许重构状态和配置，不为开发期格式保留多余兼容层。

参考材料：

- [新总览 HTML 原型](../refer/DevTabs%20总览界面新设计.html)：默认三栏、对齐项目行、启动摘要、分隔线拖动及鼠标交互。
- [老项目总览](../refer/DevTabs/src/ui.rs)：`draw`、`compact_line`、`card_lines`、`draw_detail`、`summary_line`、`stats_lines`、`conversation_lines` 和 `on_mouse`。
- [老项目项目模型](../refer/DevTabs/src/items.rs)：`home_tool` 与临时 `tool`、会话选择、勾选顺序、恢复启动方式。
- [老项目详情采集](../refer/DevTabs/src/preview.rs)：最近提交、12 周趋势和最近对话。
- [现有总览](25-Project-Overview-Workspace.md)、[功能对标](27-Reference-Feature-Parity.md)：保留已有业务边界与工作区身份管理。
- [工作区界面规范](32-Workspace-Chrome.md)：复用主题、焦点、弹层与文本处理规则。总览的“启动摘要 + 操作提示”是两种信息，不受工作区单行底栏约束。

### 1.1 当前问题及实际原因

| 现状 | 原因 | 本次处理 |
| --- | --- | --- |
| 宽屏只显示占满窗口的项目列表 | `Overview::new` 默认关闭 `show_detail` 与 `show_stats` | 初次使用按宽度默认展示详情/概况 |
| 项目行像彩色路径清单 | 名称、分支和改动直接拼接，缺少列对齐和主次 | 使用共享列宽算法及语义颜色 |
| 找不到上次工作上下文 | 最近对话主要在 F9 历史弹窗中 | 当前准备续接的会话直接进入详情 |
| 详情类似诊断报表 | 常态展示内部工作区 ID、PID、shell/命令等信息 | 常态只展示影响启动决策的信息；诊断移入操作菜单 |
| 统计开启后挤走更重要的详情 | 两栏布局优先统计，两个面板共用滚动状态 | 默认详情优先，每栏独立视口和滚动状态 |
| 大量空白与底部快捷键堆积 | 顶部预留四行、底部五行，缺少任务摘要 | 顶部最多两行，底部两行，F1 展开完整帮助 |
| 新项目几乎都归入“更早/未打开” | 当前时间分组主要依赖本工具的 `last_opened` | 标注时间来源，异步补充已知 Agent 历史时间 |

### 1.2 必须保留的既有能力

项目搜索、收藏、便签、根目录管理、新建项目、项目设置、项目内配置、额外终端、主题和语言、预设保存/套用/调整、有序批量启动、原生历史选择器、指定会话、`--fresh`、后台工作区复用、多实例、恢复登记、失败重试、`--last` 和窗口目标均保留。

开发期允许调整内部模型和配置字段，但 UI 改版不能通过删除既有能力来简化实现。

## 2. 已确定的产品决策

1. 宽屏默认三栏：项目、详情、概况；中等宽度默认项目与详情；极窄窗口使用项目列表加显式详情弹窗。
2. 当前项目、勾选队列、悬停目标和键盘焦点分别管理。悬停不改变当前项目、不替换详情、不抢焦点。
3. Enter 打开当前项目；Ctrl+Enter 按顺序启动已选队列；两者不随是否勾选而改变含义。
4. 普通单击选中并更新详情，双击打开；编号/勾选区只切换勾选，不触发双击启动。
5. 临时 Agent/会话/终端组合调整只影响本次启动草稿。F4 才保存项目默认设置。
6. Agent 默认值决定 Agent 筛选归属；临时切换 Agent 不导致项目突然从列表消失。
7. “仅 Agent”表示只创建 Agent，不创建隐藏或折叠的 Debug；额外命名终端需要明确选择。
8. “加入全部待恢复”生成可审阅队列，不立即创建进程；Ctrl+Enter 才执行恢复。
9. 运行状态依据宿主事实；最近有输出、历史文件更新不等于 Agent 正在思考。
10. 默认无呼吸动画、无自动换栏宽、无悬停磁盘扫描、无选中文字即自动覆盖剪贴板。

HTML 是交互参考，存在演示数据、故意失败逻辑和键位说明与实现不一致等情况，以本文为准。

## 3. 布局与响应式规则

### 3.1 页面结构

```text
DevTabs    / 搜索项目       全部 18  运行中 2  有改动 12  待恢复 2 …    排序 最近
┌ 项目 ─────────────────┐ ┌ 详情 ───────────────────┐ ┌ 概况 ───────────┐
│ ▾ 待恢复 2   [加入全部]│ │ ■ 项目名称               │ │ 源码 / 磁盘     │
│ 1 ■ new-project codex │ │ 路径、分支、Git 摘要      │ │ 语言占比条      │
│ ▾ 本周 4              │ │ 下一步                   │ │ 最大目录横条    │
│   ■ SnapClip    codex │ │ 打开方式                 │ │ 12 周提交趋势   │
│ …                     │ │ 改动文件                 │ │ …               │
│                       │ │ 最近对话                 │ │                 │
│                       │ │ 最近提交                 │ │                 │
└───────────────────────┘ └─────────────────────────┘ └─────────────────┘
将打开 2 项  [1 SnapClip · Codex · 续接 · Agent+Debug] [2 …]       新窗口
↑↓ 移动  Space 勾选  Enter 打开当前  Ctrl+Enter 启动已选  F1 帮助
```

示意图不表示按像素实现；实际尺寸统一为终端字符格，CJK/emoji 使用显示宽度计算。

### 3.2 宽度分级

以页面可用正文宽度 W 判定。下表为初始实现参数，后续依据真机反馈调整常量，不依赖字体像素。

| W | 默认正文 | 规则 |
| --- | --- | --- |
| ≥ 160 列 | 项目 / 详情 / 概况 | 初始约 38% / 38% / 24%，两条分隔线各占 1 列 |
| 104–159 列 | 项目 / 详情 | 初始约 44% / 56%，F8 显式打开概况弹窗 |
| 60–103 列 | 项目 | F10 打开详情弹窗；单击只选中，不自动打开弹窗 |
| < 60 列或 < 10 行 | 最小界面 | 提示扩大窗口；保留搜索退出能力，不绘制失效命中区 |

三栏最小宽度为项目 44、详情 60、概况 30；两栏为项目 42、详情 60。边框和内部留白计入面板宽度。计算后达不到最小值则降级，不能靠截断把三栏硬塞进去。

用户主动隐藏详情/概况的偏好可持久化；首次进入才使用默认可见规则。窄屏自动隐藏不是用户偏好，不反写配置。中等宽度保留详情优先；用户主动关闭详情时可选择展示项目与概况。

### 3.3 高度、留白与缩放

- 顶部常态一行；搜索和筛选无法同时放下时使用两行，低优先级筛选进入“更多”。
- 底部一行启动摘要、一行上下文提示。高度 10–15 行时将启动摘要收为可展开入口，优先保留可操作正文。
- 面板边框内横向留 1 格；详情/概况上下各留 1 行。项目列表避免每行额外空行。
- 中间内容自然自上向下排列，最近提交不固定到屏幕底部。
- 列表、详情、概况分别滚动并显示可拖拽滚动条；滚动条长度按实际换行后的行数计算。
- 调整窗口或栏宽保留当前项目、列表锚点、详情阅读位置和勾选顺序。

### 3.4 分隔线拖动

鼠标按住边框拖动调整相邻栏宽，有悬停提示及拖动强调色。拖动期间捕获手势，跨出面板仍处理释放；Esc、失焦或窗口缩放取消并恢复拖动前尺寸。

释放后保存总览独立的列宽偏好，不与工作区文件树宽度混用。配置在后台合并/原子写入；失败保留本次可见尺寸并提示未保存。重新进入窄屏再返回宽屏恢复偏好，不保存退化后的临时宽度。无宽度动画。

## 4. 项目列表

### 4.1 项目行与颜色

宽度足够时使用单行对齐列：`勾选编号 | 项目色块 | 名称 | Agent | Git | 状态/时间`。列宽在本次布局中共享，不逐行独立拼接。名称优先，长分支中间截断，完整路径/分支可通过提示或详情查看。

列表窄时改为两行：第一行保留编号、色块、名称、Agent 与状态/时间；第二行放分支、Git、便签摘要。更窄时依次移除便签摘要和次要 Git 数据，始终保留名称与选择入口。

- 项目名称用正文色；项目配置色只用于小色块、详情标题标记及相应启动条标记。
- 当前项使用局部背景和左侧标记，失焦时减弱背景但保留定位。
- 已选项显示顺序编号，不以全行高亮冒充键盘焦点。
- Codex、Claude 使用稳定工具色；Shell 使用中性色。
- 改动黄色，冲突红色，干净状态淡绿色；保留 `M`、`!`、`↑`、`↓` 等字符语义。
- 旧项目可弱化，但当前项、已选项、运行中和失败项保持正常可读性。浅色主题单独校验。
- 搜索命中着重显示；不修改项目名原值，不把路径中的控制字符直接输出到终端。

### 4.2 分组、时间与来源

顺序为待恢复、收藏、本周、本月、更早、无使用记录，每个项目只在主列表出现一次，收藏仍显示星标。分组标题有数量并可折叠；待恢复标题包含“加入全部待恢复”操作。

时间默认显示“最近使用”，按已确认的最近 DevTabs 启动时间与已知 Agent 会话时间取较新值。提示中注明来源；不用项目目录 mtime 或 Git 提交时间伪装使用时间。

历史索引未完成时显示未知/加载中；无记录显示 `—`，不显示误导性的“0 天前”。历史结果按批次合并、稳定重排，不随着每个文件返回就移动正在操作的行。键盘和鼠标锁定的当前项目身份保持不变。

### 4.3 筛选与排序

保留全部、运行中、有改动、待恢复、Codex、Claude；非默认 Agent（如 Shell）在更多筛选中提供入口。每个筛选标签显示数量，全部数量只显示一次。当前筛选使用下划线与文字强调；无效或加载中的数量显示 `—`，不冒充 0。

数量基于搜索结果、应用筛选之前的集合，标签对应各自条件；选择身份和已选队列不因筛选而丢失。分组标题不计项目数量。临时 Agent 草稿不影响默认 Agent 筛选归属。

保留最近使用、名称、源码大小、提交活跃度排序。大小/活跃度由后台数据更新；缺失值单独标识，并以路径稳定排序破除相等值。搜索和排序后按项目键保留当前项；确实不可见时选首个可见项目并更新详情。

## 5. 详情面板

### 5.1 信息顺序

| 区块 | 默认内容 | 展开/操作 |
| --- | --- | --- |
| 项目标题 | 色块、名称、完整路径的可读截断 | 显式复制路径、打开文件夹、项目菜单 |
| Git 摘要 | 分支、改动/冲突、领先/落后 | 查看改动列表；非 Git、失败和加载分别呈现 |
| 下一步 | 本地项目便签，最多 3 行摘要 | F3 或点击编辑，保存失败保留输入 |
| 打开方式 | Agent、会话、终端组合、布局、窗口目标、已有工作区处理 | 点击对应控件或 Alt+Enter 打开完整选项 |
| 改动文件 | 前 5 项，状态及相对路径 | 展开完整有界列表；打开文件查看器 |
| 最近对话 | 当前选择对应的最新消息摘要 | 展开全文、F9 换会话 |
| 最近提交 | 最近 3 条，短 hash 与标题 | 展开至后台返回的有限条数 |

常态不展示 PID、内部工作区 ID、协议版本和原始参数数组；项目菜单的诊断详情保留这些能力。

### 5.2 会话与最近对话

Agent、会话选择器、最近对话和启动摘要必须指向同一个启动草稿，禁止“展示 Codex 对话，实际启动 Claude”的分叉。

会话状态明确区分：新会话、自动续接最近、指定会话、Agent 原生选择器。历史未读完、格式不支持或权限失败时显示原因，不把未知当成“没有历史”。已知没有历史时说明将新建；不能保证自动恢复时显示“尝试续接”，不能声称已精确定位。

默认最多展示最近 2 段消息、合计 10 行正文。长用户消息保留开头，长 AI 消息可保留结尾并标注截断；展开后在详情内滚动，F9 提供会话列表及完整有界读取入口。原生历史选择器继续可用。

直接复用现有 Markdown 渲染能力，为摘要禁用图片加载和复杂图形计算；按摘要长度及可见宽度有界排版，不为总览创建第二套 Markdown 引擎。角色、标题、代码及列表应可辨认，不能只把 Markdown 源码原样堆上去。消息原文不翻译。

历史读取沿用已知格式适配器和边界；摘要不得因为裁剪尾部读不到上下文就把碎片当成完整消息。切换 Agent 使旧 Agent 的预览请求失效。

### 5.3 文件与路径操作

改动文件单击选中，Enter 或显式“查看”打开只读文件查看器。查看器复用现有预览、异步读取及路径处理能力，不启动 Agent、不开启 PTY；必要时将 Sidebar 的文件预览视图提取供总览和工作区共同使用。

路径/行号链接使用显式操作或 Ctrl+单击；Windows 盘符冒号不能按普通 `split(':')` 解析。仅识别可解析路径，远程 URL 不作本地文件处理。不存在文件、目录、二进制和无权限按既有预览规则提示。返回总览保留项目、滚动与队列。

## 6. 启动草稿与业务语义

### 6.1 草稿和持久设置

保留现有有效配置解析规则，在其结果上覆盖临时草稿。统一计算得到实际启动 Options；列表、详情、摘要、预设和执行均使用这一结果，不分别拼装参数。

草稿包含 Agent、会话策略、终端组合、布局、Debug 命令、额外终端、参数及窗口目标。切换 Agent 清除不匹配的指定会话；保留该项目的其他临时选项。刷新配置不默默丢弃已修改草稿，显示默认已变化并允许重置。

F4 保存默认值；Alt+Enter 调整本次；Ctrl+S 保存有序组合预设。项目默认 Agent 与临时 Agent 分开，不新增第二套项目配置存储。

### 6.2 终端组合与布局分离

| 选择 | 创建行为 | 显示行为 |
| --- | --- | --- |
| 仅 Agent | 只创建 Agent，不创建 Debug 或额外终端 | 单 Agent 工作区，保留侧边栏/文件预览 |
| Agent + Debug | 创建 Agent 与 Debug | 布局决定分屏、悬浮或标签页 |
| 自定义 | 创建 Agent、Debug 与全部配置的额外终端；在完整选项中增删额外项 | 完整选项显示终端名称、命令、目录 |

配置含额外终端时默认使用完整配置并标记“自定义”，不能因新的简化控件静默丢弃。切换“仅 Agent”只改草稿，默认设置原样保留。该字段需贯穿 CLI/Options、host、预设、恢复和工作区前端，移除 UI/宿主中“至少两个终端”的硬编码。

只隐藏、折叠 Debug 不算实现“仅 Agent”。单终端模式下 Debug 入口应禁用并解释原因；显式添加 Debug 属于另一个动作，不能点击按钮就悄悄创建。

### 6.3 已有工作区与多实例

运行状态来自当前构建可访问的宿主；宿主查询失败显示未知/错误，不能标为空闲。单个项目已有多个实例时，详情显示实例数量并允许选择激活目标；不静默任意选一个。

普通“打开”优先激活匹配的已有工作区。草稿与已有工作区不一致时，明确显示“激活已有配置，临时参数不会应用”，并提供“按草稿另开实例”。不得暗中重启已有终端或修改其配置。

现有实例与待恢复登记可以同时存在。恢复登记按登记身份匹配，而非只按项目路径合并；同一路径的多个恢复实例不能被去重掉。

### 6.4 有序启动队列

底部摘要展示编号、项目、Agent、会话动作、终端组合及激活/恢复/新建行为。布局、窗口目标可在摘要展开项查看；不在窄空间里重复所有参数。

普通勾选按规范化项目键去重；恢复项按登记 ID 区分实例。可通过一个队列条目结构携带普通/恢复目标，不另建互不一致的“已选列表”。已选顺序是执行和新窗口编排顺序，焦点移动不改变顺序。

- Space、编号点击、中键切换勾选；Ctrl+点击切换，Shift+点击按可见项目范围追加，已存在项不重排。
- 拖动项目至底部加入队列，拖动队列条目调序；同时提供键盘前移/后移操作，不能只有鼠标能排序。
- 点击队列条目只定位/展开，不启动；删除按钮及 Delete（队列聚焦时）移除。
- 无勾选时摘要显示“Enter 将打开当前项目”及其实际行为；Ctrl+Enter 提示队列为空，不偷偷启动当前项目。
- 摘要放不下时显示“另有 N 项”，Enter 展开可滚动的队列面板；包含当前项目不可见的已选项。
- “加入全部待恢复”追加缺少的恢复项，不覆盖用户已勾选项；加入后可撤销最近一次队列编辑。
- 执行前冻结启动快照，启动进行中禁止改动该快照，仍可浏览项目；后续草稿调整用于下一次启动。

沿用 `Queued → Opening → Opened/Failed` 状态及 generation 检查。底部显示简短结果，完整结果面板展示逐项状态、具体失败原因和重试入口。R 在失败结果面板中只重试失败项；成功项不重复创建。宿主已创建但前端打开失败时重试必须复用该工作区。

多项目批量启动不能连续抢当前前端；新窗口目标沿用既有批次窗口分组。当前视图打开与批量 WT 编排的区别必须在摘要中说明。

## 7. 概况面板

### 7.1 展示口径

| 内容 | 表达 | 数据说明 |
| --- | --- | --- |
| 源码 | 人类可读体积、文件数量 | 遵循忽略和已有源码识别规则 |
| 磁盘（逻辑体积） | 文件长度合计、文件数量 | 包含构建产物；不是磁盘分配空间 |
| 语言 | 占比条 + 前 5 项图例 | 按源码字节数，不伪装为代码行数；小项合并为其他 |
| 最大目录 | 前 5 项名称、体积、横条 | 第一层目录汇总；比例尺保持统一 |
| 12 周提交 | 12 根柱、总数、最近提交时间 | 从旧到新；零提交和加载失败不同 |

常见构建目录使用琥珀色，仅提示“构建/依赖目录”；不能根据目录名承诺可以安全删除，本次不增加删除按钮。

### 7.2 加载与刷新

概况默认显示已有缓存，并注明必要的更新时间/刷新中。无缓存时按来源分别显示加载状态，不让磁盘扫描阻塞语言、Git 或最近对话。

保留现有源码/Git 10 分钟、磁盘逻辑体积 12 小时、部分结果短 TTL 的策略。取消任务不覆盖有效缓存；部分统计显示“至少/部分结果”，不显示精确总量。F5 显式失效并刷新，不在 UI 帧内执行扫描。

在三栏可见时，当前项目稳定 200 ms 后请求无缓存的低成本详情；完整磁盘统计需稳定 500 ms 后启动。快速经过项目只显示已有缓存，停止后处理最新目标。F8 弹窗为显式请求，可立即发起。

### 8.2 鼠标与命中区域

鼠标命中区由当帧布局与组件可见区域产生；隐藏按钮、弹层覆盖区、截断溢出和面板空白不能复用旧命中区。中文按钮按终端格宽计算。

- 仅行主体的连续两次点击同一项目才触发双击打开；编号、工具、菜单、拖拽和跨项目点击均不计入双击。
- 滚轮只作用于鼠标所在面板，详情/概况滚动不改变当前项目。
- 右键选中指向项目并打开菜单：打开、选择 Agent、会话策略、另开实例、启动选项、收藏、便签、设置、打开文件夹、复制路径。
- 悬停延迟 400 ms 显示提示，提示放入底部上下文行；不移动项目或替换详情。
- 拖动超过 2 格才开始，原始按下目标捕获至释放。拖拽、弹层和滚动条优先于项目双击。
- Esc、失焦、窗口缩放取消活动手势并清除捕获；菜单执行后的释放事件不穿透。
- 文本选择后的复制由显式 Ctrl+C/菜单触发，复制失败显示错误。保留终端原生 Shift 选择路径，不宣称所有终端的原生选择均可被应用检测。

### 8.3 焦点及弹层

同一时刻仅一个区域获得键盘焦点和强调边框；选择项是独立概念。打开弹窗记录来源焦点，关闭时恢复；来源不可见时回到项目列表。

绘制顺序：页面背景 → 面板内容与边框 → 启动摘要/提示 → 临时菜单与查看器 → 确认对话框。顶层弹窗独占输入；边框不被底层文字和宽字符穿过，弹层外点击取消的事件也不能同时触发下层项目。

## 9. 实现结构与复用边界

| 位置 | 调整职责 |
| --- | --- |
| `src/overview/model.rs` | 项目身份、有序队列、临时草稿、分组/排序规则和启动快照 |
| `src/overview.rs` | 焦点、事件、命令执行、后台结果合并与状态协调 |
| `src/overview/view.rs` | 布局、按格宽列分配、可见内容、命中区域；按规模拆出列表/详情视图即可 |
| `src/overview/worker.rs` | 有界详情请求、取消、缓存调度；启动和持久化队列保持独立 |
| `src/overview/history.rs` | 复用已有格式解析，为默认详情提供轻量摘要与时间索引 |
| `src/overview/stats.rs` | 保留统计及缓存算法，拆分必要的请求粒度，补齐时间/加载元数据 |
| `src/launch.rs`、host、protocol、recovery | 贯穿真实终端组合；支持一个 Agent 的工作区、恢复及预设 |
| `src/config.rs`、项目配置 | 持久列宽、可见偏好和明确的终端组合；默认设置不被草稿覆盖 |
| `src/i18n/*.json`、`appearance.rs` | 新文案和语义样式沿用既有引擎 |

不照搬老项目的大型 `ui.rs`、无界线程和活动状态猜测。保留一个业务模型、一个启动执行通道、一套 Markdown 引擎、一套国际化资源。仅在现有模块确实承载不了职责时拆文件，不引入通用 UI 框架或新的状态管理依赖。

请求至少按“项目键、Agent、会话选择、请求类型、generation”验证结果。列表索引不能作为异步身份；切换项目、Agent、会话或刷新后，旧结果不得覆盖新详情。

同一项目的历史、Git 和磁盘请求各自可取消；关闭概况不能取消最近对话，打开 F9 不能让后台概况结果写入历史弹窗。每栏有独立的滚动状态与缓存键，主题/语言切换只使相应排版失效，不重新扫描文件。

## 10. 性能与资源约束

- UI 帧和事件处理不执行文件遍历、同步 Git、历史索引、宿主 RPC 或配置写入。
- 列表只绘制可见项目行，按正文宽度和密度缓存共享列布局；选择移动不重新解析所有 Markdown。
- 默认对话渲染有条数、字节和行数上限。历史继续沿用头 64 KiB/尾 256 KiB、条目与文件数量等现有限制；如需调整，记录原因及基准。
- 后台请求有界、合并同目标请求、只保留最新选择；禁止每次悬停生成新线程。
- 按来源和版本维护有限内存缓存，不能为每个项目长期保存完整对话/Markdown 渲染树。优先沿用现有缓存容量；新增历史摘要缓存初始上限 32 个项目/Agent 组合，超限淘汰最久未使用项。
- 队列/焦点/悬停变化不得触发磁盘统计；进度标记只在状态改变时重绘，不以动画驱动整页刷新。
- 记录总览帧时间、输入至绘制延迟、详情缓存命中、取消/丢弃结果数量、统计耗时和读取字节数，复用现有 perf 设施。

性能验收采用固定 fixture 和同一 Release 配置，对比重构前后。缓存就绪下，目标是 100 项目普通导航端到端绘制 P95 ≤ 16 ms；1,000 项目无崩溃、无无界增长，并报告实际 P95。目标是预算，不是当前已测结论。磁盘扫描单独计时，不将后台耗时混成 UI 帧时延。

若指标退化，先确定热点并优化；不能通过静默关闭默认详情或删除最近对话规避验收。无收益的性能改动回退，保留测试与测量记录。

## 12. 测试与验收矩阵

### 12.1 固定数据集

覆盖 0、1、20、100、1,000 项目，中英文、emoji、相同文件夹名不同路径、超长名称/分支、非 Git、无权限/已删除目录、无历史/未知格式/损坏历史、配置错误、宿主不可达、同项目多个实例、多条待恢复登记、额外终端与仅 Agent。

尺寸至少包含 59×9、60×10、80×24、103×30、104×30、140×36、159×40、160×40、200×50、280×65；中英文和浅/深主题都验证。临界宽度、宽字符及语言切换后命中区域必须正确。

### 12.2 自动化重点

| 方面 | 必测行为 |
| --- | --- |
| 默认布局 | 无需 F8/F10 就显示适当栏目；用户隐藏偏好与自动降级独立 |

| 列表身份 | 搜索、排序、分组、后台更新后当前项目与队列身份稳定 |
| 详情 | 角色与 Markdown 摘要、展开、便签保存失败、文件查看返回后状态保留 |
| 异步 | 快速 A→B→A、切 Agent/会话、关闭概况、刷新时迟到结果不能串页 |
| 草稿 | 默认/临时分离，详情/摘要/执行选项完全一致；切 Agent 清除错误会话 ID |
| 启动 | Enter 只打开当前；Ctrl+Enter 只启动队列；当前窗口批量行为明确 |
| 仅 Agent | 只有一个 PTY/进程；侧栏/预览/放大/退出正常；恢复/预设仍为单终端 |
| 额外终端 | 简化组合控件不静默抹去配置；自定义会话名称/目录/命令保持 |
| 实例/恢复 | 多实例选择，路径相同的恢复项不丢失，加入全部不覆盖原队列 |
| 结果/重试 | 冻结快照、重复点击、旧 generation、前端失败、成功项不重复启动 |
| 鼠标 | 单击不启动；编号/Agent 不误双击；隐藏命中区、完整手势、右键/弹窗不穿透 |

| 性能 | 导航不扫描磁盘，历史/统计有界取消，缓存命中及可见行渲染验证 |
| 既有功能 | 收藏、预设、设置合并、原生历史、CLI、恢复、host 构建隔离和工作区全部回归 |

缓冲区快照用于核验布局与样式，行为测试核验状态、身份和真实输入路由，不能只断言文案存在或更新快照掩盖回归。ConPTY 使用隔离 shell、临时数据目录与固定 fixture，禁用真实 WT/真实 Agent 启动。

实施阶段已记录升级前后的回归与 Release 基准，实测结果见 34 文档。验证命令：

```powershell
cargo test --locked --target-dir target/perf --lib --test overview --test reference_parity --test i18n -- --test-threads=1
cargo test --locked --target-dir target/perf --test pty_windows --test workspace_windows -- --test-threads=1
```

同一 target 的构建和测试顺序执行，避免 Windows 可执行文件锁冲突。真机验收由用户负责：看三栏信息是否可读、最近对话是否可辨认、双击和拖动是否自然、窄宽切换是否保留上下文。自动化结果不代替真机 UI 结论。

实际交互采用同一可搜索命令面板承载右键项目操作，不另建重复菜单。详情/概况使用 Alt+拖动选择可见文字、Ctrl+C 复制；普通点击仍用于控件与文件。选区存在时冻结该文字视口，Esc 或后续导航取消；没有选区时 Ctrl+C 复制当前项目路径。终端原生 Shift 选择是否上报由终端决定。

终端组合以最小明确模型落地：`agent-only` 为 1 个终端，`agent-debug` 为 2 个，`custom` 为 Agent + Debug + 所有已配置额外终端；本轮不增加“自定义但任意省略 Debug”开关。额外终端配置在切换组合后保留，只有选择 `custom` 才创建。新增额外项自动选用 `custom`。

自动化通过不表示真机 UI 已验收。字体、窗口目标、颜色感受、滚动和鼠标操作的最终体验由用户验证。完整测量与可运行路径见 34 文档。
