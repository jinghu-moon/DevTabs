状态：实施中；阶段 0、A、B、C 自动验证完成，D–E 待实施。创建：2026-11-12。依据：[37-Parallel-Agent-Workspace-Design.md](37-Parallel-Agent-Workspace-Design.md)，既有版本记录见 [38-Project-Pulse-and-Session-Navigation.md](38-Project-Pulse-and-Session-Navigation.md)，当前证据见 [40-Parallel-Agent-Workspace-Verification.md](40-Parallel-Agent-Workspace-Verification.md)。

本文是整个文档 37 的实施计划，覆盖 0–E 阶段、通知及每轮文件变化记录，不仅是一个通知子功能。任务按实际证据更新状态，不修改真实 Agent 配置或发送系统通知；历史构建的结果不替代实施当天基线。

## 1. 评审结论与实施范围

方案可以进入分阶段实施，需先把六个边界变成可测试契约：自动边界存在捕获窗口；Git 工作树与对象可能有表示差异；历史必须保留实际依赖内容；通知发送与 WT 激活分开验证；预算满有明确退化；fixture 与真机验收分开。具体结论已同步到文档 37 第 15 节，无需再建立另一份设计真相。

实施保留原生 Agent TUI、现有单任务、预览/编辑/图片、独立宿主与项目脉搏；直接重构过时 schema 和按下标推断角色的逻辑，不构建兼容适配层。任务隔离不保证外部端口/数据库隔离或最终合并无冲突。非 Git 单任务可记录变化，不自动建仓库、不假称具备 worktree 隔离。

DevTabs 不调用 AI 生成记忆、总结或任务分解。文件改动是范围内净变化或监听观察事实，不能归因为一定由 Agent 写入。可靠 Provider 事件只给出其实际含义，Stop 报告不能自动等同最终结束或验收通过。

## 2. TDD 执行约定

每个任务按小行为循环执行，不能先完成整个阶段实现，再集中补测：

1. **RED**：写一个可观察的用户行为或失败保护测试，运行并确认因为目标行为未实现而失败。新 API 尚不存在时只补能编译的最小声明/入口；单纯编译失败、环境缺 Git 或路径错误不算有效 RED。现有回归能暴露缺陷时直接复用。
2. **GREEN**：只实现让当前行为通过的最小代码，同时运行直接相邻回归。测试不能靠修改预期、删除断言、加 ignore 或吞错误变绿。
3. **REFACTOR**：保持绿色，去除下标角色、重复状态、无界队列和多余抽象；提炼复用点后重新运行相关测试。
4. **证据**：记录测试名、RED 的实际断言失败、GREEN/重构后的结果、命令和代码树指纹。没有实际运行结果就保持待实施，不能预填通过。

测试优先断言终端收到的字节、实际 cwd/文件内容、Git refs/index、稳定对象选择、磁盘记录和通知请求，而非私有函数调用次数。性能结构性断言可统计读写/对象数，避免仅镜像实现。普通样式/文案调整复用既有几何/国际化测试，不为每行代码建立测试。

### 2.1 测试隔离

- 使用临时目录、独立 `DEVTABS_HOME` / instance、隔离测试宿主及 shell fixture。禁止读取/改写真实 Agent 配置、项目 Git 状态、用户通知注册或杀死已有会话。
- Git fixture 配置本地 author、明确默认分支，关闭 fixture 内 hooks/signing，固定 EOL；特殊属性测试另建环境。用参数数组和 NUL 路径，不拼 shell。必要的 Git global/system 配置读取也需隔离，不能向真实配置写测试设置。
- ConPTY fixture 复用 `tests/workspace_windows.rs` 的独立可执行文件/防 WT 误启动方式。真实进程测试必须有截止时间与 RAII 清理，只清理已验证属于 fixture 的进程/目录。
- 纯状态使用可控时钟，I/O 竞态使用 barrier/可控读写点；不用几秒 sleep 期待某事件碰巧到达。真实 watcher 只断言最终可观察路径和错误传播，不固定 Windows 通知次数/顺序。
- 系统通知使用可替换的发送边界与模拟导航请求；COM/WinRT 适配的真实展示由用户验收。不要为测试创建完整虚拟文件系统/Provider 框架，仅为时钟、通知、特定故障点提供必要接缝。

### 2.2 证据与状态

每阶段记录在隔离的 `artifacts/<build-or-run>/parallel-workspace/`，至少包含：源码树指纹/dirty 清单、工具链与系统版本、命令/退出码、RED/GREEN 日志、机器与夹具参数、性能原始值及结论。目录为实施时创建的输出约定，当前不存在不代表缺失测试结果。

每个任务状态只有待实施、RED 已确认、GREEN、重构完成、等待真机、已验收；可以用任务 ID 关联外部日志，但不能仅勾选任务而无证据。自动化完成与用户真机通过分栏记录，提交/推送遵循用户最新授权：每完成一个阶段提交并推送。优化仅在正确性不退化且同条件数据有收益时保留，回退只涉及该次优化的已确认改动，不重置整个脏工作区。

```mermaid

    A --> B[B 同屏与输入]

```

测试驱动的纯逻辑可提前编写，但生产集成遵循依赖顺序，不让未实现入口出现在产品中。0–C 是首个可使用的隔离同屏体验；D/E 是已批准范围中的后续交付，不能在 0–C 完成后宣称整份方案完成。

首条主路径：A 已运行且有 staged/unstaged/untracked 与草稿 → 从 A 临时创建 B → B 从冻结提交创建独立 worktree → 同一个终端显示 A/B → 分别输入后只写到选定 Agent → 回总览再进入原进程不变。先用双 shell 证明机制，再由用户用真实 Agent 验收。

### 4.1 记录模式和完整性

不把正确性压成一个 `complete` 布尔值。至少分开记录：记录模式、路径覆盖是否完整、前/后内容是否可用、捕获窗口/边界可信度、历史内容是否已封存；状态可以采用枚举与原因集合，无需新增复杂类型框架。

- 自动开始事件到达时前态未就绪：允许开始有界采集，但标观察区间/晚起点，不宣称这一轮完整。manual prepare 基线就绪后再开始操作，可保证已采范围前态，但外部进程并发仍非全仓原子快照。
- Stop 继续与最终结束各版本复用逻辑轮的原基线；重新采集的后态各自封存。无法证明 turn 关联时不合并成同一轮。
- Git 表示首版支持经测试的普通文本/二进制和内建换行处理。特殊过滤器、LFS、自定义编码等先报告范围限制或显式限定快照，不执行未验证的外部 filter 来制造“完整支持”。
- 正常历史必须有差异实际依赖内容；对象在归档前失效则部分/不可用。不能以用户仓库 GC 后读取失败为正常“已归档完整历史”的行为。
- 非 Git watcher 无事件显示“没有观察到文件事件”；溢出/间隙标不完整。限定快照才比较所选范围净变化。二者不能比较相同行数或共用“完整零改动”。

### 4.2 第一轮预算默认值

以下是实现起点，可配置且要经过测量调整，不是已测性能或资源保证。配额在分配/读入前检查，拒绝/截断必须携带原因。

| 对象 | 初始默认值 | 达到上限时 |
| --- | --- | --- |
| 单文件内容快照 | 8 MiB | 保存可用元信息，旧内容不可用则不生成伪 diff |
| 单轮额外内容 / 单任务 / 全局存储 | 128 MiB / 512 MiB / 2 GiB | 先回收无引用过期轮次；仍满则部分/停采，不删除查看中或采集中内容 |
| 每任务保留历史 | 最近 20 个逻辑轮；报告版本也计字节预算 | 最老可回收轮次先失效，活跃引用占满则停止新增而非无限增长 |
| 单次候选/路径输出 | 200,000 路径、64 MiB 输出，任一先到 | 明确路径不完整，不能推导完整零差异 |
| 采集总截止时间 | 每侧 5 秒；Git 子命令共享该侧剩余预算 | 终止所属子进程，保留已知范围并标部分；不续跑无限后台任务 |
| Git 并发 / 文件采集 worker | 各全局最多 2；同仓库写操作串行 | 有界排队，按 task 合并可替代读请求；创建/清理意图不可丢弃 |
| 等待采集请求 / watcher 路径候选 | 全局 64 / 每任务 4,096 | 显示背压/监听遗漏；差异模式核对路径，观察模式标不完整 |
| Hook 载荷 / 总执行预算 | 1 MiB / 2 秒，且不超过 Provider 事件限制 | 快速退出，不阻断 Agent；记录有限拒绝原因，不进入现有 32 MiB/15 秒普通 RPC 等待路径 |
| Toast 发送队列 / 存活对象 | 32 / 64，保留最多 10 分钟 | 有界合并/释放并记录原因；未读结果保留，不能把释放视为已读 |
| 普通结束通知合并窗口 | 1 秒 | 同窗口按任务汇总；授权/失败单独保留，不用于延时推断最终结束 |
| 本地结果摘要 | 最多 160 字符，默认不进系统通知 | 过滤控制字符，不记录完整正文或秘密 |

8 MiB 单文件上限不意味着要在内存中同时持有所有候选；流式读写、差异按需，具体内存峰值在 D15 测量。关闭通知不停止 Agent 状态或文件记录。上述参数的边界值用小配额 fixture 等价测试，不为默认 2 GiB 限额在普通回归写入数 GiB。

## 5. 阶段 0：基线与测试地基

## 9. 阶段 D：文件记录、审阅与通知

### 9.1 先完成可独立验证的文件审阅

## 12. 命令与回归节奏

阶段开始和结束执行完整门禁；单个 RED/GREEN 循环只运行目标测试与相关回归，避免每个小修改重跑全套。下面前三条是当前已有命令，执行阶段记录实际退出码：

```powershell
cargo test --workspace --target-dir target/perf -- --test-threads=1
cargo clippy --workspace --all-targets --target-dir target/i18n-check -- -D warnings
cargo fmt --all --check
```

目标 suite 创建后，按测试名运行，示例并非现在就存在的测试入口：

```powershell
# A04 创建 suite 后：双 shell/任务路由
cargo test --test parallel_workspace_windows --target-dir target/perf -- --test-threads=1

# D03/D04 创建 suite 后：本轮 Git 真值和增量行为
cargo test --test round_git --target-dir target/perf -- --test-threads=1

# D13 创建 suite 后：纯时钟策略，不弹真实系统通知
cargo test --test notification_policy --target-dir target/perf -- --test-threads=1
```

发布/性能构建与原有 ignore 性能入口沿用独立输出目录：

```powershell
cargo build --release --target-dir target/parallel-release

# 已有 tests/performance.rs 的显式负载；输出置于隔离证据目录
```

仅显式运行选定性能 ignore 测试，不把全部 `--ignored` 当完整验证：其他 ignore 可能有不同环境前提。新性能 suite 的样本参数、输出 schema 和显式执行命令在 D15 加入后记录，不能编写不存在的命令并宣称运行成功。

## 13. 性能与优化保留规则

先定义正确结果真值，再测同机同构建配置的冷/暖样本；报告 p50/p95、峰值和完整性/模式，保留原始样本，不只报告最佳值。既有单 Agent 与新增 1/2/4 Agent 使用同等工作负载；新功能无法在旧版测量时用功能正确的简单实现作为优化前基线，并与旧版公共路径开销分别比较。

| 负载 | 观测 | 通过依据 |
| --- | --- | --- |
| 双 shell，一边连续输出，另一边交替输入 | 输入至本地写入、队列长度、帧耗时 | 接收字节真值正确、无饥饿/无界增长；不把模型延迟算入 |
| 4 任务、2 可见，反复切换/放大 | CPU/内存/图片输出、PID/草稿 | 身份不变、隐藏图片无无谓重传，不丢草稿 |
| 100k 干净受跟踪＋5 dirty＋2 untracked | 基线时间、额外内容读写/对象数 | 不新增 100k 文件内容副本，结果与已知内容一致；Git 状态成本单列 |
| 起点大量 dirty/untracked | 超限原因、存储峰值、UI 响应 | 部分可解释、守预算，不假完整或阻塞输入 |
| 非 Git 默认观察 vs 限定 src/tests 快照 | watcher 事件、快照 I/O、采集范围 | 按不同能力分别报告，不能将不存前态当同精度提速 |
| 连续 20+ 轮、相同内容及分支/GC 变化 | 归档读写、去重、淘汰/引用 | 保留历史可重建，清理不破坏正在查看内容 |
| 突发/重复/旧 hook 与多前端 | 接收至状态/通知、去重/拒绝、对象峰值 | 一次逻辑提醒、过期不覆盖，失败不阻塞输入 |

新功能公共热路径的初始回归阈值：相同负载 p95 连续两组测量均恶化超过 `max(基线的 20%, 1 ms)` 时阻止合入阶段成果并定位；这是排查阈值，不是统一帧率或硬实时保证。小于阈值但正确性/资源上界失败仍不通过。样本噪声超出收益时不声称优化有效，先修测量。
