# DevTabs 桌面端职责与配对发送设计

状态：概念稿，2026-11-13 更新。

Demo：[51-Desktop-Workspace-Demo.html](51-Desktop-Workspace-Demo.html)。它是离线单文件演示，只模拟配对、编辑、发送、排队和发送记录，不访问文件系统、不启动进程、不读取 Agent/终端、不发送真实消息。

## 1. 产品边界

DevTabs 桌面端只负责把用户写好的文字发送到指定软件的指定输入区域。它是一个“配对发送器”，不是终端模拟器、Agent 客户端、项目管理器、文件浏览器或 Debug 工具。

DevTabs 负责：

- 保存并选择配对：目标软件、目标范围和输入区域。
- 编辑待发送文字。
- 插入少量明确的文本片段，例如项目路径、文件路径或用户模板。
- 显式发送，或加入发送队列。
- 报告发送成功、失败、等待输入区域可用等连接事实。
- 保留本地发送记录，帮助用户确认“发给了谁、什么时候发的、发了什么摘要”。
- 在配对失效时明确报错，不伪造发送成功。

目标软件负责：

- 终端、Agent、Debug 和窗口渲染。
- 对话历史、上下文压缩、任务状态和任务完成判断。
- 文件树、文件预览、代码差异、Markdown 渲染和编辑。
- 权限、确认、执行结果、系统通知以及自身的会话恢复。

DevTabs 不读取目标软件内部内容来推测完成状态，也不复制目标软件的终端或 Agent 界面。发送成功只表示目标输入区域接受了文字，不能表示任务完成、命令执行成功或代码通过测试。

## 2. 人的操作逻辑

用户的实际思考顺序只有三步：

1. **发给谁**：选择 OpenAI Codex、Claude Code、PowerShell、VS Code 等已配对目标，并进一步确认项目、窗口或任务范围。
2. **发什么**：在中央编辑区写文字，可插入路径或模板；发送前仍由用户掌握内容。
3. **确认是否送达**：看到已发送、已排队或失败。目标软件接收后发生什么，由目标软件自己表达。

因此桌面端用“配对列表 → 发送编辑区 → 发送记录”作为主结构。它不显示 Agent 卡片、终端输出、文件改动表、项目统计或 Debug 面板，因为这些内容会让用户误以为 DevTabs 负责目标软件内部工作。

## 3. 界面结构

```text
DevTabs  配对发送工作台                                  [＋ 管理配对]
┌ 已配对的软件 ┐ ┌ 发送到指定软件                         ┐ ┌ 当前配对 ┐
│ ● Codex      │ │ OpenAI Codex · new-project             │ │ 软件     │
│   new-project│ │ [已配对 · Codex 当前输入区域]          │ │ 输入区域 │
│ ● Claude Code│ │                                        │ │ 连接状态 │
│   Yue-GPUI   │ │ 发送内容                               │ │ 使用逻辑 │
│ ● PowerShell │ │ ┌──────────────────────────────────┐   │ └──────────┘
│               │ │ │ 用户编辑的文字                   │   │
│ ＋ 新增配对   │ │ └──────────────────────────────────┘   │
└───────────────┘ │ [插入路径] [加入队列] [发送]          │
                  │ 发送记录：目标 / 时间 / 摘要 / 结果    │
                  └──────────────────────────────────────┘
```

左侧解决目标选择，中央解决文字编辑和发送，右侧解释当前配对。右侧可以隐藏，不改变发送目标。窄窗口按“目标选择 → 发送编辑 → 记录”顺序堆叠。

配对行显示软件、范围和当前状态。不要只显示“Codex 1”，因为用户需要确认目标软件和具体输入范围。当前配对使用背景和短状态标记；颜色始终配合文字。

## 4. 配对模型

```text
Pairing {
  pairing_id,
  software,
  scope,
  input_target,
  connector,
  connection_state,
  last_verified_at,
}
```

`software` 是目标软件类型，`scope` 是用户可理解的范围，例如项目、窗口、标签页或任务名称，`input_target` 是明确的输入区域，`connector` 是实际发送适配器。窗口位置、最近激活的标签或列表下标不能单独作为稳定身份。

配对创建时必须让用户确认目标范围和输入区域。连接器失效时显示“无法发送”，不自动切换到另一个窗口、不重启目标软件、不把文字发到最近焦点窗口。多个配对可以指向同一种软件，但目标范围必须能区分。

## 5. 发送语义

- **发送**：一次明确操作，把当前文字交给一个配对目标；成功后显示目标和时间。
- **加入队列**：文字暂存于 DevTabs 的发送队列，等待该配对的输入区域可用；队列项显示目标，不广播到其他软件。
- **清空草稿**：只清空当前编辑区。
- **插入片段**：只修改草稿，不自动发送。
- **发送记录**：记录目标、时间、结果和有限摘要；不保存目标软件内部响应，不把记录当成任务历史。

空文字禁止发送。长文字、连接失效、目标窗口关闭、权限不足和输入区域变化都要有具体失败原因。重试策略必须可见，默认不进行无界重试。

发送动作不抢目标软件之外的输入焦点；如果连接器需要激活窗口，应在发送前显示目标确认或采用目标软件提供的受控接口。DevTabs 不进行全局键盘广播。

## 6. 与现有 DevTabs 的关系

现有 Rust/TUI 版继续负责其已经实现的工作区、侧栏、预览、文件面板和 Agent 终端组合；本桌面端概念稿不把这些能力复制到新的桌面界面。未来如果桌面端与 TUI 共用数据，只共享项目配置、配对定义和发送记录等必要边界，不共享“谁在运行”“本轮是否完成”等推测状态。

“发送到指定软件”可以作为现有总览的一个入口：选择项目或任务后打开配对发送器，并把当前项目路径作为可插入片段。这个入口仍然只发送文字；用户要看终端、文件和差异，回到目标软件或现有 DevTabs 工作区。

## 7. Demo 验证路径

- 选择 Codex、Claude Code、PowerShell 或 VS Code 配对，确认中央标题始终显示软件和范围。
- 在草稿中输入多行文字，插入片段，确认插入不会自动发送。
- 点击发送，确认发送记录包含目标、时间、摘要和“已发送”。
- 点击加入队列，确认状态为“已加入队列”。
- 切换配对，确认不同目标的草稿不会混淆。
- 搜索配对、添加配对、编辑发送设置，确认这些操作不会出现终端或 Agent 业务面板。
- 断开配对的真实实现应显示失败原因；Demo 只展示成功/队列的交互。

## 8. 后续实现边界

第一阶段只验证配对模型、目标选择、发送确认、失败展示和发送记录。第二阶段再为 Codex、Claude Code、PowerShell、VS Code 分别实现连接器；每个连接器单独验证“目标输入区域身份、发送确认、窗口激活和权限边界”。

暂不设计终端渲染、Agent 状态同步、文件扫描、差异计算、桌面通知、自动任务拆分、广播输入或 AI 总结。这些功能属于目标软件或未来明确的新需求。
