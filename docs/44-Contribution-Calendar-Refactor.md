# Contribution Calendar Refactor

> 方格间距与全宽图例已根据真机反馈调整，当前样式见 [紧凑日历](45-Compact-Calendar-Layout.md)。本文保留全年数据及交互的实施记录。

2026-11-12。按独立方格贡献日历的参考图重构项目统计；这里统计的是当前仓库的 Git 提交次数，不是 GitHub 账户贡献。替代文档 43 的连续色块、相对周数横轴与未来日期点号。

## 展示与操作

- 默认近 12 周，星期一至星期日七行，每列一个自然周。使用背景色空格绘制独立格子，列间留一字符、行间留空白；宽度充足时每格两字符，窄栏每格一字符，更窄时回退周趋势。
- 月份直接标在对应周上方，首次与跨年标出年份，避免月份标签重叠。零提交为灰色，提交为四级绿色；未来日期使用淡色空心方格。深色与浅色主题使用各自的色阶。
- 顶部保留周期及提交数，下面为最近提交与连续活跃周。历史总计只有在与当前周期数不同时出现。底部左侧 UTC、右侧“少—色阶—多”，不再常驻未来日期说明或相对周数长句。
- 点击 `[年] / [1y]` 或聚焦统计后按 **Y** 切换全年，并打开统计弹窗；点击 `[12周] / [12w]` 或再按 Y 返回近 12 周。
- `[+]` 或统计聚焦时 **Z** 放大/还原；Esc 关闭弹窗。统计弹窗随窗口放大，最大 180 列。全年采用 53 个自然周（含当前周）对齐，包含周边界的日期，不等同于严格滚动 365 天；未来格子无提交数。
- 全年网格需要约 110 列正文宽度。窗口不足时显示近 12 周并提示加宽；加宽后自动显示全年，避免压缩成难以阅读的全年图。
- 悬停格子弹出日期、提交数及 UTC；未来日期说明“尚未到来”。点击将详情写到现有消息区。格子间隙没有点击行为，Alt+拖动仍是文字选择。

点击区域与绘制共用日历布局，随滚动、缩放和周期切换重新计算。仅屏幕内格子可以命中；其他详情弹窗遮挡统计时清除底层命中，浮动提示不穿透弹窗或文字选区。

## 数据与资源

后台 Git 概况查询扩展至 53 周，使用 `--since-as-filter` 保留时间戳非单调历史中的有效提交，再按 UTC 时间戳聚合。只保存 371 个日计数及 `first_day / today` 日期锚点，近 12 周由最后 84 个桶派生；没有新增文件系统扫描或逐日 Git 子进程。

绘制与鼠标详情只读内存数据，不运行 Git，也不查询文件元数据。日期转换复用原文件信息格式化中的 Gregorian 算法，提取到共享 `utc` 模块，文件时间格式原有测试继续覆盖。没有新增依赖。

日期锚点防止缓存跨日时整张热力图错位；刷新前仍显示采集时的日期范围，属于已有 TTL 采样语义。源码与完整统计缓存 schema 5 → 6，旧缓存自动失效，避免新旧日历能力混用。完整目录扫描、取消与字节口径不变。

全年覆盖比原来的 84 天查询更大，`--since-as-filter` 可能遍历更多历史；不承诺历史很长的仓库耗时不变，仍由原后台 Git 超时/失败机制报告。只读 `Yue-GPUI-Component` 查询成本记录在 `artifacts/contribution-heatmap/git-query-cost.json`：两种查询在当时均返回 170 个提交；因并发构建负载和覆盖差别，该记录只作为成本观察，不宣称同工作量提速，也不与文档 42 的磁盘扫描倍数混算。
