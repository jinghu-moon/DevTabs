# 快捷键重构改动说明

日期：2026-11-15。适用于本轮源码构建，历史打包程序不会自动更新。实施规格见 [docs/52](52-Shortcut-Refactor-Design.md)，逐阶段测试证据见 [docs/55](55-Shortcut-Refactor-Verification.md)。开发期不提供旧配置迁移或旧解析器。

## 日常操作

- 总览便签与编辑器下一处匹配均支持 F3、Ctrl+F3；默认提示首选 Ctrl+F3。二者是独立绑定，可以分别删除。
- 终端输入区默认仅截获受管前缀 Ctrl+G；Ctrl+P、F3、Ctrl+F3 等继续送给原终端。前缀可改、可解除占用；有效清单从注册表导出。
- 完整按下/松开一次 Ctrl+G，再完整按一次 Ctrl+G，向原终端发送一次原 Ctrl+G。按住第一次不算双击，第二次长按不连发。工作区菜单也提供“发送原前缀”。
- `panel.quick_open` 可由用户显式扩展到 `terminal.input`；该区域没有继承的 Ctrl+P 默认。若启用本地占用，可给 `terminal.send_quick_open_key` 另绑序列，或点击菜单发送原 Ctrl+P。
- 总览、工作区、终端菜单、资源/通知/审阅、侧栏、编辑/查找、差异、信息、书签、大纲及快速打开使用同一命令与有效绑定来源。独占弹层的 [操作] / [Actions] 列出当前命令及有效首选键；未绑定命令仍可点击执行，继续经过原业务保护。

## 改键与显示

从总览「设置 → 快捷键」或工作区「命令菜单 → 快捷键」进入管理页。录制/文本编辑、别名、作用域、冲突替换、删除备注、首选显示、恢复默认、预览导入都只改共同草稿；保存全部才提交配置，失败保留草稿。导出区分可导入的 TOML 差异与仅供查看的完整有效 JSON 目录。

所有绑定都是相对内置默认的增删；首选键只影响显示。以下片段用于 `config.toml`，让总览 F3 留给截图软件，并增加 Ctrl+J；Ctrl+F3 继续有效：

```toml
schema = 1

[[shortcuts.bindings]]
command = "overview.note.edit"
context = "overview"
add = ["Ctrl+J"]
remove = ["F3"]
preferred = "Ctrl+F3"

[shortcuts.bindings.notes]
F3 = "留给截图软件；这是用户备注，不是占用探测结果"
```

新默认会继续参与合并；显式用户键只抑制实际重叠区域的冲突默认，并在管理页说明。未知命令/区域和失效首选保留诊断；恢复绑定可以保留备注，清除备注是单独动作。

## 有意改变的行为

- 精确匹配修饰键：Ctrl+Alt+F3、Shift+F3 等不会因为主键是 F3 而触发便签。Ctrl+G 后续键也按明确修饰键匹配。
- 字母键名大小写不替代 Shift 状态；差异“上一处”使用明确的 Shift+N 或 `[`。旧测试中的 `Char('N') + 无修饰键` 不再被当作 Shift+N；新增测试验证 Alt+N 不触发。
- BackTab 规范化为 Shift+Tab，Plus 有规范拼写；标点布局所需 Shift 由输入适配层归一化。AltGr、IME 上屏文字和粘贴保留文本属性。
- 局部弹层支持与普通区域相同的两步受管前缀序列；Esc 先取消等待，之后才处理弹层取消。无效后续键不会重放给终端。
- 输入所有者按物理键与原会话/连接代次跟踪。切焦点、失焦、重连时不会把旧 release 投给新目标；需要保守抑制时提示“松开后再按一次”。
- 修复普通 Esc 的松开事件被粘贴分隔符探测丢弃的问题；修复审阅弹层的粘贴可能进入终端兜底路径的问题。终端协议及宿主个人设置未被修改。

菜单、帮助、底栏和业务提示读取有效键；固定文本输入、列表导航、确认/取消及几何调整保留原生控件键。无绑定状态不复活旧默认。
