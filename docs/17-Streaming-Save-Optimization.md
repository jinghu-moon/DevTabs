# Streaming Save Optimization

日期：2026-11-10。第四项优化，基线 `98a3207`。数据：[04-Streaming-Save.json](performance/04-Streaming-Save.json)。

## 实现

完整文件的原子替换要求把全部新内容写到临时文件，但不要求先在内存中生成另一份完整编码结果。新 `write_encoded` 直接写入 sink：UTF-8 借用原字节，UTF-16 使用 8 KiB 栈缓冲逐段编码；保留原始编码、BOM、CRLF/LF 和末尾换行。`Write::write_all` 处理短写、中断和写入失败，不隐藏错误。

保存前冲突检查与替换后备份核验使用 8 KiB 缓冲与已加载原字节逐段比较，不再读取并解码整个备份。保存后的重读仍保留，随后将请求内容逐段编码对比返回字节，确保实际交付等于所请求内容。原有保存锁、阻止直接写入的文件句柄、文件身份检查、同步临时文件、Windows ReplaceFileW 原子替换及异常恢复文件规则保留。

编辑器构造保存源码时直接用原换行符连接各行，省去先连接 LF 再全段替换的临时字符串。请求仍持有完整源码快照，保存后仍返回完整 Loaded，编辑器历史与预览状态也有完整缓冲；这不是无全文缓冲或局部磁盘修改。

最终回归还发现并修正一处模式切换问题：Markdown 渲染行不可被当作源码编辑器的颜色覆盖；在原有未保存内容预览回归中加入断言。

## 完整保存路径对比

每种编码五次独立保存，源文本包含中文、emoji、CRLF，UTF-8 源长度 234000 字节，UTF-16 文件 396002 字节。Release，真实文件与原子替换，串行执行。System 分配器计数从请求快照准备完毕后开始，涵盖冲突检查、写入、同步、替换、备份核验及最终重读；不只测编码函数。

| 编码 | 保存中位耗时：前 → 后 | 额外存活堆峰值：前 → 后 | 累计堆分配：前 → 后 |
| --- | ---: | ---: | ---: |
| UTF-8 | 7.92 → 6.68 ms | 1.24 → 0.76 MiB | 3.78 → 1.53 MiB |
| UTF-8 BOM | 7.69 → 6.65 ms | 1.24 → 0.76 MiB | 3.78 → 1.53 MiB |
| UTF-16 LE | 9.24 → 8.19 ms | 2.26 → 1.26 MiB | 7.50 → 2.75 MiB |
| UTF-16 BE | 8.92 → 7.43 ms | 2.26 → 1.26 MiB | 7.50 → 2.75 MiB |

额外堆峰值降低约 38%–44%，累计分配降低约 60%–63%，耗时降低约 11%–17%。计数覆盖 Rust System 分配，不含所有原生库分配或操作系统工作集；请求源码和原 Loaded 在测量前已存在，不能把表中数值当作保存时进程总内存。文件同步与安全软件会影响耗时。

升级前，396002 字节 UTF-16 保存的额外存活堆低于 2000000 字节测试失败；升级后通过。110 项普通工作区测试通过，新增两项覆盖实际保存分配上限和四种编码的分块/短写/中断/零写/磁盘错误。已有字节精确往返、外部内容冲突、文件身份、锁、链接、异步编辑保存与部分临时写入失败回归保留。fmt、Clippy（拒绝警告）与六进程 Release 规模测试通过。

## 复现与统计

```powershell
cargo test --workspace --all-targets --locked -- --test-threads=1
$env:DEVTABS_SAVE_REPORT = 'artifacts/save-after.json'
cargo test --release --locked --test streaming_save atomic_save_workload -- --ignored --test-threads=1
```

保存测试使用串行保护避免同一测试进程的分配统计互相干扰。默认关闭的 `DEVTABS_PERF_DIR` 聚合计时新增 `editor.stream_encode` 和 `editor.stream_verify`；编码计时也包含交付核验时的第二次编码扫描，不能简单当作写盘时间。
