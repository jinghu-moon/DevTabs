# Project Pulse and Session Navigation

日期：2026-11-11。当前实现采用 Ratatui、已有 Git 子进程与 JSONL 只读适配器，不增加统计服务或数据库。本文覆盖本轮总览、历史会话和返回导航；同项目多 Agent 独立任务仍见 [37-Parallel-Agent-Workspace-Design.md](37-Parallel-Agent-Workspace-Design.md)，尚未实现。

## 1. 项目列表

默认一个项目一行：队列编号、可展开箭头、项目色块、名称、工作状态、改动文件数。选中项使用单行轻背景与左侧竖条；悬停不改变选择或行高。非 main/master 分支在空间足够时显示，完整启动信息仍在详情。

分组优先级为需处理、运行中、待恢复、收藏、最近使用、其他项目；项目只归入一个组。需处理来自配置错误、启动失败或 Git 冲突；运行来自宿主返回的工作区；待恢复来自恢复日志；已停止需要 DevTabs 成功打开过的记录；连接异常显示未知，不推测 Agent 是否正在思考或等待输入。收藏和时间分组继续保留。

清理重复 Agent 名称和无意义的零值状态。改动摘要直接显示文件数量，Git 增加为绿色、删除为红色，冲突另有文字。列表底部提供“＋ 添加项目”，使用现有路径表单；Ctrl+A 入口保留。

## 2. 最近用户消息与多个 resume

原来的固定尾部读取会被大型工具输出挤占，导致读取到 AI 回复却没有此前用户请求。现在从文件尾按 256 KiB 分块向前读，最多 64 MiB / 2 秒；只保留用户和助手消息，跳过工具输出与超过 4 MiB 的单条记录。已知环境元数据块被移除，图片等 XML 风格的真实请求予以保留。默认摘要明确寻找最近用户与最近 AI 消息，分别使用角色徽标、颜色和竖线；无法读取时说明原因，不生成替代内容。

会话目录不再使用原来的 15 条结果与 512 个候选硬截断。当前发现预算为最多 30,000 个目录项 / 3 秒，目录元数据总读取时间最多 8 秒，达到预算明确标记不完整。按文件更新时间排列并按会话 ID 去重，先读取首个会话正文，其他正文选中后由后台惰性加载；过期请求不能覆盖当前选择。读取失败不会自动连续重试，F5 可重试。

Codex 实现参考本地源码：

- `refer/codex-main/codex-rs/tui/src/resume_picker.rs`：分页与更新时间排序。
- `refer/codex-main/codex-rs/tui/src/app_server_session/thread_list.rs`：cwd 过滤。
- `refer/codex-main/codex-rs/rollout/src/list.rs`：会话元数据和消息预览。
- `refer/codex-main/codex-rs/rollout/src/session_index.rs`：追加式名称索引。

本项目仍使用本地只读适配器。读取 `session_index.jsonl` 尾部最多 4 MiB，后出现的标题覆盖旧标题，但只有 rollout 的 cwd 独立验证通过后才应用名称；名称索引不作为项目归属依据。归档会话未接入；原生选择器仍可使用。

| 操作 | 入口与行为 |
| --- | --- |
| 展开项目会话子行 | 点击项目箭头，或 Alt+→；Alt+← 收起。仅已发现有会话时显示箭头 |
| 选择会话 | 子行选择决定精确 resume ID，Enter 打开；与队列项目选择分开 |
| 历史搜索 | F9，直接输入标题或 ID，Backspace 删除，Home/End 定位 |
| 暂存历史会话 | F9 内 Enter，只更新启动草稿；不立即启动 |
| 原生历史选择器 | F9 内 Alt+P |
| 新会话 | F9 内 Alt+N |

从会话子行进入 F9 后另选会话，会同步切换到对应子行；新会话／原生选择会清除旧 resume ID、工作区和恢复日志标识，防止旧选择覆盖新草稿。只有同 Agent 且显式 resume ID 一致的运行工作区才被精确会话选择复用；其他情况创建新实例，避免把指定会话错误送进另一条已运行对话。启动队列仍按项目组织，不代表已具备多 Agent 任务调度。

## 3. 返回总览

工作区底栏常驻可点击“← 总览”，由 DevTabs 直接处理鼠标，Ctrl+G → P 保留。返回退出当前前端，不关闭宿主会话；关闭工作区仍是单独的 Q 确认操作。

返回携带当前项目和会话启动草稿，发现项目后选回该项目；旧过滤器或折叠分组隐藏原项目时，切回全部并展开所属组。再次进入依照宿主复用和已有面板布局配置恢复，不宣称保存整个前端对象、滚动位置或全部弹窗状态。

## 4. 项目脉搏

统计在后台采集，绘制不执行 Git 或磁盘 I/O。继续使用可取消请求、内存与磁盘缓存，不增加常驻扫描器。

- 顶部显示最近提交日期、近 12 周活跃周数、总提交数。
- 近 12 个自然周按 UTC 周一对齐，7 行 × 12 列提交热力图；本周未来日期留空，颜色表示日提交次数。小于 28 列回退为周趋势条。附最活跃周和连续活跃周数；连续周从本周向前计算，本周未提交即为零。
- 最近 30 天文件热点最多展示 5 项、直接父目录热点最多 3 项，展示提交次数、增删行、最近改动日期。次数为涉及该文件／目录的不同提交数，目录次数不重复累加同一提交内的文件。
- 热点采集最多 1,000 条非合并提交；额外读取一条用于判断截断。重命名按删除和新增处理。二进制文件不把未知行数显示为文本零增删。
- 源码、测试、文档以已识别文本文件的字节数分类；测试路径／命名和文档路径／扩展名属于明确规则，不做语义推断。其合计等于源码统计字节数，不能等同完整磁盘体积。
- 构建目录 `target/build/dist/.next/obj/bin`、依赖目录 `vendor/node_modules/.venv` 单列体积；目录树进入某一分类后继承该分类。普通目录排行剔除这些内容，嵌套构建目录同样排除，避免巨大 target 压扁其他目录比例。

提交总数与活动基于仓库可达历史；热点基于项目目录范围的 Git 路径。大仓库 Git 单命令最多 5 秒 / 8 MiB，失败显示不可用，不冒充零次活动。最近提交日期由 Git 提交日期提供，日热力图使用 UTC；日期边界存在口径差异。

并行任务改动交集暂不显示：当前没有独立任务模型和可靠的任务归属，不能从项目累计修改推断任务冲突。该能力随文档 37 的任务／worktree 实现后接入。

## 5. 扫描预算与刷新

“部分结果”表示扫描未遍历完全部范围，不等于读取失败或项目有故障。现在按源码、磁盘分别记录：达到 200,000 项上限、达到时间预算、部分条目无法读取。只给对应体积加 `≥`，说明这是已扫描部分的下界；解释文本在窄面板换行。

磁盘预算 200,000 项 / 3 秒，源码预算 200,000 项 / 5 秒；源码继续遵守忽略规则和既有依赖过滤。符号链接不追踪。

完整结果或固定数量上限的界面自动刷新间隔为 10 分钟；时间预算或读错误 30 秒后允许重试，避免原来每 10 秒对固定上限反复扫描。完整磁盘结果可独立复用最多 12 小时，源码及 Git 缓存最多 10 分钟；文件／Git 缓存戳变化或 F5 强制刷新会使缓存失效。缓存版本已递增，不复用旧口径。

## 7. 性能数据与边界

Release、暖文件系统、每组 7 个扫描样本，使用同一份 3,000 个 Rust 文件与 12,000 个构建文件夹具，并运行旧项目未修改的统计函数作对照：

| 场景 | 旧项目源码扫描中位数 | 当前源码扫描中位数 |
| --- | ---: | ---: |
| 非 Git 目录 | 131.710 ms | 7.367 ms |
| 已初始化 Git 目录 | 129.888 ms | 10.359 ms |

这是指定夹具的源码遍历结果，不代表包含热点 Git 查询的完整统计能获得同样倍数；磁盘扫描中位数为约 9–10 ms，与旧项目约 10 ms 相近。真实大仓库需依据自己的忽略规则、文件数与 Git 历史单独测量。

总览 200×50 TestBackend、100 次切换样本：

| 内容 / 项目数 | 上一版 p50 | 本轮 p50 | 本轮 p95 |
| --- | ---: | ---: | ---: |
| 无对话 / 100 | 400 μs | 388 μs | 562 μs |
| 无对话 / 1,000 | 392 μs | 375 μs | 588 μs |
| 缓存对话 / 100 | 501 μs | 542 μs | 638 μs |
| 缓存对话 / 1,000 | 562 μs | 547 μs | 658 μs |

绘制中位数保持在 0.375–0.547 ms；部分样本更快，部分尾延迟升高，不宣称全面提速。该夹具测试 UI 绘制，不包含宿主、真实终端输出或文件扫描。2,000 文件缓存夹具结果完全一致，未缓存中位数 6.652 ms，暖缓存 0.120 ms；不作为所有仓库的承诺。

文本快照包含中英文、26/44/60/76/100 列统计面板，以及明暗主题的 80/140/200 列总览。热力图颜色需要真机查看，纯文本快照仅验证字符布局。
